### 2. 权限检查核心函数

#### 内核层 (`kernel/src/permission.rs` - 新增文件)
```rust
pub fn generic_permission(
    file_mode: StatMode,    // 文件权限位 (rwxrwxrwx)
    file_uid: u32,          // 文件所有者
    file_gid: u32,          // 文件所属组
    process_euid: u32,      // 进程有效UID
    process_egid: u32,      // 进程有效GID
    mask: u32,              // 请求的权限 (MAY_READ/WRITE/EXEC)
) -> bool
```

**权限检查逻辑** (参考 Linux generic_permission):
1. **Root特权**: euid=0 可以读写任何文件，执行任意有x位的文件
2. **所有者**: 如果 euid == file_uid，检查 owner 权限位
3. **组成员**: 如果 egid == file_gid，检查 group 权限位  
4. **其他用户**: 检查 other 权限位

#### VFS层 (`filesystem/vfscore/src/permission.rs` - 新增文件)

| `setgid(gid)` | 设置GID | ✅ 完整实现 |

**setuid实现逻辑** (参考 Linux):
```rust
if euid == 0 {
    // Root: 可以设置为任意uid
    uid = euid = suid = new_uid;
} else if new_uid == uid || new_uid == suid {
    // 普通用户: 只能设置为自己的real uid或saved uid
    euid = new_uid;
} else {
    return EPERM;  // 权限拒绝
}
```

## 技术要点

### 1. 三种UID的区别
- **Real UID (uid)**: 进程的实际所有者
- **Effective UID (euid)**: 用于权限检查的ID
- **Saved UID (suid)**: 用于setuid程序临时降权后恢复

### 2. 权限位解析 (rwxrwxrwx)
```
文件模式: 0o755 = rwxr-xr-x
         owner: rwx (7) = 111 (二进制)
         group: r-x (5) = 101
         other: r-x (5) = 101
```

### 3. Root特权规则
- 可以读写任何文件（无视权限位）
- 只能执行**至少有一个x位**的文件
- 这防止root误执行数据文件

## 使用示例

### 场景1: Root创建普通用户进程
```rust
let mut pcb = task.pcb.lock();
pcb.uid = 1000;  // 设为普通用户
pcb.euid = 1000;
// 现在这个进程会受到权限限制
```

### 场景2: 检查文件访问权限
```rust
use crate::permission::check_file_permission;

let stat = file.metadata()?;
check_file_permission(
    stat.mode,      // 文件权限 (如 0o644)
    stat.uid,       // 文件所有者
    stat.gid,       // 文件所属组
    pcb.euid,       // 进程有效UID
    pcb.egid,       // 进程有效GID
    MAY_READ,       // 请求读权限
)?;  // 返回 Ok(()) 或 EACCES
```

### 场景3: setuid程序
```rust
// 类似 /usr/bin/passwd 的工作方式
// 程序文件: -rwsr-xr-x root root
// 普通用户执行时，euid临时变为0
if file_mode.contains(StatMode::SET_UID) {
    pcb.euid = file_uid;  // 临时获得文件所有者权限
}
```
