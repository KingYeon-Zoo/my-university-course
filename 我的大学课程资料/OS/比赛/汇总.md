### 2.2 TCP CUBIC拥塞控制算法

#### 2.2.1 实现概述

TCP CUBIC拥塞控制算法实现参考Linux 5.15.0内核源码`~/linux-5.15.0/net/ipv4/tcp_cubic.c`文件。CUBIC是Linux内核的默认拥塞控制算法，相比传统算法在高带宽延迟网络中具有更优的性能表现。

#### 2.2.2 实现功能

本次实现包含以下功能：

1. CUBIC算法核心逻辑，采用立方函数调整拥塞窗口。
2. 慢启动阶段处理，初始拥塞窗口设为10 MSS（参照RFC 6928）。
3. 拥塞避免阶段处理，使用立方函数平滑增长。
4. 快速收敛机制，加速窗口收敛过程。
5. TCP友好性保证，确保与传统TCP协议的公平竞争。
6. 拥塞窗口动态调整功能。
7. 丢包检测和快速恢复机制。

#### 2.2.3 关键参数

算法采用以下关键参数：

1. Beta值设为717/1024，约等于0.7，作为乘性减小因子。
2. 初始拥塞窗口cwnd设为10 MSS，符合RFC 6928标准。
3. 初始慢启动阈值ssthresh设为65535字节。
4. 最小增长率限制为每RTT 2个数据包。

#### 2.2.4 算法核心公式

CUBIC算法采用以下核心公式计算目标拥塞窗口：

W_cubic(t) = C × (t - K)³ + W_max

其中，W_max表示上次丢包前的最大窗口值，K表示从当前窗口增长到W_max所需的时间，C为CUBIC参数，控制增长速度。

2. `vendor/lose-net-stack/src/connection/tcp.rs`：集成CUBIC算法。
3. `vendor/lose-net-stack/src/lib.rs`：导出tcp_cubic模块。

### 2.3 TCP SACK选择性确认机制

#### 2.3.1 实现概述

TCP SACK选择性确认机制参考Linux 5.15.0内核源码以及RFC 2018、RFC 2883、RFC 3517等标准文档实现。SACK机制可显著提升丢包环境下的网络传输性能。

#### 2.3.2 核心数据结构

本实现包含两个核心数据结构：

第一个数据结构为SackBlock，表示一个SACK块：

```rust
pub struct SackBlock {
    pub start_seq: u32,  // 起始序列号
    pub end_seq: u32,    // 结束序列号
}
```

第二个数据结构为SackInfo，用于管理SACK信息：

```rust
pub struct SackInfo {
    pub sack_enabled: bool,           // SACK启用标志
    pub sack_ok: bool,                // 对端支持SACK标志
    pub duplicate_sack: Option<SackBlock>, // D-SACK块
    pub selective_acks: Vec<SackBlock>,     // 待发送的SACK块
    pub recv_sack_cache: Vec<SackBlock>,    // 接收到的SACK块缓存
    pub sacked_out: u32,              // 已通过SACK确认的字节数
    pub highest_sack: u32,            // 最高SACK序列号
}
```

#### 2.3.3 核心功能

SackBlock结构提供以下核心方法：

1. is_valid()：验证SACK块的有效性。
2. contains()：检查指定序列号是否在块范围内。
3. overlaps()：检查与其他SACK块是否存在重叠。
4. try_merge()：合并相邻或重叠的SACK块。

SackInfo结构提供以下核心方法：

1. add_sack_block()：添加乱序数据的SACK块。
2. process_received_sacks()：处理接收到的SACK信息。
3. generate_sack_option()：生成TCP SACK选项。
4. parse_sack_option()：解析TCP SACK选项。

#### 2.3.4 TCP选项常量

本实现定义以下TCP选项常量：

1. TCP_MAX_SACK_BLOCKS：值为4，表示最多允许4个SACK块。
2. TCPOPT_SACK：值为5，表示SACK选项类型。
3. TCPOPT_SACK_PERMITTED：值为4，表示SACK许可选项。
4. TCPOLEN_SACK_BASE：值为2，表示SACK基础长度。
5. TCPOLEN_SACK_PERBLOCK：值为8，表示每个SACK块占8字节。

#### 2.3.5 工作原理对比

传统TCP确认方式：当数据段101-200丢失时，接收方只能发送连续的重复ACK=101，发送方需要重传从101开始的所有数据。

SACK确认方式：当数据段101-200丢失时，接收方发送ACK=101并附带SACK[201-300]，明确指出已成功接收201-300段数据，发送方只需重传缺失的101-200段。

## 第三章 Page Cache页面缓存实现

### 3.1 实现概述

Page Cache页面缓存参考Linux 5.15.0内核源码`~/linux-5.15.0/mm/filemap.c`文件实现。实现日期为2025年12月27日，新增代码约500行，预计可将磁盘I/O性能提升10至100倍。

### 3.2 核心数据结构

#### 3.2.1 CachedPage结构

CachedPage表示一个缓存页：

```rust
pub struct CachedPage {
    pub index: usize,      // 页索引（offset / 4KB）
    pub data: [u8; 4096],  // 4KB页数据
    pub dirty: bool,       // 脏页标记
    pub last_access: u64,  // LRU时间戳
    pub file_id: u64,      // 文件ID
}
```

#### 3.2.2 PageCache结构

PageCache为缓存管理器：

```rust
pub struct PageCache {
    pages: BTreeMap<(file_id, page_index), CachedPage>,  // 缓存页索引
    lru: LruList,          // LRU替换队列
    stats: CacheStats,     // 统计信息
}
```

### 3.3 核心功能

PageCache提供以下关键方法：

1. find_page()：查找缓存页，返回命中或未命中状态。
2. add_page()：添加页到缓存，自动执行LRU淘汰。
3. read_cached()：带缓存的读取操作。
4. write_cached()：带缓存的写入操作，采用write-through策略。
5. invalidate_file()：删除文件时清理相关缓存。
6. sync_all()：同步所有脏页到磁盘。

### 3.4 LRU替换算法

#### 3.4.1 核心逻辑

LRU替换算法采用以下逻辑：

1. 访问页时，将该页移动到队列尾部，标记为最新。
2. 缓存满时，淘汰队列头部的页，即为最旧的页。

#### 3.4.2 数据结构

LRU队列采用`VecDeque<(file_id, page_index)>`结构实现。

### 3.5 缓存文件包装器

CachedFile包装器位于`filesystem/fs/src/cached_file.rs`，具有以下特点：

1. 可包装任意实现INodeInterface接口的文件。
2. 自动使用Page Cache进行缓存。
3. 透明缓存，用户无感知。

使用示例：

```rust
let cached = CachedFile::new(raw_file);
cached.read_cached(offset, buffer)?;  // 自动缓存
```

### 3.6 脏页写回机制

脏页写回机制位于`vfscore/src/writeback.rs`，采用以下策略：

1. 每5秒自动写回脏页。
2. 页面被淘汰时立即写回脏页。
3. 支持手动调用sync_all()进行同步。

### 3.7 技术特点

#### 3.7.1 写策略

采用Write-Through写策略，具有以下特点：

1. 写入时同时更新缓存和磁盘。
2. 保证数据一致性。
3. 简化崩溃恢复过程。

#### 3.7.2 缓存容量

缓存容量设为1MB（256页），可通过`MAX_CACHED_PAGES`常量调整，在内存占用与性能之间取得平衡。

#### 3.7.3 索引结构

采用BTreeMap作为索引结构，具有以下优点：

1. O(log n)的查找时间复杂度。
2. 支持范围查询。
3. 内存效率高。

### 3.8 工作流程

#### 3.8.1 读取流程

1. 应用程序调用read()函数。
2. 计算页索引page_index = offset / 4KB。
3. 查找缓存cache[file_id, page_index]。
4. 若命中则直接返回数据，若未命中则读取磁盘并加入缓存。
5. 更新LRU时间戳。

#### 3.8.2 写入流程

1. 应用程序调用write()函数。
2. 更新缓存cache[file_id, page_index]。
3. 标记dirty = true。
4. 立即写回磁盘（write-through）。
5. 标记dirty = false。

#### 3.8.3 LRU淘汰流程

1. 检测到缓存已满（256页）。
2. 从LRU队列头部取出最旧的页。
3. 若该页为脏页，则写回磁盘。
4. 移除该页。

### 4.3 权限检查核心函数

#### 4.3.1 内核层实现

权限检查核心函数位于`kernel/src/permission.rs`：

```rust
pub fn generic_permission(
    file_mode: StatMode,    // 文件权限位（rwxrwxrwx）
    file_uid: u32,          // 文件所有者
    file_gid: u32,          // 文件所属组
    process_euid: u32,      // 进程有效UID
    process_egid: u32,      // 进程有效GID
    mask: u32,              // 请求的权限（MAY_READ/WRITE/EXEC）
) -> bool
```

#### 4.3.2 权限检查逻辑

权限检查按以下顺序执行：

1. Root特权检查：euid=0可以读写任何文件，执行任意具有x位的文件。
2. 所有者检查：若euid == file_uid，检查owner权限位。
3. 组成员检查：若egid == file_gid，检查group权限位。
4. 其他用户检查：检查other权限位。

#### 4.3.3 VFS层实现

VFS层权限检查接口位于`filesystem/vfscore/src/permission.rs`：

```rust
pub fn generic_permission(

    file_gid: u32,
    process_euid: u32,

) -> VfsResult<()>
```

### 4.4 系统调用实现

已实现的系统调用位于`kernel/src/syscall/sys.rs`：

| 系统调用 | 功能 | 实现状态 |
|---------|------|---------|
| getuid() | 获取真实UID | 完成，返回pcb.uid |
| geteuid() | 获取有效UID | 完成，返回pcb.euid |
| getgid() | 获取真实GID | 完成，返回pcb.gid |
| getegid() | 获取有效GID | 完成，返回pcb.egid |
| setuid(uid) | 设置UID | 完成，完整实现 |
| setgid(gid) | 设置GID | 完成，完整实现 |

#### 4.4.1 setuid实现逻辑

setuid系统调用按以下逻辑执行：

```rust
if euid == 0 {
    // Root用户：可以设置为任意uid
    uid = euid = suid = new_uid;
} else if new_uid == uid || new_uid == suid {
    // 普通用户：只能设置为自己的real uid或saved uid
    euid = new_uid;
} else {
    return EPERM;  // 权限拒绝
}
```

### 4.5 技术要点

#### 4.5.1 三种UID的区别

1. Real UID（uid）：进程的实际所有者。
2. Effective UID（euid）：用于权限检查的ID。
3. Saved UID（suid）：用于setuid程序临时降权后恢复。

#### 4.5.2 权限位解析

文件模式0o755 = rwxr-xr-x的解析如下：

1. owner权限：rwx（7）= 111（二进制）。
2. group权限：r-x（5）= 101（二进制）。
3. other权限：r-x（5）= 101（二进制）。

#### 4.5.3 Root特权规则

1. Root可以读写任何文件，无视权限位。
2. Root只能执行至少有一个x位的文件。
3. 此限制可防止root误执行数据文件。

### 4.6 使用示例

#### 4.6.1 Root创建普通用户进程

