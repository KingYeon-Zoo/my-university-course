# 课程报告：Linux 外存对换区（Swap Space）的工作原理与内核机制分析

**摘要**

本文旨在深入分析 Linux 操作系统中 Swap 空间的运作机制。在虚拟内存技术背景下，Swap 作为物理内存的逻辑扩展，允许系统在物理资源受限时通过磁盘 I/O 换出非活跃页，从而支持更大的地址空间和多任务并发。本文将详细探讨内核的页面回收机制（Page Reclaim）、页面置换算法（LRU 近似实现）、kswapd 守护进程的工作流程以及关键内核数据结构。此外，本文还将对比不同 Swap 实现形式的性能差异，并结合 vm.swappiness 参数探讨系统调优策略。

## 1. 引言

在现代计算机体系结构中，物理内存（RAM）虽然容量不断增长，但相对于应用程序日益膨胀的内存需求，仍属于稀缺资源。为了让多个进程能够同时运行，且每个进程都拥有独立的、连续的虚拟地址空间，操作系统引入了虚拟内存技术。Swap（对换区）是虚拟内存系统的核心组件之一。它在硬盘（HDD/SSD）上划分出一块区域，用于临时存储物理内存中暂时不被 CPU 频繁访问的数据。这使得系统能够运行总内存需求超过物理 RAM 上限的任务组合。

## 2. Linux 内存管理基础

### 2.1 虚拟地址空间与分页机制

Linux 采用分页（Paging）机制管理内存，默认页大小通常为 4KB。CPU 访问的是虚拟地址，通过内存管理单元（MMU）查页表（Page Table）映射到物理地址。

### 2.2 为什么需要 Swap

当物理内存耗尽时，内核必须释放一部分内存给新的请求。根据页面类型的不同，处理方式也不同：

1. **文件页（File-backed pages）的处理**：对于代码段、动态库等，由于磁盘上有原始文件，内核可以直接丢弃这些页面，需要时再从文件系统读取。

2. **匿名页（Anonymous pages）的处理**：对于堆、栈数据，这些数据在磁盘上没有对应的文件，不能直接丢弃。Swap 的作用正是为这些“匿名页”提供一个磁盘上的备份位置，使其可以被安全地从物理内存中移除。

## 3. Swap 的核心工作原理

### 3.1 换出机制 (Swap Out)

Linux 不会等到内存完全耗尽才开始回收，而是通过一套复杂的策略来平衡。

#### 3.1.1 页面置换算法：双链表策略

Linux 并没有使用严格的 LRU（Least Recently Used，最近最少使用）算法，因为维护全局时间戳开销太大。它采用了一种近似 LRU 算法，主要基于两个链表：

1. **Active List (活跃链表)**：存放最近被频繁访问的页面。

2. **Inactive List (非活跃链表)**：存放较长时间未被访问的页面。

当内存紧张时，内核会扫描 Active List，将部分页面“降级”移动到 Inactive List。而 Swap Out 的候选者主要来自 Inactive List 的尾部。

#### 3.1.2 回收执行者：kswapd 与 Direct Reclaim

内核中有两个主要路径进行内存回收：

1. **kswapd (内核线程)**：这是后台异步回收机制。当物理空闲内存低于“低水位线 (low watermark)”时，kswapd 被唤醒。它扫描 LRU 链表，将脏页写回磁盘（Swap out）或丢弃干净页，直到空闲内存恢复到“高水位线 (high watermark)”。

2. **Direct Reclaim (直接回收)**：当内存极度紧缺，kswapd 来不及回收导致空闲内存低于“最小水位线 (min watermark)”时，分配内存的进程会被迫自己去执行回收操作。这会造成严重的性能阻塞。

### 3.2 换入机制 (Swap In) 与缺页中断

当 CPU 试图访问一个已经被换出到 Swap 的页面时，MMU 发现页表项（PTE）的 Present 位为 0，但 PTE 中保留了该页在 Swap 设备中的位置信息。此时会触发缺页中断 (Page Fault)。处理流程如下：

1. **触发异常**：CPU 暂停当前指令，跳转到内核的缺页中断处理函数 (`do_page_fault`)。

2. **查找定位**：内核解析 PTE，发现该页在 Swap 中（而非无效地址）。

3. **分配内存**：内核在物理 RAM 中申请一个新的空闲物理页。

4. **磁盘 I/O**：启动磁盘驱动，将数据从 Swap 分区读取到新的物理页中（这是主缺页中断，Major Fault，速度较慢）。

5. **更新页表**：修改 PTE，将 Present 位置 1，指向新的物理地址。

6. **恢复执行**：CPU 重新执行刚才被暂停的指令。

### 3.3 关键数据结构

为了管理 Swap，Linux 内核设计了几个核心结构体（定义在 `include/linux/swap.h` 等文件中）：

1. **`struct swap_info_struct`**：用于描述一个 Swap 区域（可以是分区或文件）的元数据。它包含了优先级（priority）、Swap 区域的页槽位图（swap_map，用于记录哪些槽位被使用了）等关键信息。

2. **`swp_entry_t`**：这是一个抽象的数据类型。当页面被换出后，它会被编码并存储在页表项（PTE）中，代替原本的物理地址。它实际上包含了两部分信息：Swap Type（标识是第几个 Swap 设备）和 Swap Offset（在该设备中的偏移量）。

## 4. Swap 的实现形式与演进

### 4.1 Swap Partition 与 Swap File

1. **Swap Partition (分区)**：这是磁盘上独立的物理分区。其优点在于位于磁盘连续扇区，I/O 寻址理论上略快（但在 SSD 时代差异缩小）。缺点是调整大小困难，通常需要重新分区。

2. **Swap File (文件)**：这是文件系统上的一个大文件。其优点是灵活，可随时创建、删除、调整大小。在早期 Linux 中，访问 Swap File 需要经过文件系统层，效率较低。但现代内核（2.6+）支持直接映射物理块，性能已与分区基本无异。

### 4.2 ZRAM (内存压缩技术)

在嵌入式设备（如 Android 手机）或云服务器中，如果磁盘 I/O 太慢或不存在，Linux 会使用 ZRAM。其原理是划分出一块物理 RAM 模拟成块设备。当需要 Swap Out 时，CPU 将数据压缩后存入 ZRAM，而不是写到磁盘。这种方式的优势在于 CPU 压缩速度远快于磁盘 I/O，且显著节省了物理内存空间（压缩比通常可达 3:1）。

## 5. 性能影响与调优

### 5.1 系统抖动 (Thrashing)

如果系统的物理内存严重不足，导致频繁地发生 Swap In 和 Swap Out，CPU 大部分时间都在等待磁盘 I/O，而不是执行代码。这种状态称为“抖动”。此时系统响应极慢，通常需要通过 OOM Killer（内存溢出杀手）杀死进程来解决。

### 5.2 vm.swappiness 参数详解

这是一个极易被误解的内核参数（取值 0-100，默认 60），它控制的是内核在回收内存时的倾向性：

1. **参数含义**：该参数决定了内核在回收内存时，是更倾向于回收匿名页（Swap），还是更倾向于回收文件页（Drop Cache）。

2. **低数值 (接近 0)**：内核极度倾向于回收文件页（清空缓存），尽量不进行 Swap，以避免磁盘 I/O 延迟。

3. **高数值 (接近 100)**：内核更积极地进行 Swap，试图将匿名页换出，从而保留更多的文件页缓存（这对 I/O 密集型服务器可能有利）。

## 6. 结论

Swap 空间是 Linux 内存管理体系中不可或缺的安全网。它通过将非活跃的匿名内存页转移到次级存储，打破了物理内存的物理限制，提升了系统的整体吞吐量和稳定性。理解 Swap 的工作原理——从 LRU 链表的维护、kswapd 的唤醒机制到缺页中断的处理——对于系统管理员进行性能调优和故障排查具有重要的指导意义。随着存储技术的发展，虽然 RAM 容量在增加，但 ZRAM 等新型 Swap 技术的出现证明了这一机制在现代计算中依然具有强大的生命力。
