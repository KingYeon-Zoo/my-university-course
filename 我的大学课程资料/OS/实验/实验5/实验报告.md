## 2. 实验原理

### 2.1 进程的基本概念

程序是指存储在磁盘上的可执行文件，而进程是正在执行的程序实例。Linux操作系统采用分时技术，将CPU运行时间划分为若干时间片，使多个进程能够"同时"运行。对于单CPU系统，某一时刻仅有一个进程在运行，但由于时间片通常为几十毫秒，用户感觉多个进程在并发执行。

### 2.2 进程管理机制

Linux 0.11内核最多支持64个进程同时存在。除第一个进程由系统手工建立外，其余进程均通过fork系统调用创建。内核使用进程标识号PID唯一标识每个进程。

内核通过进程表task数组对进程进行管理，该数组定义在kernel/sched.c文件第129行，长度为64。每个进程表项是一个指向task_struct结构的指针。task_struct结构（进程控制块PCB）定义在include/linux/sched.h文件第146行，包含进程运行状态、信号、进程号、父进程号、运行时间、打开文件、局部描述符表及任务状态段等信息。

### 2.3 fork系统调用机制

fork系统调用在进程表中创建与父进程几乎完全相同的子进程表项。子进程与父进程执行相同代码，但拥有独立的数据空间和环境参数。fork函数具有"调用一次，返回两次"的特性：在父进程中返回子进程的PID，在子进程中返回0。

### 2.4 进程的创建与程序加载

fork系统调用为子进程申请新的进程控制块，复制父进程的控制块信息，并对子进程控制块进行适当修改，使子进程与父进程执行相同程序。execve系统调用不申请新的进程控制块，而是直接修改当前进程控制块，使其执行新程序。

在实际应用开发中，通常结合使用fork和execve：先使用fork创建子进程，再在子进程中调用execve加载执行另一个程序。

```c
#define _LIBRARY  
#include <stdio.h>  
#include <unistd.h>

int main(int argc, char * argv[])
{
    int pid;
    printf("PID:%d parent process start.\n", getpid());
    pid = fork();
    if (pid != 0)
    {
        printf("PID:%d parent process continue.\n", getpid());
    }
    else
    {
        printf("PID:%d child process start.\n", getpid());
```

## 4. 实验的思考与问题分析

### 4.1 思考题1：循环创建10个子进程

编写程序使父进程循环创建10个子进程，每个子进程输出PID后退出，父进程等待所有子进程结束后再退出。

核心代码如下：

```c
#define _LIBRARY  
#include <stdio.h>  
#include <unistd.h>

int main(int argc, char * argv[])
{
    int i, pid;
    printf("PID:%d parent process start.\n", getpid());
    
    for (i = 0; i < 10; i++)
    {
        pid = fork();
        if (pid == 0)
        {
            // 子进程分支
            printf("PID:%d child process %d created.\n", getpid(), i + 1);
            return 0;
        }
        else if (pid < 0)
        {
            printf("Fork failed!\n");
            return 1;
        }
        // 父进程继续循环创建下一个子进程
    }
    
    // 父进程等待所有子进程结束
    for (i = 0; i < 10; i++)
    {
        wait(NULL);
    }
    
    printf("PID:%d parent process exit.\n", getpid());
    return 0;
}
```

程序设计要点：

（1）使用for循环调用fork函数10次创建子进程。

（2）在子进程分支中输出PID后立即return，避免子进程继续执行循环。

（3）父进程在循环结束后调用wait函数10次，等待所有子进程退出。

（4）每次fork后检查返回值，处理可能的创建失败情况。

### 4.2 思考题2：fork与execve结合使用

编写程序在子进程中使用execve加载执行另一个程序，父进程等待子进程退出后结束。

首先创建被执行的程序child_program.c：

```c
#define _LIBRARY
#include <stdio.h>
#include <unistd.h>

int main(int argc, char * argv[])
{
    printf("PID:%d child program is running.\n", getpid());
    printf("This is a new program loaded by execve.\n");
    return 0;
}
```

主程序main_exec.c代码如下：

```c
#define _LIBRARY  
#include <stdio.h>  
#include <unistd.h>

int main(int argc, char * argv[])
{
    int pid;
    char *argv_child[] = {"/usr/bin/child_program", NULL};
    
    printf("PID:%d parent process start.\n", getpid());
    
    pid = fork();
    if (pid == 0)
    {
        // 子进程分支
        printf("PID:%d child process created.\n", getpid());
        printf("Loading new program...\n");
        execve("/usr/bin/child_program", argv_child, NULL);
        
        // 如果execve成功，以下代码不会执行
        printf("execve failed!\n");
        return 1;
    }
    else if (pid > 0)
    {
        // 父进程分支
        printf("PID:%d parent waiting for child.\n", getpid());
        wait(NULL);
        printf("PID:%d parent process exit.\n", getpid());
    }
    else
    {
        printf("Fork failed!\n");
        return 1;
    }
    
    return 0;
}
```

程序设计要点：

（1）使用fork创建子进程，通过返回值判断父子进程分支。

（2）在子进程中调用execve函数，传入新程序路径和参数数组。

（3）execve成功执行后，子进程的代码段被完全替换，后续代码不会执行。

（4）父进程调用wait函数阻塞等待子进程结束。

（5）需先编译child_program.c生成可执行文件，并将其放置在正确路径。

### 4.3 fork与execve的区别与联系分析

通过实验可以总结出fork与execve的以下区别：

（1）**进程控制块处理方式：** fork为子进程申请新的进程控制块并复制父进程信息；execve直接修改当前进程的进程控制块，不创建新进程。

（2）**代码执行：** fork后父子进程执行相同代码；execve后进程执行全新的程序代码。

（3）**进程号：** fork创建新进程，获得新的PID；execve不改变进程号。

（4）**内存空间：** fork为子进程复制父进程的内存空间；execve用新程序的代码段和数据段替换当前进程的内存。

两者的联系在于：

（1）通常组合使用，先fork创建子进程，再在子进程中execve加载新程序。

（2）这种组合是Unix/Linux系统启动新程序的标准方式，既保证了进程隔离，又实现了程序切换。

（3）父进程通过fork创建子进程后仍能继续运行，而子进程通过execve加载执行新任务，实现了进程的并发执行。
