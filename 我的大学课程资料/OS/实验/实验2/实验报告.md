# 1. 实验目的和任务要求

本实验的目的是跟踪调试Linux 0.11操作系统在PC机上从CPU加电到完成初始化的完整过程，查看Linux 0.11启动后的状态和行为，从而加深对操作系统启动机制和工作方式的理解。

实验的主要任务包括：

1. 调试Linux 0.11在CPU加电后执行BIOS程序、引导程序（bootsect.asm）、加载程序（setup.asm）以及内核模块（head.s）的完整启动过程。

2. 观察启动过程中关键内存地址的变化，包括引导扇区加载、setup模块加载、内核模块加载以及移动等过程。

3. 理解Linux 0.11从实模式进入保护模式的过程。

4. 查看内核初始化完成后系统中的进程状态和进程间的父子关系。

5. 在Linux 0.11进入保护模式之前添加提示信息，加深对启动过程的理解。

# 2. 实验原理

## 2.1 操作系统启动流程

Linux 0.11操作系统的启动过程涉及多个阶段，从CPU加电到进入内核入口函数start，主要经历以下几个阶段：

### 2.1.1 BIOS阶段

CPU加电后，处理器从物理地址0xFFFF0处开始执行BIOS程序。BIOS完成硬件自检和初始化后，将软盘0号扇区（引导扇区，512字节）加载到物理地址0x7C00处，并跳转到该地址开始执行引导程序。

### 2.1.2 引导程序（bootsect.asm）

引导程序首先将自己从0x7C00移动到0x90000处继续执行，然后将setup.bin（4个扇区）加载到0x90200处，将内核模块linux011.bin加载到0x10000处，最后跳转到setup程序开始执行。

### 2.1.3 加载程序（setup.asm）

setup程序利用BIOS中断读取机器参数并保存到0x90000开始的内存区域，然后将内核模块从0x10000移动到0x00000处。随后加载中断描述符表寄存器（IDTR）和全局描述符表寄存器（GDTR），开启A20地址线，对8259A中断控制器重新编程，最后进入保护模式并跳转到地址0:0（即head.s的第一条指令）执行。

### 2.1.4 内核模块（head.s）

head.s执行时首先加载各段寄存器的值，重新设置中断描述符表IDT，将IDT中的256个表项指向一个哑中断子程序ignore_int。最后通过ret指令将预先压栈的start函数地址弹出到EIP寄存器，从而跳转到init/main.c文件中的start函数执行。

## 2.2 实模式与保护模式

实模式是CPU加电后的初始工作模式，使用段地址:偏移地址的方式访问内存，最大寻址空间为1MB。保护模式是80386及以上处理器的工作模式，通过段选择符和段描述符表实现内存保护和多任务管理，可以访问4GB的内存空间。

## 2.3 关键数据结构

全局描述符表（GDT）：保护模式下用于描述内存段信息的数据结构，每个描述符8字节，包含段基址、段限长、访问权限等信息。

中断描述符表（IDT）：保护模式下用于描述中断处理程序信息的数据结构，每个描述符8字节。

## 3.4 在进入保护模式前添加提示信息

为了在Linux 0.11进入保护模式前显示提示信息"Enter protected mode..."，需要修改boot/setup.asm文件。

### 3.4.1 修改setup.asm

在setup.asm文件第116行的cli指令之前添加如下代码：

```asm
mov ax, INITSEG
mov es, ax
mov ah, 0x03
xor bh, bh
int 0x10

mov cx, 24
mov bx, 0x0007
mov bp, msg_protected
mov ax, 0x1301
int 0x10

msg_protected:
    db "Enter protected mode..."
```

该代码通过BIOS中断int 0x10输出字符串。注意ES:BP必须指向字符串地址，因此需要为ES寄存器设置值为INITSEG。

### 3.4.2 修改hd.c

为避免后续显示内容覆盖提示信息，修改kernel/blk_drv/hd.c文件第203行，在输出"Partition table ok"之前添加两个回车换行：

```c
printf("\n\nPartition table%s ok.\n\r", (NR_HD>1)?s:"");
```

# 4. 实验的思考与问题分析

## 4.1 为什么Linux 0.11从软盘启动时要使用bootsect.bin和setup.bin两个程序？使用一个可以吗？它们各自的主要功能是什么？如果将setup.bin的功能移动到bootsect.bin文件中，则bootsect.bin文件的大小是否仍然能保持小于512字节？

答：必须使用两个程序，不能合并为一个。原因如下：

1. BIOS规定引导扇区大小必须为512字节，bootsect.bin必须严格符合这个限制。

2. bootsect.bin的主要功能是：
   - 将自己从0x7C00移动到0x90000
   - 加载setup模块到0x90200
   - 加载内核模块到0x10000
   - 跳转到setup执行

3. setup.bin的主要功能是：
   - 利用BIOS中断获取机器参数
   - 将内核模块从0x10000移动到0x00000
   - 加载IDT和GDT
   - 开启A20地址线

4. setup.bin占用4个扇区（2048字节），其功能代码远超512字节。如果将setup的功能移动到bootsect中，bootsect将无法保持在512字节以内，不符合BIOS对引导扇区的要求。

```asm
    mov bx, 0x0200        
    mov ax, 0x0200+SETUPLEN    
    int 0x13
    jnc ok_load_setup
```

# 5. 总结和感想体会

通过本次实验，我深入理解了Linux 0.11操作系统从CPU加电到完成初始化的完整启动过程。实验中通过Bochs调试器逐步跟踪了BIOS、bootsect、setup和head.s各个阶段的执行，观察了关键内存地址的变化，理解了实模式到保护模式的转换过程。

3. 理解了实模式和保护模式的区别。实模式下使用段地址:偏移地址访问内存，寻址空间有限；保护模式下使用段选择符和描述符表，可以访问更大的内存空间并提供内存保护机制。

4. 认识到操作系统启动过程中内存布局的重要性。不同的模块被加载到不同的内存位置，然后在适当的时候进行移动，这种精心设计的内存布局保证了启动过程的顺利进行。
