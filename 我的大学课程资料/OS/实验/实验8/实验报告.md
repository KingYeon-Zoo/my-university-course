## 1. 实验目的和任务要求

依据操作系统课程所介绍的段页式内存管理机制，本实验的目的是深入理解物理内存的分页管理方式、操作系统的段页式内存管理机制，包括段表、二级页表，以及逻辑地址、线性地址、物理地址的映射过程，并通过编程实现段页式内存管理上的内存共享，从而加深对操作系统内存管理的理解。

4. 实现基于共享内存的生产者-消费者问题解决方案。

## 2. 实验原理

### 2.1 物理内存管理

Linux 0.11内核将16MB物理内存划分为4KB大小的物理页，每个物理页的基地址按照4KB对齐，并按基地址由小到大编号为物理页框号(PFN)。内核使用mem_map字节数组管理所有物理页，数组元素值为0表示物理页空闲，值大于0表示被引用的次数。

### 2.2 段式内存管理

x86处理器保护模式下通过段选择符和段描述符实现分段机制。段选择符包含索引、TI标志和RPL字段，用于在GDT或LDT中定位段描述符。段描述符包含32位段基址和段限长等信息。逻辑地址由段选择符和段内偏移组成，通过段表映射得到线性地址。

### 2.3 页式内存管理

Linux 0.11采用二级页表结构。线性地址的高10位为页目录索引，中间10位为页表索引，低12位为页内偏移。CR3寄存器指向页目录基址，通过页目录项找到页表，再通过页表项找到物理页框号，最后加上页内偏移得到物理地址。

### 2.4 写时复制机制

为节约内存和加快进程创建速度，fork创建子进程时以只读方式共享父进程的物理页面。当任一进程执行写操作时产生页面异常中断，内核异常处理函数复制新物理页并设置可写标志，实现延迟复制。

### 2.5 按需加载机制

程序运行时并非一次性加载所有代码和数据。当访问未加载页面时产生缺页异常，内核异常处理函数从文件系统加载对应页面到内存并建立映射，使程序能立即开始执行。

## 4. 实验的思考与问题分析

### 4.1 思考题1

**问题：** 列出逻辑地址映射为物理地址过程中最重要的几步。

**答：**

1. 从段寄存器(如DS)获取段选择符，提取TI标志和索引值
2. 根据TI标志确定在GDT或LDT中查找，根据索引值定位段描述符
3. 从段描述符提取段基址，与偏移量相加得到线性地址
4. 从线性地址提取页目录索引(高10位)、页表索引(中10位)、页内偏移(低12位)
5. 从CR3寄存器获取页目录基址，根据页目录索引找到页目录项
6. 从页目录项提取页表基址，根据页表索引找到页表项
7. 从页表项提取物理页框号，左移12位得到物理页基址
8. 物理页基址加上页内偏移得到最终物理地址

### 4.2 思考题2

**问题：** loop程序退出后再次运行并跟踪地址，会发现有哪些异同？说明原因。

**答：**

相同点：变量i的逻辑地址保持不变，段基址、页目录和页表的映射关系基本相同。

不同点：映射的物理页框号可能不同，这是因为第一次运行结束后物理页被释放，第二次运行时可能分配到不同的空闲物理页。另外，进程PID会增加，对应的LDT段基址也会不同。

原因：Linux 0.11的物理页分配采用动态分配策略，每次分配可能得到不同的空闲页。但逻辑地址由编译链接时确定，保持不变。

### 4.3 思考题3

**问题：** 在内核中编写系统调用，跟踪内核变量的地址映射过程。

**答：** 实现如下系统调用：

```c
volatile int i = 0x12345678;

void sys_testg()
{
    printk("The logical/virtual address of i is 0x%08x\n", &i);
    while(i);
}
```

在应用程序中调用该系统调用，按照任务二的方法跟踪地址映射。

**主要差异：**

1. 内核代码段和数据段的段基址为0，而应用程序段基址为0x10000000(进程6)
2. 内核变量的逻辑地址即为线性地址，应用程序需要加上段基址
3. 内核的物理地址与线性地址一致，映射关系固定
4. 内核变量存储在低地址空间，应用程序变量存储在高地址空间

### 4.4 思考题4

**问题：** 将变量i改为sys_testg函数的局部变量，体会全局变量与局部变量在逻辑地址空间中位置的不同。

**答：** 修改后的代码：

```c
void sys_testg()
{
    volatile int i = 0x12345678;
    printk("The logical/virtual address of i is 0x%08x\n", &i);
    while(i);
}
```

**差异分析：**

全局变量存储在数据段(.data段)，地址较低且固定。局部变量存储在栈中，地址较高且随函数调用动态分配。通过地址映射可以观察到，全局变量的逻辑地址在代码段之后的数据段区域，而局部变量的逻辑地址在栈区域，接近段限长上限。

### 4.5 思考题5

**问题：** 修改程序为一个生产者与多个消费者的情况。

**答：** 核心修改如下：

```c
// 将消费者的游标放入共享内存
struct shared_data {
    char buffer[BUFFER_SIZE];
    int consumer_index;  // 消费者共享游标
};

// 在生产者和消费者中使用共享游标
struct shared_data *shared = (struct shared_data *)shmat(shmid, NULL);

// 消费者取数据时使用P操作保护共享游标
P(mutex);
int index = shared->consumer_index;
data = shared->buffer[index];
shared->consumer_index = (index + 1) % BUFFER_SIZE;
V(mutex);
```

关键是将消费者游标放入共享内存，并用信号量保护对游标的并发访问。

### 4.6 思考题6

**问题：** 实现shmdt系统调用解决物理页重复释放问题。

**答：**

1. 定义共享内存结构体：

```c
struct shm_struct {
    unsigned long addr;  // 物理页基址
    int count;           // 引用计数
};

struct shm_struct shm_vector[SHM_SIZE];
```

2. 实现cancel_mapping函数：

```c
void cancel_mapping(const void *linearaddr)
{
    unsigned long *page_table;
    unsigned long page_dir_entry;
    unsigned long linear = (unsigned long)linearaddr;
    
    page_dir_entry = ((unsigned long *)0)[linear >> 22];
    page_table = (unsigned long *)(0xFFFFF000 & page_dir_entry);
    page_table[(linear >> 12) & 0x3FF] = 0;
}
```

3. 实现sys_shmdt函数：

```c
void sys_shmdt(int key, const void *shmaddr)
{
    unsigned long linearaddr;
    
    if (key < 0 || key >= SHM_SIZE || shm_vector[key].count <= 0)
        return;
    
    linearaddr = current->start_code + (unsigned long)shmaddr;
    cancel_mapping((void *)linearaddr);
    
    shm_vector[key].count--;
    if (shm_vector[key].count == 0) {
        free_page(shm_vector[key].addr);
        shm_vector[key].addr = 0;
    }
}
```

4. 修改sys_shmget增加引用计数：

```c
int sys_shmget(int key, int size)
{
    if (key < 0 || key >= SHM_SIZE || size > PAGE_SIZE)
        return -1;
    
    if (shm_vector[key].addr == 0) {
        shm_vector[key].addr = get_free_page();
        shm_vector[key].count = 0;
    }
    shm_vector[key].count++;
    return shm_vector[key].addr;
}
```

5. 在生产者和消费者退出前调用shmdt：

```c
shmdt(key, startaddress);
```

### 4.7 思考题7

**问题：** 设计4GB物理内存的操作系统初始化方案。

**答：**

1. **全局描述符表：** 至少包含4个描述符：
   - 空描述符(索引0)：全0
   - 内核代码段(索引1)：段基址0x00000000，段限长0xFFFFF，粒度G=1(4KB)，类型为可执行可读
   - 内核数据段(索引2)：段基址0x00000000，段限长0xFFFFF，粒度G=1(4KB)，类型为可读写
   - TSS段描述符等

2. **CS、DS寄存器值：** CS=0x0008(指向代码段)，DS=0x0010(指向数据段)

3. **页目录：** 物理页框号为0，页目录包含1024个页目录项，每项映射4MB线性地址空间，需要全部1024项映射完整4GB空间

4. **页表：** 
   - 第一个页表物理页框号为1，页表项值：第0项=0x00000003(映射物理页0，存在、可写)，第1项=0x00001003(映射物理页1)，...，第1023项=0x003FF003(映射物理页1023)
   - 其他页表类似，第n个页表映射物理页n×1024到(n+1)×1024-1

5. **占用物理页：** 页目录1个 + 页表1024个 = 1025个物理页
