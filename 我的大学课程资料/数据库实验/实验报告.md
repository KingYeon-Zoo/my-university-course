# 实验一 数据库的创建和删除

## 一、实验目的

1. 了解SQL Server 2008数据库管理系统的操作环境；
2. 学习SQL Server Management Studio管理平台的使用；
3. 理解SQL Server数据库服务器用户登录的特点与过程；
4. 掌握使用SQL 语句创建和删除数据库。

## 二、实验要求

1. 学会SQL Server Management Studio中利用查询窗口进行交互式SQL语句的编写与执行方法。
2. 用SQL语句创建第一个属于你自己的数据库EDUC。
3. 注意实验过程的截图与保存，供撰写实验报告使用。

## 三、实验内容

1. 使用SQL语句创建数据库EDUC。
   数据库的参数要求：
   数据库名称：EDUC
   数据库存储路径：将数据库文件存储在D:\MYDB\ 文件夹中。
   其他参数要求：
   数据文件的初始大小：10M 最大：60M 按5%的比例自动增长。
   日志文件的初始大小：4M 最大：10M 增量为1M。
2. 创建另一个数据库TestDB，参数与EDUC相同。
3. 用SQL语句删除数据库TestDB。
4. 将EDUC数据库设置为当前数据库。

## 四、实验步骤

1. 打开SQL Server Management Studio (SSMS) 平台并连接到数据库服务器。
2. 点击“新建查询”以打开交互式SQL查询窗口。
   ![alt text](image-2.png)
3. 编写并执行创建 `EDUC` 数据库的SQL语句：
   ```sql
   CREATE DATABASE EDUC
   ON PRIMARY
   ( NAME = 'EDUC_Data',
     FILENAME = 'D:\MYDB\EDUC_Data.mdf',
     SIZE = 10MB,
     MAXSIZE = 60MB,
     FILEGROWTH = 5% )
   LOG ON
   ( NAME = 'EDUC_Log',
     FILENAME = 'D:\MYDB\EDUC_Log.ldf',
     SIZE = 4MB,
     MAXSIZE = 10MB,
     FILEGROWTH = 1MB );
   ```
4. 编写并执行创建 `TestDB` 数据库的SQL语句（参数与 `EDUC` 相同）：

   ```sql
   CREATE DATABASE TestDB
   ON PRIMARY
   ( NAME = 'TestDB_Data',
     FILENAME = 'D:\MYDB\TestDB_Data.mdf',
     SIZE = 10MB,
     MAXSIZE = 60MB,
     FILEGROWTH = 5% )
   LOG ON
   ( NAME = 'TestDB_Log',
     FILENAME = 'D:\MYDB\TestDB_Log.ldf',
     SIZE = 4MB,
     MAXSIZE = 10MB,
     FILEGROWTH = 1MB );
   ```

   ![alt text](image-6.png)

5. 编写并执行删除 `TestDB` 数据库的SQL语句：
   ```sql
   DROP DATABASE TestDB;
   ```
6. 使用 `USE EDUC;` 语句将 `EDUC` 数据库设置为当前操作数据库。

## 五、实验小结

这是数据库课程的第一次实验，虽然任务看起来只是简单的“建库”和“删库”，但在实际操作中我才发现里面门道不少。刚打开 SQL Server Management Studio 时，面对复杂的界面其实有点无从下手。跟着步骤一步步敲入 `CREATE DATABASE` 语句，特别是自己去配置数据文件和日志文件的初始大小、最大容量还有增长比例时，我对“数据库不仅仅是一个文件，而是一个需要精细管理的系统”有了最直观的感受。期间也因为粗心写错路径报错过，但在排查错误后成功建库那一刻，还是挺有成就感的。这次实验不仅帮我跨过了工具使用的门槛，也为后面要做的各种复杂操作打好了底子。

## 四、实验步骤

1. 在查询窗口中，确保当前数据库为 `EDUC`。
2. 依次使用 `CREATE TABLE` 语句创建系、专业、教师、学生、课程、学生选课6个基本表：

   ```sql
   CREATE TABLE Department (
    DeptID CHAR(4) PRIMARY KEY,           -- 系编号，主键
    DeptName VARCHAR(20) NOT NULL,        -- 系名称，非空
    DeptHead CHAR(10),                    -- 系主任
    Phone VARCHAR(20),                    -- 联系电话
    Address VARCHAR(40)                   -- 地址
   );


   CREATE TABLE Major (
   MajorID CHAR(2) PRIMARY KEY, -- 专业编号，主键
   MajorName VARCHAR(40) NOT NULL, -- 专业名称，非空
   DeptID CHAR(4), -- 所属系（外键）
   FOREIGN KEY (DeptID) REFERENCES Department(DeptID) -- 外键约束
   );

   CREATE TABLE Teacher (
   TeacherID CHAR(10) PRIMARY KEY, -- 教师编号，主键
   Name CHAR(10) NOT NULL, -- 姓名，非空
   DeptID CHAR(4), -- 所在系（外键）
   Phone VARCHAR(20), -- 电话
   Email VARCHAR(30), -- 电子信箱
   FOREIGN KEY (DeptID) REFERENCES Department(DeptID) -- 外键约束
   );

   CREATE TABLE Student (
   StudentID CHAR(10) PRIMARY KEY, -- 学号，主键
   Name VARCHAR(20) NOT NULL CONSTRAINT UQ_Student_Name UNIQUE, -- 姓名，非空，并命名唯一约束为UQ_Student_Name
   Gender CHAR(2) CHECK(Gender IN ('男', '女')), -- 性别，只能是'男'或'女'
   BirthDate DATETIME, -- 出生日期
   MajorID CHAR(2), -- 所学专业（外键）
   FOREIGN KEY (MajorID) REFERENCES Major(MajorID) -- 外键约束
   );

   CREATE TABLE Course (
   CourseID CHAR(4) PRIMARY KEY, -- 课程号，主键
   CourseName VARCHAR(30), -- 课程名
   Credit DECIMAL(2,1), -- 学分（例如：3.0）
   PreCourseID CHAR(4), -- 先修课（外键）
   FOREIGN KEY (PreCourseID) REFERENCES Course(CourseID) -- 自引用外键
   );

   CREATE TABLE StudentCourse (
   StudentID CHAR(10), -- 学号（外键）
   CourseID CHAR(4), -- 课程号（外键）
   Score DECIMAL(4,1) CHECK(Score >= 0 AND Score <= 100), -- 成绩，0-100之间
   PRIMARY KEY (StudentID, CourseID), -- 复合主键
   FOREIGN KEY (StudentID) REFERENCES Student(StudentID), -- 外键约束
   FOREIGN KEY (CourseID) REFERENCES Course(CourseID) -- 外键约束
   );
   ```

# 实验四 数据库的分离和附加

## 一、实验目的

理解数据库为何要进行分离和附加？掌握数据库的分离和附加的具体操作方法。

## 二、实验要求

1．将创建的数据库EDUC进行分离并拷贝到U盘。
2．注意操作结果的截图与保存，供撰写实验报告使用。

## 三、实验内容

1. 数据库的分离
   当SQL Server服务器运行时，该服务器上所有的数据库自动处于运行状态，而运行中的数据库文件是无法进行数据库文件的拷贝的。实验任务完成后，往往需要将数据库文件，以及在实验过程中产生的各种资料拷贝到U盘保存起来。
   本实验的目的就是将需要拷贝的数据库（如EDUC）从数据库服务器上分离出来，使其处于非运行状态，从而可以正常进行数据库文件的拷贝。
2. 数据库附加
   数据库附加是为了将某个数据库的文件附加在数据库服务器上，使其处于运行状态。比如：学生在上一次实验结束后，通过数据库分离，将数据库的文件拷贝在自己的U盘上，下一次实验时对U盘上的数据库文件进行附加，该数据库中原有的数据对象及数据可以正常使用。

## 四、实验步骤

1. 数据库分离
   在分离数据库之前，必须确保没有其他用户或进程正在使用该数据库。如果有活动连接，分离操作可能会失败。
   首先将当前操作数据库切换到系统数据库 `master`，然后使用 `sp_detach_db` 系统存储过程执行分离操作。
   在 SSMS 的“新建查询”窗口中执行以下 SQL 语句：

   ```sql
   -- 切换到 master 数据库
   USE master;
   GO

   -- 分离数据库 EDUC
   -- 执行成功后，EDUC 数据库将从“对象资源管理器”中移除，但物理文件仍保留在磁盘上
   EXEC sp_detach_db @dbname = 'EDUC';
   ```

![alt text](image-20.png)

2. 拷贝数据库文件
   数据库成功分离后，其对应的数据文件和日志文件不再被 SQL Server 锁定，可以进行正常的系统文件级复制操作。
   打开计算机的文件资源管理器，导航到之前设定的数据库存储路径（例如 `D:\MYDB\`）。
   找到 `EDUC_Data.mdf`（主数据文件）和 `EDUC_Log.ldf`（事务日志文件），选中并将这两个文件复制保存到 U 盘中。

3. 数据库附加
   在需要恢复或迁移数据库时，先将 U 盘中的 `.mdf` 和 `.ldf` 文件拷贝到目标计算机的本地磁盘目录中（例如 `D:\MYDB\`）。
   然后可以通过 SSMS 界面进行附加操作：
   1. 首先在 SQL Server Management Studio (SSMS) 的“对象资源管理器”中，右键点击“数据库”节点，在快捷菜单中选择“附加...”。
   2. 接着在弹出的“附加数据库”对话框中，点击右侧的“添加”按钮。
   3. 然后在文件选择对话框中，浏览并选中刚刚拷贝到磁盘上的 `EDUC_Data.mdf` 主数据文件，点击“确定”。
   4. SQL Server 会自动识别同级目录下的日志文件。检查下方“数据库详细信息”列表中是否已正确显示数据文件和日志文件的路径。
   5. 最后点击“确定”按钮完成附加。此时，`EDUC` 数据库将重新恢复到可用状态，并出现在“对象资源管理器”中。

   ![alt text](image-23.png)

## 五、实验小结

分离和附加数据库这个操作，听起来像是纯纯的“运维工作”，但在实际学习和做项目的过程中真的太有用了。之前我一直有个疑问：为什么不能直接像复制 Word 文档一样把 `.mdf` 文件拷走？通过这次实验我彻底明白了，运行中的数据库是被系统锁定保护的。看着执行 `sp_detach_db` 后数据库从资源管理器里“消失”，再成功把它从 U 盘附加到其他环境里，整个过程有一种“把沉重的数据打包带走”的踏实感。这不仅解决了我之后在机房和自己电脑之间同步实验数据的痛点，也让我对 SQL Server 底层是如何管理物理文件和逻辑数据库之间的映射关系有了更深的理解，感觉自己对数据库的掌控感又强了几分。


恢复时：

```bash
docker cp ~/Desktop/educ_backup.sql opengauss:/home/omm/educ_backup.sql

docker exec -it opengauss bash
su - omm
gsql -d postgres -p 5432 -c "CREATE DATABASE educ_restore ENCODING 'UTF8' TEMPLATE template0;"
gsql -d educ_restore -p 5432 -f /home/omm/educ_backup.sql
```

## 五、实验小结

做完这次增删改的实验，最大的感触就是：数据库真的比我想象中要“严格”得多。以前觉得 `INSERT` 和 `UPDATE` 挺简单的，无非就是加点数据、改改字段。但这次按着参照完整性的要求去插入数据（先插系表、再插专业表、最后才是学生表），才发现顺序一旦搞反就会直接报错。尤其是后来故意去插入重复的系编号，或者给学生分配不存在的专业号时，看到 SSMS 弹出红色的报错拦截信息，反而让我觉得挺有安全感的——这说明实体完整性和参照完整性确实在底层死死把关，防止了“脏数据”混进系统。

```sql
CREATE TABLE dept (
```

8. 创建、测试并删除触发器

在 openGauss 中创建触发器时，需要先创建触发器函数，再创建触发器。下面创建一个在选课表插入记录后自动更新课程表选课人数的触发器。

```sql
CREATE OR REPLACE FUNCTION fn_sc_insert()
RETURNS trigger AS $$
BEGIN
    UPDATE course
    SET select_count = select_count + 1
    WHERE cno = NEW.cno;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

```sql
CREATE TRIGGER tr_sc_insert
AFTER INSERT ON sc
FOR EACH ROW
EXECUTE PROCEDURE fn_sc_insert();
```

插入一条新的选课记录，观察课程表中对应课程的选课人数是否发生变化。

```sql
INSERT INTO sc VALUES ('20180001', 'C102', 88);

SELECT cno, cname, select_count
FROM course
WHERE cno = 'C102';
```

实验完成后，删除触发器和触发器函数。

```sql
DROP TRIGGER tr_sc_insert ON sc;
DROP FUNCTION fn_sc_insert();
```

在 openGauss 中创建无参数存储过程，用于查询学生表中的所有学生信息。

```sql
CREATE OR REPLACE PROCEDURE proc_query_all_students()
AS

    SELECT * FROM student;
END;
```

创建带输入参数的存储过程，根据学号查询学生信息。

```sql
CREATE OR REPLACE PROCEDURE proc_query_student_by_sno(IN p_sno CHAR(10))
AS
BEGIN
    SELECT sno, sname, ssex, sage
    FROM student
    WHERE sno = p_sno;
END;
/

```

