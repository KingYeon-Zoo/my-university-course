# **实验六 数据更新操作**

**一. 实验目的**

1. 掌握INSERT/UPDATE/DELETE语句的使用。
2. 体会数据更新操作对完整性约束的影响。

**二. 实验准备**

1. 准备基本表中的数据。

2. 保证第一次实验中创建的数据库及基本表可以正常使用。

3. 准备一些违反完整性约束规则的数据，要求涉及：实体完整性、参照完整性和用户定义的完整性。

**三. 实验要求**

1. 元组要求，系信息表的元组不少于4个，专业表不少于8个，学生表不少于15个，课程表不少于10个，选课表SC的元组不少于20。
2. 注意操作结果的截图与保存，供撰写实验报告使用。

**四. 实验内容**

1. 数据插入操作

依次将准备好的数据用Insert Into语句将数据插入相应的基本表：

1. 正确数据的插入插入，这些数据应该不会违反完整性约束
2. 注意基本表的先后插入顺序，体会参照完整性。特别要注意课程表的数据插入与其他基本表的不同。
3. 对每一个基本表，插入错误的数据，这些数据应该是事先准备好，且违反了基本表的某一个约束条件的。

2．数据修改

用Update 语句完成下列任务：

（1）修改某位学生的专业号，要求包括：修改语句成功执行和修改操作被拒绝两种情形。

（2）修改某门课学生的成绩，学生、课程及成绩由学生自行确定。

（3）将选课表中50\~59之间的成绩整体增加10分。

（4）将“Java语句”课程的先修课改为“c209”。（可根据表中数据调整条件数据）

3. 数据删除

用Delete from语句完成下列任务：

1. 先在学生表中插入一个专业号为空值的元组。
2. 删除学生表中所有未设定专业号的学生。

**五、实验步骤：**

在SQL Server Management Studio的查询窗口中，将EDUC设置为当前数据库，根据实验内容的要求，分别完成：数据插入、数据修改和数据删除任务。

# **实验七 数据查询**

    - **实验目的**

1. 熟悉SQL Server交互式使用Select语句的方法；
2. 掌握执行和检查SELECT语句结果的方法；
3. 熟练运用单表查询、多表查询、嵌套查询等完成实际查询要求。

    - **实验准备**

1. 在EDUC数据库中已经建立教学管理系统的6个基本表。
2. 完成了实验六的任务。
3. 学会在SQL Server Management Studio的查询窗口中编辑和执行SELECT语句的方法。

    - **实验要求**

1.完成所要求的全部查询。

2.注意操作结果的截图与保存，供撰写实验报告使用。

    - **实验内容**

1. 单表查询

（1）查询全体学生的信息；

（2）根据专业编号查询学生的学号、性别和年龄；

（3）查询未设定先修课的所有课程的信息；

（4）查询选修了‘C101’（学生自学设定课程号）号课程，且成绩达到80分的学号。

2. 多表连接查询

（1）查询“计算机系”全体学生的学号、姓名、专业名称；

（2）查询非“软件工程”专业，年龄小于20的学生信息；

（3）查询先修课是“操作系统”的所有课程的信息；

（4）查询至少选修了‘c110’和‘c210’（课程号由学生自学确定！）课程的学生学号和姓名；

（5）查询未选修“计算机网络”课程的学生学号、姓名、性别和专业号；

（6）查询未选修任何课程的学生学号和姓名。

（7）查询未被学生选修的课程号、课程名、先修课。

（8）用派生关系查询平均成绩达到90分的学生学号、姓名和平均成绩。

（9）查询学生的学号，只要先修课是“c331”的课程他们都选修了。

（10）查询未参加课程“c209”考试的学生名单（学号、姓名、专业号）。

    - **实验步骤**

在SQL Server Management Studio的查询窗口中，将EDUC设置为当前数据库，根据实验内容的要求，完成所要求的查询。

# **实验九 视图的定义与使用**

**一．实验目的**

1.熟悉和掌握对数据表中视图的查询操作和SQL语句的使用；

2.熟悉和掌握对数据表中视图的更新操作和SQL语句的使用，并注意视图更新与基本表更新的区别与联系；

3.学习灵活熟练的进行视图的操作，认识视图的作用。

**二．实验准备**

１.EDUC数据库。

２.复习有关视图操作的SQL语句。

**三．实验要求**

1. 在实验开始之前做好准备工作。
2. 思考视图和基本表的区别。
3. 注意操作结果的截图与保存，供撰写实验报告使用。

**四．实验内容**

1.定义视图

在EDUC数据库中，已Student、Course 和SC表为基础完成一下视图定义:

1. 定义视图V\_SC\_G：该视图包含Student、 Course 和SC表中学生的学号、姓名、课程号、课程名和成绩；
2. 定义一个反映学生出生年份的视图V\_YEAR，该视图要求使用系统函数来获取当前日期及转换；
3. 定义视图V\_AVG\_S\_G：该视图将反映学生选修课程的门数及平均成绩；
4. 定义视图V\_AVG\_C\_G：该视图将统计各门课程的选修人数及平均成绩；
5. 定义一个学生表的行列子集视图V\_S：该视图包含学生的学号、姓名、专业号；
6. 定义一个视图V\_SC：该视图包含学号、姓名、课程号、成绩。

2.使用视图（下列操作只允许对视图进行）

1. 查询以上所建的视图结果。
2. 查询平均成绩为90分及以上的学生学号、姓名和成绩。
3. 查询科目成绩大于平均成绩的学生学号、课程号、成绩和平均成绩。
4. 查询2000年出生的学生学号和姓名。
5. 将学生“张三”的专业号改为“03” （数据视实际数据而定）。
6. 利用视图V\_SC将学号为“20180001”、课程号为“c111”的成绩改为85分。

**五. 实验步骤**

在SQL Server Management Studio的查询窗口中，将EDUC设置为当前数据库，根据实验内容的要求，完成所要求的查询。

# **实验十 触发器的定义与使用**

**一．实验目的**

1.熟悉和掌握触发器的创建、使用和删除操作；

2.深入理解触发器在数据完整性、安全性及业务逻辑实现中的作用；

3.提升在 SQL Server数据库环境下创建和运用触发器的能力。

**二、实验准备**

1.在 SQL Server的 EDUC 数据库中，确保学生表（Student）、课程表（Course）及选课表（SC）等基本表已正确创建并插入了实验六要求的数据，以保障实验的顺利开展。

2.复习触发器的相关概念、类型（如 INSERT 触发器、UPDATE 触发器、DELETE 触发器）以及创建触发器的语法格式，明确触发器的触发时机和作用范围，为实验做好知识储备。

**三、实验要求**

1.在实验开始前，仔细检查数据库连接是否正常，表结构是否完整，数据是否准确，确保实验环境的稳定性。

2.对于每个触发器的创建、使用及删除操作，都要进行详细的记录，包括编写的 SQL 语句、执行结果以及遇到的问题和解决方法，以便撰写实验报告时使用。

3.在 SQL Server 和 openGauss 两种数据库中分别完成以下实验内容，对比分析两种数据库在触发器实现上的异同点，加深对触发器的理解和掌握。

**四、实验内容**

1.创建一个触发器TR\_SC\_Insert，当向选课表SC插入新记录时，自动更新课程表Course中的“选课人数”字段。

**测试步骤：**

插入一条选课记录，验证Course表中对应课程的选课人数是否增加。

尝试插入违反参照完整性的选课记录（如不存在的课程号），观察触发器是否阻止操作。

2.创建一个触发器TR\_Student\_Update，当修改学生表Student的“专业号”字段时，检查新专业号是否存在于专业表中。若不存在，则回滚操作。

**测试步骤：**

将某学生的专业号修改为存在的值，验证操作成功。

将某学生的专业号修改为不存在的值，验证操作被拒绝。

3.删除触发器

在实验结束后，分别删除之前创建的TR\_SC\_Insert和TR\_Student\_Update触发器，以清理实验环境，避免触发器对后续其他操作或实验产生不必要的影响。

**五. 实验步骤**

在SQL Server Management Studio的查询窗口中，将EDUC设置为当前数据库，根据实验内容的要求，完成所要求的查询。

# **实验十一 存储过程的定义与调用**

**一．实验目的**

1.熟悉和掌握存储过程的创建、执行和删除操作，深入理解存储过程在封装复杂业务逻辑、提高程序执行效率、减少网络传输等方面的优势。

2.学会在 SQL Server 数据库环境下，灵活运用存储过程来完成特定的数据操作任务，提升在不同数据库系统上的编程能力。

3.掌握存储过程的参数传递机制，包括输入参数和输出参数的使用方法，能够根据实际需求设计带有参数的存储过程，增强存储过程的通用性和灵活性。

**二、实验准备**

1.确保 SQL Server 的 EDUC 数据库处于可用状态，学生表（Student）、课程表（Course）及选课表（SC）等基本表结构完整且数据充实，满足实验操作的需求，为存储过程的测试提供可靠的数据基础。

2.复习存储过程的相关知识，包括存储过程的定义、语法结构、参数类型（输入参数、输出参数、返回值等）以及创建、执行和删除存储过程的具体步骤，明确存储过程在数据库编程中的重要地位和作用，为实验做好充分的理论准备。

**三、实验要求**

1. 在实验开始前，仔细检查数据库连接是否正常，确认能够顺利连接到 SQL Server数据库，避免因连接问题影响实验进度。

2.  对于每个存储过程的创建、执行和删除过程，都要进行详细的记录，包括编写的 SQL 语句、参数设置、执行结果以及遇到的问题和解决方案，为撰写实验报告提供详实的资料。

3.  在 SQL Server 和 openGauss 中分别完成以下实验内容，对比两种数据库在存储过程语法和功能上的差异，总结经验，提高在不同数据库环境下开发存储过程的能力。

**四、实验内容**

1. 无参数存储过程：创建一个名为proc\_query\_all\_students的存储过程，其功能是查询学生表中的所有学生信息，并将查询结果显示出来。该存储过程不带任何参数，直接对学生表进行全表查询操作，适用于需要获取完整学生数据的场景，如学生信息列表展示等。

2.带输入参数存储过程：创建一个名为proc\_query\_student\_by\_sno的存储过程，该存储过程带有一个输入参数@sno nvarchar(10)。其功能是根据输入的学号（@sno），查询出对应的学生姓名（Sname）、性别（Ssex）和年龄（Sage），实现按学号查询特定学生信息的功能，提高数据查询的针对性和效率，适用于根据学号快速检索学生信息的应用需求。

3.执行以上存储过程。

4.删除存储过程

实验结束后，分别删除创建的proc\_query\_all\_students和proc\_query\_student\_by\_sno存储过程。

**五. 实验步骤**

在SQL Server Management Studio的查询窗口中，将EDUC设置为当前数据库，根据实验内容的要求，完成所要求的查询。
