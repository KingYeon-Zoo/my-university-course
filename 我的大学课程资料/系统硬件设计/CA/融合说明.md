## 📖 概述

本项目采用**条件编译策略**，将仿真代码和上板验证代码融合到同一个工程中。通过简单的宏定义切换，可以在两种模式间灵活切换：

- **仿真模式**: 用于testbench仿真验证，不包含FPGA硬件接口
- **上板模式**: 用于FPGA开发板验证，包含LED、数码管等硬件接口

### ✨ 优点

✅ 一套代码，两种用途  
✅ 避免维护多个版本  
✅ 通过宏定义快速切换  
✅ 保持核心逻辑一致性  
✅ 降低出错风险

## 🎯 融合策略

### 条件编译机制

使用Verilog的预处理指令 `` `ifdef`` 和 `` `endif`` 实现条件编译：

```verilog
`ifdef FPGA_BOARD
    // 上板模式下的代码
    output [15:0] leds,
    output [7:0] seg
`endif
```

### 修改的模块

| 模块 | 修改内容 | 说明 |
|------|---------|------|
| **SYSTEM_DEF.vh** | 添加 `FPGA_BOARD` 宏定义 | 全局模式切换开关 |
| **RF.v** | 添加调试读端口 | 用于读取寄存器值显示到LED/数码管 |

| **seven_seg_driver.v** | 提取到RTL目录 | 七段数码管驱动模块 |

## 🔧 模式切换方法

### 方法一：修改 SYSTEM_DEF.vh（推荐）

打开 `SYSTEM_DEF.vh` 文件，找到以下部分：

```verilog
//=============================================================================
// 工作模式选择
//=============================================================================

// *** 仿真模式 (默认) ***
// 如需上板验证，请取消下面一行的注释:
// `define FPGA_BOARD

// *** 上板验证模式 ***
// 如需仿真验证，请注释下面一行:
// `define FPGA_BOARD
```

**切换到仿真模式**:
```verilog
// `define FPGA_BOARD    // 注释掉这一行
```

**切换到上板模式**:
```verilog
`define FPGA_BOARD      // 取消注释
```

### 方法二：Vivado编译选项

在Vivado中，也可以通过全局宏定义来切换：

1. 打开 Vivado 工程
2. `Tools` → `Settings` → `Compilation`
3. 在 `Verilog Options` 中添加 `-define FPGA_BOARD`

## 📝 使用步骤

### 🖥️ 仿真模式使用

#### Step 1: 确认仿真模式
打开 `SYSTEM_DEF.vh`，确保 `FPGA_BOARD` 被注释：
```verilog
// `define FPGA_BOARD    // 注释掉
```

#### Step 2: 在Vivado中仿真
1. 打开 `CA/CA.xpr` 工程
2. 确认顶层模块为 **RISCV_CPU_tb**
3. 设置仿真文件：`RISCV_CPU_tb.v`
4. 点击 `Run Simulation` → `Run Behavioral Simulation`

#### Step 3: 查看波形
- 观察PC、寄存器、ALU结果等信号
- 验证指令执行的正确性

---

### 🔌 上板验证模式使用

#### Step 1: 切换到上板模式
打开 `SYSTEM_DEF.vh`，取消 `FPGA_BOARD` 的注释：
```verilog
`define FPGA_BOARD      // 取消注释
```

#### Step 2: 在Vivado中设置

##### 方法A：使用现有工程
1. 打开 `CA/CA.xpr` 工程
2. 将顶层模块改为 **RISCV_CPU_Wrapper**
   - 在 Sources 窗口右键 `RISCV_CPU_Wrapper.v`
   - 选择 `Set as Top`
3. 添加约束文件：
   - 右键 `Constraints` → `Add Sources`
   - 选择 `constraints/RISCV_CPU.xdc`
4. 添加源文件（如果未添加）：
   - 确保 `RTL/RISCV_CPU_Wrapper.v` 和 `RTL/seven_seg_driver.v` 在工程中

##### 方法B：使用上板验证工程
1. 打开 `上板验证文件/New-CPU.xpr`
2. 该工程已配置好所有设置

#### Step 3: 综合与实现
1. 点击 `Run Synthesis`
2. 等待综合完成（约1-3分钟）
3. 点击 `Run Implementation`
4. 等待实现完成（约3-5分钟）
5. 点击 `Generate Bitstream`

#### Step 4: 烧录到FPGA
1. 连接EGO1开发板到电脑
2. 点击 `Open Hardware Manager`
3. 点击 `Auto Connect`
4. 右键设备 → `Program Device`
5. 选择生成的 `.bit` 文件
6. 点击 `Program`

#### Step 5: 验证功能
- **LED[7:0]**: 观察x1寄存器低8位的值
- **LED[15:8]**: 观察PC低8位的变化
- **数码管**: 显示x2寄存器的32位值（十六进制）
- **复位按钮**: 按下复位，观察CPU重新启动

## ⚠️ 注意事项

### 1. 模式切换前的检查

✅ **仿真模式切换到上板模式**:
- 确认 `FPGA_BOARD` 宏已定义
- 确认顶层模块为 `RISCV_CPU_Wrapper`
- 确认约束文件已添加

✅ **上板模式切换到仿真模式**:
- 确认 `FPGA_BOARD` 宏已注释
- 确认顶层模块为 `RISCV_CPU_tb`
- 可以移除约束文件

### 2. 编译顺序

修改 `SYSTEM_DEF.vh` 后，需要：
1. 清除之前的编译结果（可选但推荐）
2. 重新运行综合/仿真

### 3. 约束文件匹配

确保约束文件 `RISCV_CPU.xdc` 中的端口名与 `RISCV_CPU_Wrapper.v` 中的端口名**完全一致**。

当前匹配关系：
| 约束文件端口 | Wrapper端口 | 说明 |
|------------|-----------|------|
| sys_clk | sys_clk | 系统时钟 |
| aresetn | aresetn | 复位信号 |
| leds[15:0] | leds[15:0] | LED指示灯 |
| seg[7:0] | seg[7:0] | 第一组数码管段选 |
| an[7:0] | an[7:0] | 第一组数码管位选 |
| seg1[7:0] | seg1[7:0] | 第二组数码管段选 |
| debug_pc[31:0] | debug_pc[31:0] | PC调试输出 |

### 4. 时钟约束

约束文件中定义的时钟周期为 **10ns (100MHz)**：
```tcl
create_clock -name aclk -period 10.000 [get_ports sys_clk]
```

如需修改时钟频率，需同时修改：
- 约束文件中的 `period` 值
- `seven_seg_driver.v` 中的分频系数

### 5. 数据存储器初始化

- **仿真模式**: 使用 `testbench/IM.dat` 和 `DM.dat`
- **上板模式**: 指令和数据存储器需要在 `I_Mem.v` 和 `D_Mem.v` 中初始化

### 6. 调试技巧

**仿真调试**:
- 使用波形查看所有内部信号
- 可以观察流水线各阶段的状态
- 方便调试逻辑错误

**上板调试**:
- 通过LED观察关键寄存器值
- 通过数码管观察32位数据
- 使用逻辑分析仪连接 `debug_pc` 引脚观察PC变化
- 可以添加ILA (Integrated Logic Analyzer) 观察内部信号

## ❓ 常见问题

### Q1: 切换模式后编译出错？

**A**: 可能的原因：
1. 没有清除之前的编译结果
   - 解决: `Flow` → `Reset Runs` → 重新综合
2. 宏定义没有生效
   - 解决: 检查 `SYSTEM_DEF.vh` 中 `` `define FPGA_BOARD`` 是否正确注释/取消注释
3. 缺少源文件
   - 解决: 检查 `RISCV_CPU_Wrapper.v` 和 `seven_seg_driver.v` 是否在工程中

### Q2: 上板后LED和数码管不显示？

**A**: 检查以下几点：
1. 确认比特流已完全烧录成功
2. 按下复位按钮（aresetn）
3. 检查 `FPGA_BOARD` 宏是否已定义
4. 检查约束文件是否正确添加
5. 查看综合报告，确认没有端口被优化掉

### Q3: 仿真时找不到某些信号？

**A**: 这是正常的：
- 在仿真模式下，`FPGA_BOARD` 相关的调试接口不会被编译
- 如需查看寄存器值，在testbench中添加探针：
  ```verilog
  wire [31:0] reg_x1 = RISCV_CPU_tb.cpu.Register_File.GPR[1];
  ```

### Q4: 时序违例怎么办？

**A**: 如果在实现后报告时序违例：
1. 降低时钟频率（修改约束文件中的 period）
2. 添加流水线级数（高级优化）
3. 优化关键路径的逻辑
4. 查看 `timing_summary_routed.rpt` 定位问题

### Q5: 数码管显示乱码？

**A**: 可能原因：
1. 复位信号未正确连接
2. 时钟信号异常
3. `seven_seg_driver.v` 的分频系数不正确
4. 段选和位选信号极性错误（检查共阳/共阴）

### Q6: 如何添加更多调试信号？

**A**: 修改以下文件：

1. **在 RF.v 中添加更多调试端口**:
```verilog
`ifdef FPGA_BOARD
    input [`ADDR_WIDTH - 1:0] Debug_Addr3,
    output [`DATA_WIDTH - 1:0] Debug_Data3
`endif
```

2. **在 RISCV_CPU.v 中连接**:
```verilog
`ifdef FPGA_BOARD
    ,input [`ADDR_WIDTH - 1:0] Debug_Reg_Addr3,
    output [`DATA_WIDTH - 1:0] Debug_Reg_Data3
`endif
```

3. **在 RISCV_CPU_Wrapper.v 中使用**:
```verilog
.Debug_Reg_Addr3(5'd3),
.Debug_Reg_Data3(x3_value)
```

### Q7: 如何验证融合是否成功？

**A**: 按以下步骤验证：

1. **仿真验证**:
   - 注释 `FPGA_BOARD`
   - 运行仿真，确认testbench通过
   - 观察波形，验证功能正确

2. **上板验证**:
   - 定义 `FPGA_BOARD`
   - 综合实现无错误
   - 烧录到FPGA，LED和数码管正常显示

3. **来回切换测试**:
   - 仿真 → 上板 → 仿真，确认每次切换都能正常工作

## 🎓 总结

本融合方案采用**最小侵入性修改**，仅在必要的地方添加条件编译：

✅ **核心优势**:
- 一套代码，两种模式
- 通过简单的宏切换即可转换
- 保持核心CPU逻辑完全一致
- 降低维护成本和出错风险

✅ **适用场景**:
- 团队协作（一人仿真，一人上板）
- 课程设计（需要提交统一工程）
- 验证流程（先仿真验证，再上板验证）

✅ **扩展性**:
- 可以轻松添加更多调试信号
- 可以支持不同的FPGA开发板
- 可以根据需求定制显示内容
