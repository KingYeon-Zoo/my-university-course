# 实验一：算法伪代码设计的一般思路

## 题目1：最长公共子序列

## 一、实验内容和要求

本实验要求通过分析小规模具体实例，归纳、提炼并形式化描述最长公共子序列问题的通用算法步骤，最终产出规范的伪代码描述及设计过程报告。实验需要展示从问题定义、实例手工求解、思路提炼到伪代码撰写的完整思维过程。

## 二、问题背景和相关工作介绍

最长公共子序列（Longest Common Subsequence, LCS）问题是计算机科学中的经典问题，广泛应用于生物信息学中的DNA序列比对、文件差异比较（如diff工具）、版本控制系统等领域。

问题定义：给定两个序列X和Y，找出它们的最长公共子序列。子序列不要求连续，但必须保持相对顺序。

输入：两个序列X = <x1, x2, ..., xm>和Y = <y1, y2, ..., yn>

输出：X和Y的最长公共子序列的长度及具体序列

相关工作：该问题是动态规划的典型应用，由Wagner和Fischer在1974年提出了经典的动态规划算法，时间复杂度为O(mn)。

## 三、解题思路

### 3.1 问题实例化

选择两个小规模序列进行分析：

X = "ABCBDAB"（长度m=7）

Y = "BDCABA"（长度n=6）

### 3.2 手工求解过程记录

步骤1：首先尝试穷举思路

我像"笨电脑"一样开始思考：是否需要尝试所有可能的子序列？

X的所有子序列数量为2^7=128个，Y的所有子序列数量为2^6=64个，如果穷举所有可能再比较，工作量巨大。

步骤2：观察小规模匹配过程

手工比对过程：

1. 从X的第一个字符'A'开始，在Y中找到'A'（位置6）
2. 从X的第二个字符'B'开始，在Y中找到'B'（位置1或4）
3. 尝试构造：B（Y[1]）→D（Y[2]）→C（Y[3]）→A（Y[4]）→B（Y[5]）→A（Y[6]）

通过多次尝试，我发现了几个公共子序列：

1. "BDAB"（长度4）
2. "BCAB"（长度4）
3. "BCBA"（长度4）

步骤3：发现子问题结构

在手工比对时，我发现：

1. 如果X[i] = Y[j]，那么这个字符可以加入公共子序列
2. 如果X[i] ≠ Y[j]，需要考虑跳过X[i]或跳过Y[j]

关键观察：问题可以分解为更小的子问题。

步骤4：构造比对表格

我决定用表格记录比对过程，设c[i][j]表示X[1..i]和Y[1..j]的LCS长度：

```
    ""  B  D  C  A  B  A
""   0  0  0  0  0  0  0
A    0  0  0  0  1  1  1
B    0  1  1  1  1  2  2
C    0  1  1  2  2  2  2
B    0  1  1  2  2  3  3
D    0  1  2  2  2  3  3
A    0  1  2  2  3  3  4
B    0  1  2  2  3  4  4
```

填表规则：
1. 初始化：c[0][j]=0, c[i][0]=0
2. 如果X[i]=Y[j]：c[i][j] = c[i-1][j-1] + 1
3. 如果X[i]≠Y[j]：c[i][j] = max(c[i-1][j], c[i][j-1])

最终c[7][6]=4，说明LCS长度为4。

步骤5：回溯构造具体序列

从c[7][6]开始回溯：

1. c[7][6]=4，X[7]='B'，Y[6]='A'，不相等，c[7][5]=4，向左移
2. c[7][5]=4，X[7]='B'，Y[5]='B'，相等！记录'B'，移到c[6][4]
3. c[6][4]=3，X[6]='A'，Y[4]='A'，相等！记录'A'，移到c[5][3]
4. c[5][3]=2，X[5]='D'，Y[3]='C'，不相等，c[4][3]=2，向上移
5. c[4][3]=2，X[4]='B'，Y[3]='C'，不相等，c[3][3]=2，向上移
6. c[3][3]=2，X[3]='C'，Y[3]='C'，相等！记录'C'，移到c[2][2]
7. c[2][2]=1，X[2]='B'，Y[2]='D'，不相等，c[2][1]=1，向左移
8. c[2][1]=1，X[2]='B'，Y[1]='B'，相等！记录'B'，移到c[1][0]

反向得到：B→C→A→B，正向为"BCAB"，长度为4。

### 3.3 思路提炼与通用化

核心策略：动态规划

1. 子问题定义：c[i][j]表示X[1..i]和Y[1..j]的LCS长度

2. 递推关系（状态转移方程）：
   - 边界条件：c[i][0] = 0, c[0][j] = 0
   - 当X[i] = Y[j]时：c[i][j] = c[i-1][j-1] + 1
   - 当X[i] ≠ Y[j]时：c[i][j] = max(c[i-1][j], c[i][j-1])

3. 计算顺序：按行或按列，从小到大填表

4. 最优解构造：从c[m][n]回溯，根据转移方向构造LCS

可扩展性分析：即使m和n增大到1000，算法仍需要填充1000×1000=100万个表格项，每项计算时间为O(1)，总体可行。

## 四、算法伪代码

### 算法1：LCS长度计算

输入：序列X[1..m]和Y[1..n]

输出：二维数组c[0..m][0..n]，其中c[m][n]为LCS长度

```
LCS-LENGTH(X, Y, m, n)
    // 初始化边界条件
    for i = 0 to m
        c[i][0] = 0
    for j = 0 to n
        c[0][j] = 0
    
    // 动态规划填表
    for i = 1 to m
        for j = 1 to n
            if X[i] = Y[j]
                c[i][j] = c[i-1][j-1] + 1
                b[i][j] = "↖"  // 记录方向：左上
            else if c[i-1][j] >= c[i][j-1]
                c[i][j] = c[i-1][j]
                b[i][j] = "↑"  // 记录方向：向上
            else
                c[i][j] = c[i][j-1]
                b[i][j] = "←"  // 记录方向：向左
    
    return c, b
```

### 算法2：LCS序列回溯构造

输入：序列X[1..m]，方向数组b[1..m][1..n]，当前位置(i, j)

输出：打印LCS序列

```
PRINT-LCS(b, X, i, j)
    if i = 0 or j = 0
        return
    
    if b[i][j] = "↖"
        PRINT-LCS(b, X, i-1, j-1)
        print X[i]  // 当前字符属于LCS
    else if b[i][j] = "↑"
        PRINT-LCS(b, X, i-1, j)
    else
        PRINT-LCS(b, X, i, j-1)
```

### 算法复杂度分析

时间复杂度：
1. LCS-LENGTH：两层嵌套循环，每次O(1)操作，总时间O(mn)
2. PRINT-LCS：回溯路径长度最多m+n，时间O(m+n)
3. 总时间复杂度：O(mn)

空间复杂度：
1. 数组c需要O(mn)空间
2. 数组b需要O(mn)空间
3. 总空间复杂度：O(mn)

优化空间：如果只需要LCS长度而不需要构造序列，可以只保留c数组的两行，空间优化到O(min(m,n))。

## 七、实验结果分析

通过实验验证，动态规划算法能够正确计算最长公共子序列的长度并构造出具体序列。

算法正确性分析：
1. 边界条件正确：空序列与任何序列的LCS长度为0
2. 递推关系正确：字符匹配时长度加1，不匹配时取两个子问题的最大值
3. 最优子结构：问题的最优解包含子问题的最优解

性能分析：
1. 时间效率：O(mn)的时间复杂度对于中等规模的序列（如DNA片段比对）是可接受的
2. 空间效率：O(mn)空间在实际应用中可能较大，但可优化到O(min(m,n))

遇到的问题及解决方案：
1. 问题：初始尝试穷举所有子序列，发现复杂度为O(2^m × 2^n)，不可行
   解决：转向动态规划思路，利用子问题重叠性质

2. 问题：如何构造具体的LCS序列而不仅是长度
   解决：增加方向数组b记录状态转移方向，通过回溯构造序列

3. 问题：手工推演过程中容易出错
   解决：严格按照状态转移方程，逐行逐列填表，确保每步正确

改进空间：
1. 可以使用滚动数组技术将空间复杂度降低到O(min(m,n))
2. 对于超长序列，可以考虑使用Hirschberg算法，空间复杂度为O(min(m,n))但能构造完整LCS

## 八、总结

### 感想、体会、建议

通过本次实验，我深刻体会到了从具体实例到通用算法的思维过程：

1. 从实例出发的重要性：通过手工求解小规模实例，我发现了问题的子结构性质和重叠子问题特征，这是设计动态规划算法的关键。

2. 结构化思维的培养：从最初的穷举想法，到发现子问题结构，再到构造状态转移方程，整个过程训练了我将直观想法转化为形式化算法的能力。

3. 伪代码的价值：伪代码作为算法描述工具，既保持了算法的本质逻辑，又避免了编程语言细节的干扰，是沟通算法思想的最佳方式。

4. 验证的必要性：通过多个测试用例的手工推演，不仅验证了算法的正确性，也加深了对算法每个步骤的理解。

本次实验让我认识到，算法设计不是一蹴而就的，而是一个从问题分析、实例探索、模式发现到形式化描述的渐进过程。这种系统性的思维方法将对今后解决复杂算法问题大有裨益。
