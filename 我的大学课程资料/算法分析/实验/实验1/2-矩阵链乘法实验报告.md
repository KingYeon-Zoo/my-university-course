# 实验一：算法伪代码设计的一般思路

## 题目2：矩阵链乘法

## 一、实验内容和要求

本实验要求通过分析小规模具体实例，归纳、提炼并形式化描述矩阵链乘法问题的通用算法步骤，最终产出规范的伪代码描述及设计过程报告。实验需要展示从问题定义、实例手工求解、思路提炼到伪代码撰写的完整思维过程。

## 二、问题背景和相关工作介绍

矩阵链乘法问题是动态规划的经典应用之一，在科学计算、计算机图形学、数据库查询优化等领域有广泛应用。

问题定义：给定n个矩阵的链A1, A2, ..., An，其中矩阵Ai的维度为pi-1 × pi，如何确定计算矩阵链乘积的顺序，使得标量乘法次数最少。

关键性质：矩阵乘法满足结合律但不满足交换律，即(A1×A2)×A3 = A1×(A2×A3)，但不同的加括号方式会导致计算代价差异巨大。

输入：矩阵维度序列p = <p0, p1, p2, ..., pn>，其中矩阵Ai的维度为pi-1 × pi

输出：最优加括号方案及最少标量乘法次数

相关工作：该问题的动态规划解法时间复杂度为O(n³)，由Godbole在1973年首次提出。这是一个典型的最优化问题，展示了动态规划在组合优化中的强大能力。

## 三、解题思路

### 3.1 问题实例化

选择4个矩阵的链进行分析：

A1: 30 × 35

A2: 35 × 15

A3: 15 × 5

A4: 5 × 10

维度序列：p = <30, 35, 15, 5, 10>

### 3.2 手工求解过程记录

步骤1：理解计算代价

矩阵乘法基础：计算p × q矩阵与q × r矩阵的乘积，需要p × q × r次标量乘法。

例如，A1×A2（30×35的矩阵乘以35×15的矩阵）需要30 × 35 × 15 = 15750次标量乘法。

步骤2：穷举所有加括号方式

对于4个矩阵，可能的加括号方式有：

方式1：((A1×A2)×A3)×A4
1. 计算A1×A2：30 × 35 × 15 = 15750，结果为30×15
2. 计算(A1×A2)×A3：30 × 15 × 5 = 2250，结果为30×5
3. 计算((A1×A2)×A3)×A4：30 × 5 × 10 = 1500，结果为30×10
   总代价：15750 + 2250 + 1500 = 19500

方式2：(A1×(A2×A3))×A4
1. 计算A2×A3：35 × 15 × 5 = 2625，结果为35×5
2. 计算A1×(A2×A3)：30 × 35 × 5 = 5250，结果为30×5
3. 计算(A1×(A2×A3))×A4：30 × 5 × 10 = 1500，结果为30×10
   总代价：2625 + 5250 + 1500 = 9375

方式3：(A1×A2)×(A3×A4)
1. 计算A1×A2：30 × 35 × 15 = 15750，结果为30×15
2. 计算A3×A4：15 × 5 × 10 = 750，结果为15×10
3. 计算(A1×A2)×(A3×A4)：30 × 15 × 10 = 4500，结果为30×10
   总代价：15750 + 750 + 4500 = 21000

方式4：A1×((A2×A3)×A4)
1. 计算A2×A3：35 × 15 × 5 = 2625，结果为35×5
2. 计算(A2×A3)×A4：35 × 5 × 10 = 1750，结果为35×10
3. 计算A1×((A2×A3)×A4)：30 × 35 × 10 = 10500，结果为30×10
   总代价：2625 + 1750 + 10500 = 14875

方式5：A1×(A2×(A3×A4))
1. 计算A3×A4：15 × 5 × 10 = 750，结果为15×10
2. 计算A2×(A3×A4)：35 × 15 × 10 = 5250，结果为35×10
3. 计算A1×(A2×(A3×A4))：30 × 35 × 10 = 10500，结果为30×10
   总代价：750 + 5250 + 10500 = 16500

最优方案：方式2，总代价为9375次标量乘法。

步骤3：发现子问题结构

观察方式2：(A1×(A2×A3))×A4

关键发现：
1. 最优方案在A1和A2A3A4之间断开（记为k=1）
2. 子问题A2A3A3也需要最优加括号
3. 问题具有递归结构

步骤4：构造动态规划表格

定义m[i][j]为计算矩阵链Ai..Aj的最少标量乘法次数。

定义s[i][j]为最优断开位置k。

手工填表过程：

初始化（链长度为1）：

1. m[1][1] = 0（单个矩阵无需计算）
2. m[2][2] = 0
3. m[3][3] = 0
4. m[4][4] = 0

链长度为2：

1. m[1][2]：A1×A2，只有一种断开k=1
   代价：m[1][1] + m[2][2] + p0×p1×p2 = 0 + 0 + 30×35×15 = 15750
   s[1][2] = 1

2. m[2][3]：A2×A3，k=2
   代价：m[2][2] + m[3][3] + p1×p2×p3 = 0 + 0 + 35×15×5 = 2625
   s[2][3] = 2

3. m[3][4]：A3×A4，k=3
   代价：m[3][3] + m[4][4] + p2×p3×p4 = 0 + 0 + 15×5×10 = 750
   s[3][4] = 3

链长度为3：

1. m[1][3]：A1A2A3，尝试k=1和k=2
   k=1: m[1][1] + m[2][3] + p0×p1×p3 = 0 + 2625 + 30×35×5 = 7875
   k=2: m[1][2] + m[3][3] + p0×p2×p3 = 15750 + 0 + 30×15×5 = 18000
   最优k=1，m[1][3] = 7875，s[1][3] = 1

2. m[2][4]：A2A3A4，尝试k=2和k=3
   k=2: m[2][2] + m[3][4] + p1×p2×p4 = 0 + 750 + 35×15×10 = 6000
   k=3: m[2][3] + m[4][4] + p1×p3×p4 = 2625 + 0 + 35×5×10 = 4375
   最优k=3，m[2][4] = 4375，s[2][4] = 3

链长度为4：

1. m[1][4]：A1A2A3A4，尝试k=1, 2, 3
   k=1: m[1][1] + m[2][4] + p0×p1×p4 = 0 + 4375 + 30×35×10 = 14875
   k=2: m[1][2] + m[3][4] + p0×p2×p4 = 15750 + 750 + 30×15×10 = 21000
   k=3: m[1][3] + m[4][4] + p0×p3×p4 = 7875 + 0 + 30×5×10 = 9375
   最优k=3，m[1][4] = 9375，s[1][4] = 3

最终结果：
```
m数组：
    1      2      3      4
1   0   15750   7875   9375
2          0   2625   4375
3                 0    750
4                        0

s数组：
    1   2   3   4
1       1   1   3
2           2   3
3               3
```

步骤5：构造最优加括号方案

从s[1][4]=3回溯：

1. 在位置3断开：(A1A2A3) × (A4)
2. 查看s[1][3]=1：在位置1断开：(A1) × (A2A3)
3. 查看s[2][3]=2：在位置2断开：(A2) × (A3)

最优加括号方案：(A1×(A2×A3))×A4

验证：这正是我们手工穷举中的方式2，代价9375。

### 3.3 思路提炼与通用化

核心策略：动态规划

1. 子问题定义：m[i][j]表示计算矩阵链Ai..Aj所需的最少标量乘法次数

2. 递推关系：
   - 边界条件：m[i][i] = 0（单个矩阵无需计算）
   - 递推公式：m[i][j] = min{m[i][k] + m[k+1][j] + pi-1×pk×pj}，其中i ≤ k < j

3. 计算顺序：按照链长度从小到大计算，确保计算m[i][j]时所需的子问题已经求解

4. 最优解构造：通过s数组记录断开位置，递归构造加括号方案

可扩展性分析：

1. 4个矩阵有5种加括号方式（Catalan数C3=5）
2. n个矩阵有Cn-1种加括号方式，增长极快（C10 ≈ 16796）
3. 动态规划算法复杂度为O(n³)，对于n=100仍然可行
4. 避免了指数级的穷举，大大提高了效率

## 四、算法伪代码

### 算法1：矩阵链乘法最优代价计算

输入：维度数组p[0..n]，表示n个矩阵，矩阵Ai的维度为p[i-1] × p[i]

输出：代价数组m[1..n][1..n]和断开位置数组s[1..n-1][2..n]

```
MATRIX-CHAIN-ORDER(p, n)
    // 初始化代价数组和断开位置数组
    let m[1..n][1..n] and s[1..n-1][2..n] be new tables
    
    // 边界条件：单个矩阵代价为0
    for i = 1 to n
        m[i][i] = 0
    
    // 按链长度递增顺序计算
    for len = 2 to n  // len是链长度
        for i = 1 to n - len + 1
            j = i + len - 1  // 链的结束位置
            m[i][j] = ∞  // 初始化为无穷大
            
            // 尝试所有可能的断开位置k
            for k = i to j - 1
                // 计算在位置k断开的代价
                q = m[i][k] + m[k+1][j] + p[i-1] × p[k] × p[j]
                
                // 更新最小代价
                if q < m[i][j]
                    m[i][j] = q
                    s[i][j] = k  // 记录最优断开位置
    
    return m, s
```

### 算法2：构造最优加括号方案

输入：断开位置数组s，起始位置i，结束位置j

输出：打印最优加括号方案

```
PRINT-OPTIMAL-PARENS(s, i, j)
    if i = j
        print "A" + i  // 单个矩阵，直接打印
    else
        print "("
        PRINT-OPTIMAL-PARENS(s, i, s[i][j])  // 递归打印左半部分
        PRINT-OPTIMAL-PARENS(s, s[i][j] + 1, j)  // 递归打印右半部分
        print ")"
```

### 算法复杂度分析

时间复杂度：
1. MATRIX-CHAIN-ORDER算法：
   - 外层循环len：n-1次
   - 第二层循环i：对于长度len，约n-len+1次
   - 第三层循环k：对于区间[i,j]，j-i次
   - 总时间：O(n³)

2. PRINT-OPTIMAL-PARENS算法：
   - 递归调用次数等于最优解中的内部节点数
   - 最多O(n)次
   - 总时间：O(n)

总时间复杂度：O(n³)

空间复杂度：
1. 数组m：O(n²)
2. 数组s：O(n²)
3. 递归栈深度：O(n)
4. 总空间复杂度：O(n²)

## 七、实验结果分析

通过实验验证，动态规划算法能够有效找到矩阵链乘法的最优加括号方案。

算法正确性分析：
1. 最优子结构：如果最优方案在位置k断开，则左右两部分也必须是最优的
2. 重叠子问题：不同的加括号方式会重复计算相同的子链
3. 动态规划避免重复计算，保证找到全局最优解

性能分析：
1. 时间效率：O(n³)比穷举的O(Catalan(n))效率高得多
   - n=10时：穷举需要考虑16796种方案，动态规划只需1000次基本操作
   - n=100时：动态规划仍可在合理时间内完成

2. 空间效率：O(n²)空间对于实际应用是可接受的

实际意义：
1. 不同加括号方式的代价差异可达数倍甚至数十倍
2. 测试用例1中，最差方案（21000）是最优方案（9375）的2.24倍
3. 在大规模科学计算中，选择最优方案可节省大量计算时间

遇到的问题及解决方案：
1. 问题：初始尝试穷举所有加括号方式，发现n个矩阵有Catalan(n-1)种方案，增长极快
   解决：观察到子问题重叠和最优子结构性质，转向动态规划

2. 问题：确定正确的计算顺序
   解决：按链长度从小到大计算，确保依赖的子问题已求解

3. 问题：如何构造具体的加括号方案
   解决：使用s数组记录每个子问题的最优断开位置，通过递归回溯构造方案

4. 问题：手工计算容易出错，特别是三层循环的枚举
   解决：建立清晰的表格，系统地按顺序填写，每步都验证计算

改进空间：
1. 对于非常大的n，可以考虑并行化计算相同长度的不同子链
2. 如果只需要最优代价而不需要构造方案，可以省略s数组

## 八、总结

### 感想、体会、建议

通过本次矩阵链乘法问题的实验，我获得了以下深刻体会：

1. 问题分解的艺术：矩阵链乘法问题展示了如何将一个复杂的优化问题分解为更小的子问题。关键在于找到合适的"断开点"作为问题分解的依据。

2. 最优子结构的理解：这个问题完美诠释了动态规划的核心性质——最优解包含子问题的最优解。如果整体方案在k处断开是最优的，那么左右两部分也必须各自最优。

3. 计算顺序的重要性：动态规划不仅要找到递推关系，还要确定正确的计算顺序。本问题按链长度递增计算，巧妙地保证了依赖关系。

4. 手工推演的价值：通过穷举4个矩阵的所有5种加括号方式，我直观地看到了不同方案的代价差异，这激发了寻找最优方案的动力，也帮助我理解了动态规划如何避免重复计算。

5. 算法复杂度的对比：穷举法的复杂度随Catalan数增长（指数级），而动态规划将其降至O(n³)（多项式级），这种降维打击的威力令人印象深刻。

6. 实际应用价值：在科学计算和数据库查询优化中，选择合适的计算顺序可以带来数倍甚至数十倍的性能提升，这不是理论上的数字游戏，而是实实在在的效率改进。

本次实验进一步巩固了我从实例到算法的思维模式：先手工求解理解问题本质，再抽象出子问题结构，最后形式化为算法描述。这种系统化的方法论将是我今后解决算法问题的有力武器。
