# 二、问题背景和相关工作介绍

## 2.1 最长公共子序列（LCS）

最长公共子序列问题是计算机科学中的经典问题，广泛应用于生物信息学中的DNA序列比对、文件差异比较（如diff工具）、版本控制系统等领域。

问题定义：给定两个序列X和Y，找出它们的最长公共子序列。子序列不要求连续，但必须保持相对顺序。

输入：两个序列X = <x1, x2, ..., xm>和Y = <y1, y2, ..., yn>

输出：X和Y的最长公共子序列的长度及具体序列

相关工作：该问题是动态规划的典型应用，由Wagner和Fischer在1974年提出了经典的动态规划算法，时间复杂度为O(mn)。

## 2.2 矩阵链乘法

矩阵链乘法问题是动态规划的经典应用之一，在科学计算、计算机图形学、数据库查询优化等领域有广泛应用。

问题定义：给定n个矩阵的链A1, A2, ..., An，其中矩阵Ai的维度为pi-1 × pi，如何确定计算矩阵链乘积的顺序，使得标量乘法次数最少。

关键性质：矩阵乘法满足结合律但不满足交换律，不同的加括号方式会导致计算代价差异巨大。

输入：矩阵维度序列p = <p0, p1, p2, ..., pn>

输出：最优加括号方案及最少标量乘法次数

相关工作：该问题的动态规划解法时间复杂度为O(n³)，由Godbole在1973年首次提出。

## 2.3 n皇后问题

n皇后问题是经典的组合优化问题和回溯算法的典型应用，最早由国际象棋棋手Max Bezzel在1848年提出。该问题在人工智能、约束满足、搜索算法等领域有重要研究价值。

问题定义：在n×n的国际象棋棋盘上放置n个皇后，使得任意两个皇后都不能互相攻击，即任意两个皇后不能处于同一行、同一列或同一斜线上。

输入：棋盘大小n

输出：一个或所有可行的皇后放置方案

相关工作：n皇后问题是NP完全问题，但通过回溯法可以高效求解。4皇后问题有2个解，8皇后问题有92个解。

## 2.4 传教士与野人过河问题

传教士与野人过河问题是人工智能和状态空间搜索领域的经典问题，最早出现于1800年代的数学娱乐题。该问题是状态空间搜索、广度优先搜索（BFS）和深度优先搜索（DFS）的典型教学案例。

问题定义：有3个传教士和3个野人要过河，只有一条船，船每次最多载2人。在任何时刻，如果野人数量超过传教士数量，传教士就会被野人吃掉。如何安全地将所有人运送到对岸。

输入：左岸传教士数量M，左岸野人数量C，船的容量K

输出：一系列合法的过河动作序列

相关工作：该问题可以建模为状态空间搜索问题，通过BFS可以找到最短解。经典的3传教士3野人问题的最短解需要11步。

## 2.5 0-1背包问题

0-1背包问题是组合优化领域的经典NP完全问题，在资源分配、投资决策、装载问题等领域有广泛应用。该问题是动态规划的典型应用案例，也是贪心算法与动态规划对比的重要教学实例。

问题定义：给定n个物品和一个容量为W的背包，第i个物品的重量为wi，价值为vi。每个物品只能选择装入或不装入（0-1选择），求在不超过背包容量的前提下，能够装入背包的物品的最大总价值。

输入：背包容量W、物品数量n、物品重量数组w[1..n]、物品价值数组v[1..n]

输出：最大总价值及对应的物品选择方案

相关工作：0-1背包问题是NP完全问题，不存在已知的多项式时间精确算法。然而，通过动态规划可以在伪多项式时间O(nW)内求解。

# 三、解题思路

## 3.1 最长公共子序列

### 问题实例化

选择两个小规模序列进行分析：
- X = "ABCBDAB"（长度m=7）
- Y = "BDCABA"（长度n=6）

### 手工求解过程

步骤1：首先尝试穷举思路

像"笨电脑"一样开始思考：是否需要尝试所有可能的子序列？X的所有子序列数量为2^7=128个，Y的所有子序列数量为2^6=64个，如果穷举所有可能再比较，工作量巨大。

步骤2：观察小规模匹配过程

手工比对过程发现了几个公共子序列：

1. "BDAB"（长度4）
2. "BCAB"（长度4）
3. "BCBA"（长度4）

步骤3：发现子问题结构

在手工比对时发现：

1. 如果X[i] = Y[j]，那么这个字符可以加入公共子序列
2. 如果X[i] ≠ Y[j]，需要考虑跳过X[i]或跳过Y[j]

关键观察：问题可以分解为更小的子问题。

步骤4：构造比对表格

设c[i][j]表示X[1..i]和Y[1..j]的LCS长度，通过填表发现：

填表规则：

1. 初始化：c[0][j]=0, c[i][0]=0
2. 如果X[i]=Y[j]：c[i][j] = c[i-1][j-1] + 1
3. 如果X[i]≠Y[j]：c[i][j] = max(c[i-1][j], c[i][j-1])

最终c[7][6]=4，说明LCS长度为4。

步骤5：回溯构造具体序列

从c[7][6]开始回溯，根据转移方向构造出LCS："BCAB"。

### 思路提炼

核心策略：动态规划

1. 子问题定义：c[i][j]表示X[1..i]和Y[1..j]的LCS长度
2. 递推关系：基于字符是否匹配的状态转移
3. 计算顺序：按行或按列，从小到大填表
4. 最优解构造：从c[m][n]回溯

## 3.2 矩阵链乘法

### 问题实例化

选择4个矩阵的链进行分析：
- A1: 30 × 35
- A2: 35 × 15
- A3: 15 × 5
- A4: 5 × 10
- 维度序列：p = <30, 35, 15, 5, 10>

### 手工求解过程

步骤1：理解计算代价

矩阵乘法基础：计算p × q矩阵与q × r矩阵的乘积，需要p × q × r次标量乘法。

步骤2：穷举所有加括号方式

对于4个矩阵，手工计算了5种可能的加括号方式：

1. ((A1×A2)×A3)×A4：代价19500
2. (A1×(A2×A3))×A4：代价9375 ⭐最优
3. (A1×A2)×(A3×A4)：代价21000
4. A1×((A2×A3)×A4)：代价14875
5. A1×(A2×(A3×A4))：代价16500

最优方案：方式2，总代价为9375次标量乘法。

步骤3：发现子问题结构

观察方式2：(A1×(A2×A3))×A4，发现：

1. 最优方案在A1和A2A3A4之间断开
2. 子问题A2A3也需要最优加括号
3. 问题具有递归结构

步骤4：构造动态规划表格

定义m[i][j]为计算矩阵链Ai..Aj的最少标量乘法次数，定义s[i][j]为最优断开位置k。

按链长度从小到大填表，最终m[1][4] = 9375，通过回溯构造最优加括号方案。

### 思路提炼

核心策略：动态规划

1. 子问题定义：m[i][j]表示计算矩阵链Ai..Aj所需的最少标量乘法次数
2. 递推关系：m[i][j] = min{m[i][k] + m[k+1][j] + pi-1×pk×pj}
3. 计算顺序：按照链长度从小到大计算
4. 最优解构造：通过s数组记录断开位置，递归构造加括号方案

## 3.3 n皇后问题

### 问题实例化

选择4×4棋盘进行分析（4皇后问题），这是最小的有解实例。

### 手工求解过程

步骤1：理解问题约束

皇后的攻击范围包括：同一行、同一列、同一主对角线、同一副对角线的所有位置。

步骤2：尝试逐行放置

采用逐行放置策略：从第1行开始，在每行选择一个合法位置放置皇后。

详细记录了完整的搜索过程，包括：

1. 尝试第1行第1列，逐步向下搜索
2. 遇到冲突时回溯
3. 最终找到第一个解：(1,2), (2,4), (3,1), (4,3)

步骤3：验证解的正确性

检查所有皇后对，确认都满足约束条件。

步骤4：继续搜索找到第二个解

4皇后问题共有2个本质不同的解（不考虑旋转和镜像）。

### 思路提炼

核心策略：回溯法（Backtracking）

1. 搜索策略：逐行放置皇后，每行恰好放一个
2. 约束检查：使用三个布尔数组快速判断列和对角线是否被占用
3. 剪枝优化：提前检查约束，避免无效搜索
4. 解的表示：使用一维数组col[i]表示第i行皇后所在的列号

## 3.4 传教士与野人过河问题

### 问题实例化

标准实例：3个传教士，3个野人，船容量为2。

状态表示：使用三元组(m, c, b)表示状态，其中：

1. m：左岸传教士数量（0到3）
2. c：左岸野人数量（0到3）
3. b：船的位置（0表示右岸，1表示左岸）

初始状态：(3, 3, 1)
目标状态：(0, 0, 0)

### 手工求解过程

步骤1：理解状态转移

从初始状态开始，列举可能的动作，检查每个动作后的状态是否安全。

步骤2-4：尝试多条路径

通过多次尝试发现某些路径会陷入困境，需要重新分析安全性约束。

步骤5：系统化搜索（BFS）

使用广度优先搜索，按层次搜索，保证找到最短路径。详细记录了从第1层到第12层的搜索过程，最终找到11步的最短解。

### 思路提炼

核心策略：广度优先搜索（BFS）

1. 状态空间建模：状态、动作、状态转移
2. 安全性检查：传教士数量要么为0，要么≥野人数量
3. 搜索策略：BFS保证找到最短路径
4. 状态去重：使用访问标记避免重复访问

## 3.5 0-1背包问题

### 问题实例化

背包容量：W = 8
物品数量：n = 4
物品信息：{(2,3), (3,4), (4,5), (5,6)}（重量,价值）

### 手工求解过程

步骤1：尝试穷举所有可能

对于4个物品，列举了16种可能的组合，找到可行方案中的最大价值为10。

步骤2：观察穷举过程的重复计算

发现了很多重复的子问题，例如：

1. 计算{1,2}的最优解时，需要知道{1}和{2}的情况
2. 计算{1,2,3}时，需要知道{1,2}、{1,3}、{2,3}的情况

步骤3：尝试贪心策略

尝试了按价值、按重量、按性价比三种贪心策略，发现贪心策略不能保证总是得到最优解。

步骤4：构造动态规划表格

定义dp[i][w]：考虑前i个物品，背包容量为w时能获得的最大价值。

手工填表，按物品逐个处理，根据状态转移方程更新dp值。最终dp[4][8] = 10。

步骤5：回溯构造最优解

从dp[4][8]开始回溯，确定选择了物品2和物品4。

### 思路提炼

核心策略：动态规划

1. 子问题定义：dp[i][w]表示考虑前i个物品、背包容量为w时的最大价值
2. 状态转移方程：dp[i][w] = max(dp[i-1][w], dp[i-1][w-wi] + vi)
3. 计算顺序：外层循环物品，内层循环容量
4. 最优解构造：从dp[n][W]开始回溯

# 四、算法伪代码

## 4.1 最长公共子序列

### 算法1：LCS长度计算

输入：序列X[1..m]和Y[1..n]

输出：二维数组c[0..m][0..n]，其中c[m][n]为LCS长度

```
LCS-LENGTH(X, Y, m, n)
    // 初始化边界条件
    for i = 0 to m
        c[i][0] = 0
    for j = 0 to n
        c[0][j] = 0
    
    // 动态规划填表
    for i = 1 to m
        for j = 1 to n
            if X[i] = Y[j]
                c[i][j] = c[i-1][j-1] + 1
                b[i][j] = "↖"  // 记录方向：左上
            else if c[i-1][j] >= c[i][j-1]
                c[i][j] = c[i-1][j]
                b[i][j] = "↑"  // 记录方向：向上
            else
                c[i][j] = c[i][j-1]
                b[i][j] = "←"  // 记录方向：向左
    
    return c, b
```

### 算法2：LCS序列回溯构造

输入：序列X[1..m]，方向数组b[1..m][1..n]，当前位置(i, j)

输出：打印LCS序列

```
PRINT-LCS(b, X, i, j)
    if i = 0 or j = 0
        return
    
    if b[i][j] = "↖"
        PRINT-LCS(b, X, i-1, j-1)
        print X[i]  // 当前字符属于LCS
    else if b[i][j] = "↑"
        PRINT-LCS(b, X, i-1, j)
    else
        PRINT-LCS(b, X, i, j-1)
```

复杂度分析：
- 时间复杂度：O(mn)
- 空间复杂度：O(mn)

## 4.2 矩阵链乘法

### 算法：矩阵链乘法最优代价计算

输入：维度数组p[0..n]，表示n个矩阵

输出：代价数组m[1..n][1..n]和断开位置数组s[1..n-1][2..n]

```
MATRIX-CHAIN-ORDER(p, n)
    // 初始化代价数组和断开位置数组
    let m[1..n][1..n] and s[1..n-1][2..n] be new tables
    
    // 边界条件：单个矩阵代价为0
    for i = 1 to n
        m[i][i] = 0
    
    // 按链长度递增顺序计算
    for len = 2 to n  // len是链长度
        for i = 1 to n - len + 1
            j = i + len - 1  // 链的结束位置
            m[i][j] = ∞  // 初始化为无穷大
            
            // 尝试所有可能的断开位置k
            for k = i to j - 1
                // 计算在位置k断开的代价
                q = m[i][k] + m[k+1][j] + p[i-1] × p[k] × p[j]
                
                // 更新最小代价
                if q < m[i][j]
                    m[i][j] = q
                    s[i][j] = k  // 记录最优断开位置
    
    return m, s
```

复杂度分析：
- 时间复杂度：O(n³)
- 空间复杂度：O(n²)

## 4.3 n皇后问题

### 算法1：n皇后问题主算法

输入：棋盘大小n

输出：打印所有可行解或解的个数

```
N-QUEENS(n)
    // 初始化数据结构
    let col[1..n] be new array  // col[i]表示第i行皇后在第几列
    let colUsed[1..n] be new boolean array, all false
    let mainDiag[1..2n-1] be new boolean array, all false
    let antiDiag[2..2n] be new boolean array, all false
    solutionCount = 0
    
    // 从第1行开始搜索
    BACKTRACK(1, n, col, colUsed, mainDiag, antiDiag, solutionCount)
    
    return solutionCount
```

### 算法2：回溯搜索

输入：当前行row，棋盘大小n，皇后位置数组col，约束数组

输出：通过递归找到所有解

```
BACKTRACK(row, n, col, colUsed, mainDiag, antiDiag, solutionCount)
    // 递归边界：所有行都已成功放置皇后
    if row > n
        solutionCount = solutionCount + 1
        PRINT-SOLUTION(col, n)
        return
    
    // 尝试在当前行的每一列放置皇后
    for c = 1 to n
        // 计算对角线编号
        mainDiagIndex = row - c + n
        antiDiagIndex = row + c
        
        // 检查当前位置是否合法
        if not colUsed[c] and not mainDiag[mainDiagIndex] 
           and not antiDiag[antiDiagIndex]
            // 放置皇后
            col[row] = c
            colUsed[c] = true
            mainDiag[mainDiagIndex] = true
            antiDiag[antiDiagIndex] = true
            
            // 递归处理下一行
            BACKTRACK(row + 1, n, col, colUsed, mainDiag, antiDiag, 
                      solutionCount)
            
            // 回溯：撤销当前放置
            colUsed[c] = false
            mainDiag[mainDiagIndex] = false
            antiDiag[antiDiagIndex] = false
```

复杂度分析：
- 时间复杂度：O(n!)（实际，理论O(n^n)）
- 空间复杂度：O(n)

## 4.4 传教士与野人过河问题

### 算法1：主算法（BFS）

输入：传教士总数M，野人总数C，船容量K

输出：最短过河方案

```
MISSIONARIES-AND-CANNIBALS(M, C, K)
    // 定义初始状态和目标状态
    initialState = (M, C, 1)
    goalState = (0, 0, 0)
    
    // 初始化BFS队列和访问标记
    queue = new Queue()
    queue.enqueue(initialState)
    visited = new Set()
    visited.add(initialState)
    parent = new Map()
    parent[initialState] = null
    
    // BFS主循环
    while not queue.isEmpty()
        currentState = queue.dequeue()
        
        // 检查是否到达目标状态
        if currentState = goalState
            return CONSTRUCT-SOLUTION(parent, goalState)
        
        // 生成所有合法后继状态
        successors = GENERATE-SUCCESSORS(currentState, M, C, K)
        
        for each nextState in successors
            if nextState not in visited
                visited.add(nextState)
                parent[nextState] = currentState
                queue.enqueue(nextState)
    
    return "无解"
```

### 算法2：状态合法性检查

输入：状态(m, c, b)，总人数M和C

输出：状态是否合法

```
IS-VALID(m, c, b, M, C)
    // 检查人数范围
    if m < 0 or m > M or c < 0 or c > C
        return false
    
    // 计算右岸人数
    rightM = M - m
    rightC = C - c
    
    // 检查左岸安全性
    if m > 0 and m < c
        return false
    
    // 检查右岸安全性
    if rightM > 0 and rightM < rightC
        return false
    
    return true
```

复杂度分析：
- 时间复杂度：O(MC × K²)
- 空间复杂度：O(MC)

## 4.5 0-1背包问题

### 算法：0-1背包动态规划算法

输入：背包容量W，物品数量n，重量数组w[1..n]，价值数组v[1..n]

输出：最大总价值

```
KNAPSACK-01(W, n, w, v)
    // 初始化DP表
    let dp[0..n][0..W] be new array
    
    // 边界条件：没有物品或容量为0时，价值为0
    for i = 0 to n
        dp[i][0] = 0
    for j = 0 to W
        dp[0][j] = 0
    
    // 动态规划填表
    for i = 1 to n
        for w_cap = 0 to W
            // 默认不选第i个物品
            dp[i][w_cap] = dp[i-1][w_cap]
            
            // 如果容量足够，考虑选择第i个物品
            if w_cap >= w[i]
                valueWithItem = dp[i-1][w_cap - w[i]] + v[i]
                if valueWithItem > dp[i][w_cap]
                    dp[i][w_cap] = valueWithItem
    
    return dp[n][W]
```

复杂度分析：
- 时间复杂度：O(nW)
- 空间复杂度：O(nW)或O(W)（优化版）

## 7.1 算法正确性分析

### 7.1.1 最长公共子序列

2. 重叠子问题：不同的加括号方式会重复计算相同的子链
3. 动态规划避免重复计算，保证找到全局最优解

- 不同加括号方式的代价差异可达数倍
- 测试用例1中，最差方案是最优方案的2.24倍
- 在大规模科学计算中，选择最优方案可节省大量计算时间

1. **加深理解**：手工填写DP表、遍历搜索树，让我理解了算法的每一个细节
2. **发现错误**：多次手工推演发现了初期算法设计的问题
3. **验证正确性**：通过小实例验证是检验算法正确性的最佳方法
4. **培养直觉**：大量的手工计算培养了对算法复杂度的直觉

### 5. 伪代码的重要性

将算法思想形式化为伪代码是算法设计的重要环节：

1. **清晰表达**：伪代码既保持了算法的本质，又避免了编程语言细节的干扰
2. **沟通工具**：伪代码是与他人交流算法思想的最佳方式
3. **实现蓝图**：规范的伪代码可以直接指导代码实现

### 6. 算法的普适性

五个问题涵盖了不同的应用领域，但核心思想是相通的：

1. **问题分解**：将复杂问题分解为更小的子问题
2. **状态管理**：合理定义和管理问题状态
3. **策略选择**：根据问题特性选择合适的算法策略
4. **优化思维**：始终思考如何提高算法效率

这些通用的算法思维方式将适用于更广泛的问题求解。

## 8.2 对算法设计方法的认识

### 8.2.1 动态规划适用场景

通过三个DP问题，我总结了动态规划的适用特征：

1. 问题具有最优子结构
2. 存在大量重叠子问题
3. 可以用表格存储中间结果
4. 能够明确定义状态和转移关系

关键是找到合适的状态定义和转移方程。

### 8.2.2 贪心策略的局限性

0-1背包问题的反例清楚地展示了贪心策略的局限：

1. 贪心做出局部最优选择
2. 但无法保证全局最优
3. 只有在特定条件下（如分数背包）才有效

这提醒我不能凭直觉选择算法，必须严格证明正确性。

### 8.2.3 搜索算法的选择

1. **BFS**：适合寻找最短路径，空间开销较大
2. **DFS/回溯**：适合遍历所有解，空间开销小，可以剪枝
3. **状态空间设计**：合理的状态表示是搜索成功的关键
