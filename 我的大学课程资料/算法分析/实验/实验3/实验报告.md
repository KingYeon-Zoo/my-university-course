# 一、实验内容和要求

本实验旨在通过实验设计方法，研究混合排序策略中切换阈值对算法性能的影响。具体内容包括：

1. 提出科学问题：研究混合排序（快速排序+插入排序）中，切换阈值k对算法运行时间和比较次数的影响，并寻找最优切换阈值。

2. 设计控制变量实验：系统地测试不同切换阈值下的算法性能，保持数据规模、数据分布等其他条件不变。

3. 理论预测与实验验证：基于算法原理预测性能曲线，通过实验数据验证理论分析，并解释实际结果。

# 二、问题背景和相关工作介绍

在实际应用中，纯粹的快速排序并非最优选择。工业级排序算法（如C++的std::sort、Java的Arrays.sort）普遍采用混合排序策略，即在递归过程中，当子数组规模小于某个阈值k时，切换为插入排序。

理论分析表明，快速排序的时间复杂度为O(n log n)，而插入排序为O(n²)。然而在小规模数据上，插入排序具有以下优势：

1. 常数因子较小，循环体简单高效

2. 无递归调用开销，避免函数栈压栈出栈

3. 内存访问局部性好，缓存命中率高

4. 对近乎有序的数据处理效率极高

因此，存在一个最优切换阈值k*，使得混合排序的整体性能最佳。本实验通过系统化的实验设计，寻找这一最优阈值，并分析其与数据规模、数据分布的关系。

参考文献：

1. Sedgewick R. Implementing Quicksort Programs. Communications of the ACM, 1978.

2. Musser D R. Introspective Sorting and Selection Algorithms. Software Practice and Experience, 1997.

# 三、解题思路

本实验的核心思路是设计一个混合排序算法，并通过控制变量法系统地测试不同切换阈值的性能。

算法设计思路如下：

1. 实现标准快速排序作为基础算法，采用三路划分优化处理重复元素。

2. 在快速排序的递归过程中，当子数组长度小于阈值k时，不再递归而是标记该区间。

3. 递归结束后，对整个数组执行一次插入排序，利用插入排序对近乎有序数据的高效特性。

4. 通过改变阈值k（从0到50），观察算法的运行时间和比较次数变化。

实验设计思路：

1. 自变量：切换阈值k，取值范围为0、5、10、15、20、25、30、35、40、45、50

2. 因变量：运行时间（秒）、比较次数

3. 控制变量：数据规模固定为10000、50000、100000，数据分布采用完全随机分布，随机种子固定为42

以规模为10的随机数组[34, 7, 23, 32, 5, 62, 32, 12, 45, 18]为例说明算法过程：

1. 当k=0时，纯快速排序，递归到底

2. 当k=5时，第一次划分后若子数组长度≤5则不再递归，最后统一插入排序

3. 当k=10时，整个数组直接使用插入排序

理论预测：

1. k过小时，递归层次过深，函数调用开销大

2. k过大时，插入排序处理的数据规模大，O(n²)复杂度占主导

3. 存在最优值k*，预计在10到20之间，使得总体性能最佳

# 四、算法伪代码

算法1：混合排序主函数

输入参数：
    arr - 待排序数组
    threshold - 切换阈值k
    
输出参数：
    sorted_arr - 排序后的数组
    comparisons - 比较次数

```
HYBRID_SORT(arr, threshold):
    n = LENGTH(arr)
    comparisons = 0
    
    // 执行混合快速排序
    comparisons = comparisons + HYBRID_QUICK_SORT(arr, 0, n-1, threshold)
    
    // 对整个数组执行插入排序，处理小片段
    comparisons = comparisons + INSERTION_SORT(arr, 0, n-1)
    
    RETURN arr, comparisons
```

算法2：混合快速排序

输入参数：
    arr - 待排序数组
    left - 左边界
    right - 右边界
    threshold - 切换阈值
    
输出参数：
    comparisons - 比较次数

```
HYBRID_QUICK_SORT(arr, left, right, threshold):
    comparisons = 0
    
    // 如果子数组长度小于等于阈值，直接返回
    IF right - left + 1 <= threshold:
        RETURN 0
    
    // 选择枢轴元素（取中位数）
    mid = (left + right) / 2
    pivot = MEDIAN(arr[left], arr[mid], arr[right])
    comparisons = comparisons + 3
    
    // 三路划分
    i = left
    lt = left       // 小于pivot的区域
    gt = right      // 大于pivot的区域
    
    WHILE i <= gt:
        comparisons = comparisons + 1
        IF arr[i] < pivot:
            SWAP(arr[i], arr[lt])
            i = i + 1
            lt = lt + 1
        ELSE IF arr[i] > pivot:
            SWAP(arr[i], arr[gt])
            gt = gt - 1
        ELSE:
            i = i + 1
    
    // 递归处理左右两部分
    comparisons = comparisons + HYBRID_QUICK_SORT(arr, left, lt-1, threshold)
    comparisons = comparisons + HYBRID_QUICK_SORT(arr, gt+1, right, threshold)
    
    RETURN comparisons
```

算法3：插入排序

输入参数：
    arr - 待排序数组
    left - 左边界
    right - 右边界
    
输出参数：
    comparisons - 比较次数

```
INSERTION_SORT(arr, left, right):
    comparisons = 0
    
    FOR i = left + 1 TO right:
        key = arr[i]
        j = i - 1
        
        // 将key插入到已排序序列的正确位置
        WHILE j >= left AND arr[j] > key:
            comparisons = comparisons + 1
            arr[j+1] = arr[j]
            j = j - 1
        
        // 边界条件也需要比较
        IF j >= left:
            comparisons = comparisons + 1
        
        arr[j+1] = key
    
    RETURN comparisons
```

算法4：三数取中

输入参数：
    a, b, c - 三个待比较的数
    
输出参数：
    median - 中位数

```
MEDIAN(a, b, c):
    IF a <= b:
        IF b <= c:
            RETURN b
        ELSE IF a <= c:
            RETURN c
        ELSE:
            RETURN a
    ELSE:
        IF a <= c:
            RETURN a
        ELSE IF b <= c:
            RETURN c
        ELSE:
            RETURN b
```

# 七、实验结果分析

通过实验数据分析，可以得出以下结论：

1. 实验结果验证了理论预测。运行时间和比较次数均呈现U型曲线，存在明显的最优切换阈值。在本实验环境下，不同数据规模的最优阈值略有差异：n=10000时k*=10（提升20.53%），n=50000时k*=20（提升17.43%），n=100000时k*=15（提升26.08%）。平均性能提升约21%。

2. 性能提升机制分析。以规模100000的数据为例，最优阈值k=15时，运行时间从0.3756秒降至0.2776秒，比较次数从2193468次降至1885642次，性能提升达26.08%。以规模10000的数据为例，最优阈值k=10时，运行时间从0.0197秒降至0.0157秒，比较次数从180610次降至146287次。性能提升主要来源于：
   (1) 减少了递归调用次数，降低函数调用开销
   (2) 小片段由插入排序处理，利用了其常数因子小的优势
   (3) 内存访问更具局部性，提高缓存命中率

3. 阈值过小的影响。当k<10时，递归层次过深，虽然比较次数较少，但函数调用开销成为主要瓶颈。每次递归需要保存上下文、压栈出栈，这些操作的时间开销不可忽略。

4. 阈值过大的影响。当k>20时，插入排序需要处理较大的数组片段，O(n²)的时间复杂度开始占主导。当k=50时，运行时间几乎是最优值的2倍。

5. 最优阈值的规模相关性。在三种不同数据规模下，最优阈值分别为10、20、15，均在10到20之间。这说明最优阈值主要由算法特性和硬件特性决定，但也受数据规模一定影响。对于中等规模（10000），较小的阈值更优；对于大规模（50000），稍大的阈值效果更好；对于更大规模（100000），阈值趋于中间值。实际应用中可选择k=10-20作为通用阈值。

6. 实验过程中的问题及解决方案：
   (1) 问题：初始实现中时间测量不准确，波动较大
       解决：使用time.perf_counter()替代time.time()，并增加重复测试次数取平均值
   (2) 问题：小规模数据下时间差异不明显
       解决：增大数据规模，使用更精细的阈值步长
   (3) 问题：比较次数统计遗漏边界条件
       解决：仔细检查所有比较操作，确保统计完整

7. 改进空间：
   (1) 可以测试不同数据分布（有序、逆序、部分有序）对最优阈值的影响
   (2) 可以引入更多优化策略，如三数取中选择枢轴、尾递归优化等
   (3) 可以在不同硬件平台上测试，研究缓存大小对最优阈值的影响
