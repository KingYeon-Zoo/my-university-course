**数据库课程设计要求整理**

**一、总体要求**

1. **分组要求**
   
   1. 每组 2-3 人。
   2. 每组设组长一名。
   3. 需要明确角色划分和任务分配。
   4. 每组从 48 个题目中任选一个作为课程设计题目。
   5. 同一个班中不同小组不允许选择相同题目。
   6. 选好题目后发给班长汇总。
   7. 若产生选题冲突，由班长或委员协调解决。

2. **课程设计完成内容**
   
   每组需独立完成以下内容：
   
   1. 通过调查研究和 Internet 检索，收集相关资料和最新技术信息。
   2. 基本掌握设计报告的撰写步骤和写作方法。
   3. 根据课题要求，理解并掌握 E-R 图设计方法和关系模式转换方法。
   4. 根据 E-R 图生成数据库表。
   5. 设计数据库完整性和安全性保证措施。
   6. 完成数据库物理设计。
   7. 制定数据库实施与维护计划。
   8. 完成应用系统的设计和实现。

3. **技术平台要求**
   
   1. 数据库平台可选：
      
      1. MS SQL Server
      2. MySQL
      3. openGaussDB
      4. 其他数据库平台
   
   2. 开发平台可选：
      
      1. .NET
      2. J2EE
      3. PHP
      4. 其他开发平台
   
   3. 软件架构可选：
      
      1. B/S 架构
      2. C/S 架构

4. **补充说明**
   
   鼓励采用国产数据库。

---

**二、具体要求**

1. **需求分析阶段**
   
   课题组选题后进入需求分析阶段，需要通过以下方式明确系统需求：
   
   1. 网上查阅资料。
   2. 组内讨论。
   3. 社会调查。
   4. 其他调研方式。
   
   需求分析内容包括：
   
   1. 数据需求。
   2. 功能需求。
   3. 其他需求。
   
   需求分析由课题组成员共同完成。

2. **系统设计阶段**
   
   1. 由课题组长进行任务分配。
   2. 课题组所有成员均需完成一定的设计任务。

3. **编程实现阶段**
   
   1. 每一位成员均需完成一定的程序量。
   2. 若课题组中存在没有参与编程的成员，该成员成绩为不及格。
   3. 若课题组中存在没有参与编程的成员，组长成绩也将降档处理。

**三、课题验收要求**

1. **验收方式**
   
   1. 在规定时间内进行课题验收。
   2. 验收以课题组为单位进行。
   3. 课题组全体成员验收时必须参加。
   4. 若有特殊情况，需要作书面说明。

2. **验收主要参考指标**
   
   1. **需求分析**
      
      课题组成员需要通力合作，力求需求分析全面、有效。
   
   2. **数据库设计**
      
      1. 数据应覆盖系统的数据需求。
      2. 逻辑结构应达到 3NF。
      3. 需要结合系统特点思考性能优化。
   
   3. **数据完整性**
      
      1. 分析关键表中的关键数据。
      2. 制定完整性约束规则。
   
   4. **安全性**
      
      1. 必须具有基本的用户及权限控制手段。
      2. 需要支持数据库备份和恢复。
   
   5. **视图**
      
      需要从以下方面综合考虑视图设计：
      
      1. 操作方便性。
      2. 数据安全性。
      3. 数据逻辑独立性。
   
   6. **触发器**
      
      需要根据应用需求判断是否采用触发器，并说明触发器带来的好处。
   
   7. **存储过程**
      
      需要在充分理解系统业务处理的基础上，合理设计并使用存储过程。
   
   8. **索引**
      
      需要结合数据量估算，设计合理的索引。
   
   9. **系统功能**
      
      需要在需求分析基础上尽可能细致地设计系统功能。
   
   10. **用户界面友好性**
       
       需要从用户角度出发，提升系统界面友好性。

**题目名称：某学校的题库管理系统**

**五、题库管理系统基本功能要求**

1. 实现课程、题型等基本信息的管理。

2. 能够管理每一门课程的题型，以及每门课程的章节。

3. 实现习题信息管理，能够按照题型或章节录入每门课程的习题。

4. 定义存储过程，查询指定课程中各种题型和各章节的习题数量。

5. 定义视图，查询各门课程使用的题型。

6. 每个习题设置一个题号，题号由系统自动生成，要求从 1 开始编号。

7. 每个习题都需要记录建立日期，建立日期的值为系统时间，要求使用默认值实现。

8. 定义存储过程，实现查询各门课程、各种题型的习题数量。

9. 系统可以自动抽题组成套题。

10. 习题每被抽取一次，其抽取次数需要加 1，该功能要求使用触发器实现。

11. 系统需要具有数据备份和数据恢复功能。

**六、该课题需要重点完成的数据库设计内容**

1. **需求分析**
   
   1. 分析题库管理系统的用户角色。
   2. 分析课程、章节、题型、习题、试卷等核心数据。
   3. 分析题目录入、题目查询、自动组卷、统计查询、备份恢复等功能需求。

2. **概念结构设计**
   
   需要绘制 E-R 图，建议包含以下实体：
   
   1. 课程。
   2. 章节。
   3. 题型。
   4. 习题。
   5. 试卷。
   6. 试卷明细。
   7. 用户。
   8. 角色或权限。

3. **逻辑结构设计**
   
   需要根据 E-R 图转换为关系模式，并注明：
   
   1. 主键。
   2. 外键。
   3. 唯一约束。
   4. 非空约束。
   5. 默认值约束。
   6. 检查约束。

4. **数据库表设计**
   
   建议包含以下数据表：
   
   1. 课程表。
   2. 章节表。
   3. 题型表。
   4. 课程题型表。
   5. 习题表。
   6. 试卷表。
   7. 试卷明细表。
   8. 用户表。
   9. 角色表。
   10. 用户角色表。

5. **视图设计**
   
   至少需要设计一个视图，用于查询各门课程使用的题型。

6. **存储过程设计**
   
   至少需要设计以下存储过程：
   
   1. 查询指定课程中各种题型的习题数量。
   2. 查询指定课程中各章节的习题数量。
   3. 查询各门课程、各种题型的习题数量。
   4. 自动抽题组成套题。

7. **触发器设计**
   
   至少需要设计一个触发器：
   
   1. 当习题被抽取加入试卷时，自动将该习题的抽取次数加 1。

8. **索引设计**
   
   可以考虑在以下字段上建立索引：
   
   1. 课程编号。
   2. 章节编号。
   3. 题型编号。
   4. 习题编号。
   5. 试卷编号。
   6. 抽取次数。

9. **安全性设计**
   
   系统需要具备基本用户和权限管理功能，例如：
   
   1. 管理员。
   2. 教师。
   3. 普通用户。

10. **备份与恢复设计**
    
    系统需要提供数据库备份和恢复功能，保证数据安全。

**八、课题重点总结**

本课题的核心是设计并实现一个学校题库管理系统。系统需要完成课程、章节、题型、习题、试卷等信息的管理，并支持自动抽题组卷、题目数量统计、视图查询、触发器维护抽取次数、存储过程统计查询、数据库备份与恢复等功能。

在数据库设计方面，需要重点体现 E-R 图设计、关系模式转换、3NF 分析、主键和外键设计、完整性约束、安全性控制、视图、存储过程、触发器和索引设计。
