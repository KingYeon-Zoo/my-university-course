# 指令调度优化报告

## 原始代码问题分析

### 1. print_loop 中的数据相关

**原始代码：**
```assembly
slt r6,r5,r17       ; 计算比较结果
beqz r6,start_sum   ; 立即使用r6 → RAW相关，需要停顿
```

**优化方案：**
```assembly
slt r6,r5,r17       ; 计算比较结果
dsll r7,r5,3        ; 插入独立指令，消除停顿
beqz r6,start_sum   ; 现在使用r6不会停顿
dadd r8,r16,r7      ; 利用分支延迟槽
```

### 2. 地址计算相关

**原始代码：**
```assembly
dsll r7,r5,3        ; r7 = i * 8
dadd r8,r16,r7      ; 立即使用r7 → RAW相关
ld r9,(r8)          ; 立即使用r8 → RAW相关
```

**优化方案：**
- 将 `dsll` 指令移到分支指令之前
- 将 `dadd` 指令放入分支延迟槽
- 在 load 和使用之间插入其他独立指令

### 3. Load-Use 相关

**原始代码：**
```assembly
ld r9,(r8)          ; 加载数据
sd r9,(r22)         ; 立即使用 → Load-Use 相关，停顿2-3个周期
```

**优化方案：**
```assembly
ld r9,(r8)          ; 加载数据
daddi r5,r5,1       ; 插入独立的i++操作
sd r9,(r22)         ; 现在使用r9，停顿已减少
```

### 4. 分支延迟槽未利用

**原始代码：**
```assembly
j sum_loop          ; 跳转
; 延迟槽为空 → 浪费一个周期
```

**优化方案：**
```assembly
j sum_loop
nop                 ; 明确填充延迟槽（或放入有用指令）
```

## array_sum 函数的循环展开优化

### 原始循环的问题

每次迭代包含：
- 1次比较 + 1次分支
- 2次地址计算
- 1次load
- 1次加法
- 1次循环变量更新

**关键瓶颈：** Load-Use 相关导致每次迭代需要停顿

### 4路循环展开优化

**优化策略：**

1. **减少分支开销**
   - 原来12次迭代需要12次分支
   - 展开后只需3次分支（处理12个元素）
   - 分支开销减少75%

2. **消除 Load-Use 停顿**
   ```assembly
   ld r6,(r5)          ; 加载 A[i]
   ; 在等待r6的同时，计算并加载 A[i+1], A[i+2], A[i+3]
   daddi r7,r4,8
   dadd r8,r16,r7
   ld r9,(r8)          ; 加载 A[i+1]
   ; ...
   dadd r18,r18,r6     ; 此时r6已就绪，无需停顿
   ```

3. **指令级并行**
   - 多个独立的load操作可以并行执行
   - 地址计算与数据加载交叉进行
   - 求和操作与下一轮加载重叠

### 性能分析

**原始版本（未优化）：**
- 每次迭代周期数：~8-10周期（包含停顿）
- 12次迭代总周期：~96-120周期

**优化版本（4路展开）：**
- 每4次迭代周期数：~12-15周期（大部分停顿已消除）
- 12次迭代总周期：~36-45周期

**性能提升：约 2.5-3倍**

## 具体优化技术汇总

| 优化技术 | 应用位置 | 效果 |
|---------|---------|------|
| 指令重排序 | 全局 | 消除RAW相关 |
| 填充延迟槽 | 所有分支 | 避免1周期浪费 |
| 循环展开 | array_sum | 减少分支，提高ILP |
| Load调度 | 循环内 | 消除Load-Use停顿 |
| 提前计算 | print_loop | 减少关键路径长度 |

## 寄存器使用说明

### 优化版本新增寄存器：
- **r10**: 循环展开因子（值为4）
- **r11**: 可展开部分的上界（N - N%4）
- **r12**: 常量3（用于模运算）
- **r13**: N对4的余数

### 主循环寄存器映射：
- **r2**: 循环变量i
- **r3**: 比较结果临时变量
- **r4, r7**: 地址偏移计算
- **r5, r8**: 完整地址
- **r6, r9**: 加载的数组元素
- **r18**: 累加和

## 验证说明

优化后的代码应该产生与原始代码相同的结果：
- 输出相同的数组元素
- 计算相同的总和（1+2+...+12 = 78）
- 保持程序语义完全一致

## 注意事项

1. **MIPS延迟槽**：WinMIPS64使用延迟槽模型，分支后的一条指令总会执行
2. **循环展开限制**：数组长度必须已知且是展开因子的倍数（本例N=12，4的倍数）
3. **余数处理**：展开后需要单独处理不足一组的剩余元素
