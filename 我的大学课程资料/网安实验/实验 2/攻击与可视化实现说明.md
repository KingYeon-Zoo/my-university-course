# 实验 2 攻击模拟与可视化仪表盘实现说明

本文档用于详细阐述“基于 Suricata 的公网入侵检测、内联防御与可视化”实验中，六类受控攻击的具体实现、检测防御规则，以及实时可视化界面的底层工作原理，供实验验收与技术汇报使用。

## 一、 六类 Web 攻击实现与防御机制

为了确保实验在公网环境下的安全可控与可重复演示，攻击脚本 **只发送无害的特征字符串，并不执行真实的漏洞利用或命令**。防御端 Suricata 使用 `NFQUEUE` 内联模式拦截流量，根据自定义规则阻断报文。

### 1. SQL 注入 (SQL Injection)
* **攻击模拟**：在 [attack_simulator.py](file:///Users/zoo/Desktop/网安/实验 2/src/attack_simulator.py#L28-L32) 中模拟向搜索接口发送 `UNION SELECT` 查询敏感信息的特征：
  ```text
  GET /search?q=1%20union%20select%20password%20from%20users HTTP/1.1
  ```
* **检测规则**：对应 [lab-ips.rules:L4](file:///Users/zoo/Desktop/网安/实验 2/rules/lab-ips.rules#L4)：
  ```text
  drop http any any -> any 8080 (msg:"LAB-IPS WEB SQL Injection UNION SELECT Attempt"; flow:established,to_server; http.uri; content:"union"; nocase; fast_pattern; content:"select"; nocase; distance:0; within:80; classtype:web-application-attack; sid:1001001; rev:1;)
  ```
* **实现原理**：限制为已建立会话中发往服务器的请求；解析 HTTP 协议的应用层 URI 缓冲区 (`http.uri`)；检查是否**不区分大小写**地包含 `union`，且在往后 **80 字节之内**再次出现 `select`。满足条件则直接丢弃（`drop`）数据包。

### 2. XSS 跨站脚本攻击 (Cross-Site Scripting)
* **攻击模拟**：在 [attack_simulator.py](file:///Users/zoo/Desktop/网安/实验 2/src/attack_simulator.py#L33-L37) 中模拟向 URL 参数中嵌入脚本执行特征：
  ```text
  GET /search?q=%3Cscript%3Ealert(1)%3C/script%3E HTTP/1.1
  ```
* **检测规则**：对应 [lab-ips.rules:L6](file:///Users/zoo/Desktop/网安/实验 2/rules/lab-ips.rules#L6)：
  ```text
  drop http any any -> any 8080 (msg:"LAB-IPS WEB XSS Script Tag Attempt"; flow:established,to_server; http.uri; content:"<script"; nocase; fast_pattern; classtype:web-application-attack; sid:1001002; rev:1;)
  ```
* **实现原理**：提取规范化后的 HTTP URI；检测是否以不区分大小写的方式包含了 `<script` 标签特征，命中则丢弃报文。

### 3. 目录穿越 (Directory Traversal)
* **攻击模拟**：在 [attack_simulator.py](file:///Users/zoo/Desktop/网安/实验 2/src/attack_simulator.py#L38-L42) 中模拟试图利用 `../` 跳出 Web 根目录读取系统敏感文件（如 `/etc/passwd`）。在传输时对字符进行了 URL 编码：
  ```text
  GET /download?file=%2e%2e%2f%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd HTTP/1.1
  ```
* **检测规则**：对应 [lab-ips.rules:L8](file:///Users/zoo/Desktop/网安/实验 2/rules/lab-ips.rules#L8)：
  ```text
  drop http any any -> any 8080 (msg:"LAB-IPS WEB Directory Traversal Attempt"; flow:established,to_server; http.uri.raw; pcre:"/(?:\\.\\.|%2e%2e)(?:\\/|%2f)/i"; classtype:web-application-attack; sid:1001003; rev:1;)
  ```
* **实现原理**：针对部分攻击者使用 URL 编码试图绕过规范化检测，此规则特意使用 **原始 URI 缓冲区** (`http.uri.raw`)，并通过正则表达式（`pcre`）同时匹配明文的 `../` 和编码后的 `%2e%2e%2f`（或 `%2e%2e/`、`..\` 等各种变形形式）。

### 4. 命令注入 (Command Injection)
* **攻击模拟**：在 [attack_simulator.py](file:///Users/zoo/Desktop/网安/实验 2/src/attack_simulator.py#L43-L47) 中模拟利用分号 `;` 拼接并执行 Linux 系统命令：
  ```text
  GET /api/run?cmd=whoami;id HTTP/1.1
  ```
* **检测规则**：对应 [lab-ips.rules:L10](file:///Users/zoo/Desktop/网安/实验 2/rules/lab-ips.rules#L10)：
  ```text
  drop http any any -> any 8080 (msg:"LAB-IPS WEB Command Injection Attempt"; flow:established,to_server; http.uri.raw; content:"cmd="; nocase; fast_pattern; content:"|3b|"; distance:0; within:80; classtype:web-application-attack; sid:1001004; rev:1;)
  ```
* **实现原理**：检查原始 URI 缓冲区 `http.uri.raw`；匹配不区分大小写的 `cmd=` 字符串，并检查其后 80 字节之内是否出现了 ASCII 字符为 `0x3b`（十六进制表示为 `|3b|`，即英文分号 `;`），用以识别命令拼接逻辑。

### 5. Log4Shell / JNDI 探测
* **攻击模拟**：在 [attack_simulator.py](file:///Users/zoo/Desktop/网安/实验 2/src/attack_simulator.py#L48-L53) 中，模拟利用 Log4j 漏洞的探测特征。该特征并非放在 URL 中，而是通过自定义的 HTTP 请求头 `User-Agent` 发送：
  ```text
  User-Agent: JNDI-LAB-PROBE
  ```
* **检测规则**：对应 [lab-ips.rules:L12](file:///Users/zoo/Desktop/网安/实验 2/rules/lab-ips.rules#L12)：
  ```text
  drop http any any -> any 8080 (msg:"LAB-IPS EXPLOIT Log4Shell JNDI Probe"; flow:established,to_server; http.user_agent; content:"JNDI-LAB-PROBE"; nocase; fast_pattern; classtype:attempted-admin; sid:1001005; rev:2;)
  ```
* **实现原理**：聚焦于 HTTP 协议的应用层 User-Agent 缓冲区 (`http.user_agent`)，匹配是否出现该探测特征，匹配到则触发阻断。

### 6. SQLMap 自动化扫描器探测
* **攻击模拟**：在 [attack_simulator.py](file:///Users/zoo/Desktop/网安/实验 2/src/attack_simulator.py#L54-L59) 中，模拟攻击者使用知名的 SQLMap 自动化扫描器进行漏洞探针。该脚本在请求头中携带特定的 User-Agent 信息：
  ```text
  User-Agent: SQL-MAP-LAB
  ```
* **检测规则**：对应 [lab-ips.rules:L14](file:///Users/zoo/Desktop/网安/实验 2/rules/lab-ips.rules#L14)：
  ```text
  drop http any any -> any 8080 (msg:"LAB-IPS SCAN Automated SQLMap User-Agent"; flow:established,to_server; http.user_agent; content:"SQL-MAP-LAB"; nocase; fast_pattern; classtype:web-application-attack; sid:1001006; rev:2;)
  ```
* **实现原理**：在 `http.user_agent` 中匹配 `SQL-MAP-LAB` 标识。通过检测此特定签名，防止自动化工具对 Web 服务的恶意测绘与扫描。

## 二、 可视化仪表盘实现机制

实时可视化仪表盘能直观展示公网攻击源的 IP、命中规则与阻断状态。其工作原理是一个“**日志驱动、后端流式解析、前端轮询刷新**”的经典轻量级架构：

### 1. 核心架构与数据流向
```text
[Suricata IPS 引擎] 
      │ 匹配 drop 规则
      ▼ 写入结构化 JSON
[EVE JSON 日志文件] (/var/log/suricata/eve.json)
      │
      ▼ Python 读取并流式解析 (eve_reader.py)
[Flask 后端服务] (dashboard.py)
      │
      ▼ 暴露 REST API 接口 (/api/alerts)
[浏览器前端页面] (dashboard.html) -- 周期轮询渲染可视化图表
```

### 2. 详细实现细节

1. **Suricata 日志输出**：
   当 Suricata 匹配到带有 `drop`（或 `alert`）动作的规则时，会自动将该事件的详细元数据以 JSON 格式附加写入到 `/var/log/suricata/eve.json` 中。
   
2. **日志读取与标准化解析 ([eve_reader.py](file:///Users/zoo/Desktop/网安/实验 2/src/eve_reader.py))**：
   * 脚本每次被调用时，会读取 `eve.json` 的最新行。
   * 解析 JSON 格式，过滤并提取 `event_type == "alert"` 的安全警报事件。
   * 解析出以下关键字段并进行格式标准化：
     * `timestamp`：警报产生时间
     * `signature`：命中的规则名称（例如：`LAB-IPS WEB SQL Injection UNION SELECT Attempt`）
     * `src_ip` & `src_port`：攻击端的公网 IP（即 Mac 的 IP）和源端口
     * `dest_ip` & `dest_port`：被攻击的服务端 IP 及端口（`8080`）
     * `action`：Suricata 实际执行的阻断动作（若为 `blocked`，说明包已被成功丢弃）
     * `blocked`：布尔值判定是否已成功阻断

3. **Flask 后端 API 接口 ([dashboard.py](file:///Users/zoo/Desktop/网安/实验 2/src/dashboard.py))**：
   * 使用 Flask Web 框架启动轻量级服务，监听在 ECS 本地的 `8090` 端口。
   * 暴露 `/api/alerts` 接口，该接口在被请求时调用 `eve_reader.py` 读取最新的 200 条警报记录，并统计总警报数、已成功阻断的攻击数，以 JSON 格式返回给前端。
   * 主页 `/` 加载并返回渲染后的静态页面模板 `templates/dashboard.html`。

4. **前端实时轮询渲染 (`templates/dashboard.html`)**：
   * 前端使用简洁美观的现代 CSS 框架与图表库，提供良好的视觉体验。
   * 页面中的 JavaScript 设置了周期性定时器（通常每隔 1 到 2 秒），自动使用 `fetch('/api/alerts')` 接口向后端发起异步请求。
   * 拿到最新的 JSON 数据后，动态更新仪表盘中的：
     * **实时滚动警报列表**：展示攻击源 IP、攻击时间、命中的攻击类型。
     * **安全看板统计数据**：展示“当前总拦截次数”、“已阻断请求比例”。
     * **攻击地理与来源列表**：展示发起攻击最多的外部 IP 排行。

5. **SSH 端口转发保证安全安全访问**：
   * 考虑到安全日志信息的私密性，可视化仪表盘只绑定在服务器本地的 `127.0.0.1:8090`，没有暴露到公网上。
   * 管理员（你）在 Mac 终端通过执行 `ssh -L 8090:127.0.0.1:8090 root@ECS公网IP` 建立加密隧道，将远程服务器的 `8090` 端口转发映射到 Mac 本地的 `8090` 端口。
   * 这样你就可以直接在 Mac 浏览器中打开 `http://127.0.0.1:8090` 安全、实时地观察到从这台 Mac 发起的每一笔恶意攻击流量被 ECS 防御端精准拦截的全过程。
