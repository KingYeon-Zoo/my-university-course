# 实验 2：基于 Suricata 的公网入侵检测、内联防御与可视化

## 一、实验目的

1. 在阿里云 ECS 上部署 Suricata 网络入侵检测与防御系统。
2. 使用本人 Mac 作为公网攻击源，向本人拥有的 ECS 发起受控攻击流量。
3. 参考公开主流规则集的编写方法，重新编写可解释的本地 IPS 规则。
4. 使用 Suricata `NFQUEUE` 内联模式实际阻断恶意请求，而不是只产生告警。
5. 使用 Python 浏览器仪表盘实时展示攻击来源、规则名称和阻断动作。

## 三、实验原理

### 1. IDS 与 IPS 的区别

原实验使用 `lo` 回环网卡，只能证明 Suricata 可以检测本机生成的字符串，不能证明公网攻击流量到达服务器，也不能证明规则能够阻断攻击。

**原有截图：Suricata 监听 `lo` 虚拟网卡**

**原有截图：回环网络中的本地 HTTP 测试服务**

![](/Users/zoo/Library/Application%20Support/marktext/images/2026-06-03-14-14-24-image.png)

![](/Users/zoo/Library/Application%20Support/marktext/images/2026-06-03-14-15-00-image.png)

**原有截图：回环 IDS 阶段的 HTTP 异常请求告警**

本实验使用 Suricata 的 IPS 模式。Suricata 官方文档说明，IPS 模式可作为流量过滤器，规则动作使用 `drop` 或 `reject` 时可以阻断不需要的流量。Linux 主机可以通过 Netfilter/NFQUEUE 将主机流量发送给 Suricata。

### 2. 实验数据流

```text
Mac Python 攻击模拟器
        |
        | 公网 HTTP 请求
        v
阿里云 ECS 公网网卡
        |
        v
iptables INPUT/OUTPUT
        |
        v
NFQUEUE 0 -> Suricata IPS -> lab-ips.rules
        |                         |
        | 正常请求放行            | 恶意请求 drop
        v                         v
Flask 实验服务                EVE JSON 告警
                                  |
                                  v
                         Python 浏览器仪表盘
```

### 3. 规则来源与重写

本实验参考以下公开资料：

1. [Suricata 官方规则格式](https://docs.suricata.io/en/suricata-8.0.3/rules/intro.html)
2. [Suricata 官方 HTTP 关键字文档](https://docs.suricata.io/en/suricata-8.0.0/rules/http-keywords.html)
3. [Suricata 官方 NFQUEUE IPS 文档](https://docs.suricata.io/en/suricata-7.0.15/setting-up-ipsinline-for-linux.html)
4. [Suricata 官方 suricata-update / ET Open 文档](https://docs.suricata.io/en/suricata-8.0.1/rule-management/suricata-update.html)
5. [AWS GitHub：Proofpoint Emerging Threats Open 规则集导入项目](https://github.com/aws-samples/aws-network-firewall-rulegroups-with-proofpoints-emerging-threats-open-ruleset)

`suricata-update` 默认获取 Emerging Threats Open 规则集。该规则集包含大量真实威胁检测规则。本实验没有直接复制其中某一条规则，而是参考其按攻击类别组织、使用应用层协议缓冲区和降低误报的思路，重新编写了只针对实验端口 `8080` 的规则。

## 七、更新公开规则并安装重写规则

更新 ET Open 规则：

```bash
sudo suricata-update
```

安装本地规则：

```bash
sudo install -m 0644 \
  /root/suricata-ips-lab/rules/lab-ips.rules \
  /var/lib/suricata/rules/lab-ips.rules
```

本实验规则共覆盖六类主流攻击：

| SID     | 攻击类别                  | 检测位置                    | 防御动作   |
| ------- | --------------------- | ----------------------- | ------ |
| 1001001 | SQL 注入 `UNION SELECT` | `http.uri`              | `drop` |
| 1001002 | XSS `<script>`        | `http.uri`              | `drop` |
| 1001003 | 目录穿越                  | `http.uri.raw` + `pcre` | `drop` |
| 1001004 | 命令注入                  | `http.uri.raw`          | `drop` |
| 1001005 | Log4Shell/JNDI 探测     | `http.user_agent`       | `drop` |
| 1001006 | SQLMap 自动化扫描器         | `http.user_agent`       | `drop` |

![](/Users/zoo/Library/Application%20Support/marktext/images/2026-06-03-13-59-56-image.png)

**原有截图：Suricata 自定义检测规则**

规则示例：

```text
drop http any any -> any 8080 (msg:"LAB-IPS WEB SQL Injection UNION SELECT Attempt"; flow:established,to_server; http.uri; content:"union"; nocase; fast_pattern; content:"select"; nocase; distance:0; within:80; classtype:web-application-attack; sid:1001001; rev:1;)
```

该规则不是简单匹配固定实验字符串，而是只检查已建立 TCP 会话中发往服务端的 HTTP URI，并要求 `union` 后在限定距离内出现 `select`，从而体现应用层协议识别和组合特征检测。

编辑 `/etc/suricata/suricata.yaml`：

```yaml
default-rule-path: /var/lib/suricata/rules

rule-files:
  - suricata.rules
  - lab-ips.rules
```

**原有截图：`suricata.yaml` 加载本地规则**

## 八、启动 Python 实验服务和仪表盘

第一个 ECS SSH 终端启动无漏洞实验服务：

```bash
cd /root/suricata-ips-lab
/opt/miniforge3/bin/conda run -n suricata-ips-lab \
  python -m src.lab_server --host 0.0.0.0 --port 8080
```

该服务只返回固定 JSON，不执行、不保存、不反射请求中的攻击特征。

第二个 ECS SSH 终端启动仪表盘：

```bash
cd /root/suricata-ips-lab
/opt/miniforge3/bin/conda run -n suricata-ips-lab \
  python -m src.dashboard --host 127.0.0.1 --port 8090 \
  --eve /var/log/suricata/eve.json
```

仪表盘只绑定 `127.0.0.1`，Mac 使用 SSH 转发访问：

```bash
ssh -L 8090:127.0.0.1:8090 root@你的服务器公网IP
```

浏览器打开：

```text
http://127.0.0.1:8090
```

## 九、启动 Suricata 内联 IPS

停止默认被动服务并清理旧日志：

```bash
sudo systemctl stop suricata
sudo rm -f /var/log/suricata/eve.json /var/log/suricata/fast.log
```

启动 NFQUEUE IPS：

```bash
cd /root/suricata-ips-lab
sudo /opt/miniforge3/bin/conda run -n suricata-ips-lab \
  python -m src.ipsctl enable
```

`ipsctl.py` 只添加两条与实验端口相关的规则：

```text
iptables -I INPUT 1 -p tcp --dport 8080 -j NFQUEUE --queue-num 0 --queue-bypass
iptables -I OUTPUT 1 -p tcp --sport 8080 -j NFQUEUE --queue-num 0 --queue-bypass
```

因此 SSH 和 RDP 不进入队列，实验不会修改阿里云安全组。

查看状态：

```bash
sudo /opt/miniforge3/bin/conda run -n suricata-ips-lab \
  python -m src.ipsctl status
```

实时查看告警：

```bash
sudo tail -f /var/log/suricata/fast.log
```

## 十、Mac 发起公网攻击并验证防御

### 1. 正常请求

```bash
cd "/Users/zoo/Desktop/网安/实验 2"
conda activate suricata-ips-lab
python -m src.attack_simulator \
  --target http://你的服务器公网IP:8080 \
  --scenario normal \
  --i-own-this-target
```

预期：

```text
[REACHED] normal ... HTTP 200
```

这证明公网路径、实验服务和正常流量放行均工作正常。

### 2. 六类攻击请求

```bash
python -m src.attack_simulator \
  --target http://你的服务器公网IP:8080 \
  --scenario all \
  --i-own-this-target
```

脚本会发送无害攻击特征字符串，不执行真实漏洞利用。正常请求应返回 HTTP 200，其余六类请求应表现为连接被断开或超时，并显示为 `BLOCKED`。

### 3. 检查 JSON 阻断证据

```bash
sudo jq 'select(.event_type=="alert") |
  {time:.timestamp, action:.alert.action, signature:.alert.signature,
   src:.src_ip, dst:.dest_ip, dport:.dest_port}' \
  /var/log/suricata/eve.json
```

关键字段：

```json
{
  "action": "blocked",
  "signature": "LAB-IPS WEB SQL Injection UNION SELECT Attempt",
  "src": "Mac 的公网 IP",
  "dport": 8080
}
```

浏览器仪表盘也会实时显示相同告警。

## 十四、实验总结

本实验将原先只在 ECS 回环网卡上产生告警的 IDS 实验，升级为由 Mac 通过公网发起攻击流量、由 ECS 上 Suricata 内联 IPS 实际阻断、由浏览器实时展示结果的完整攻击与防御实验。

实验规则参考 Suricata 官方文档和 Emerging Threats Open 规则集的编写思路，使用 HTTP 应用层缓冲区、组合内容匹配、正则表达式和 `drop` 动作，覆盖六类主流 Web 攻击。实验结果表明，正常请求可以到达服务，恶意请求会被阻断，并在 EVE JSON 和浏览器仪表盘中留下来源 IP、规则名称和 `action=blocked` 证据。
