# TCP流量控制分析 - 算法实现逻辑

## 一、流量控制概述

TCP**流量控制（Flow Control）**是一种端到端的控制机制，目的是**防止发送方发送过快导致接收方缓冲区溢出**。

流量控制 vs 拥塞控制：
- **流量控制**：解决发送方和接收方之间的速率匹配问题
- **拥塞控制**：解决网络中间路由器的拥塞问题

## 二、滑动窗口机制原理

### 2.1 接收窗口（rwnd）

```
接收方缓冲区示意:

┌─────────────────────────────────────────────────────────┐
│             接收方缓冲区 (Receive Buffer)                │
├───────────────────────────────────────────────────────-─┤
│                                                         │
│   已确认已读取   │    已接收待读取    │    可接收空间    │
│   (已释放)      │    (占用中)        │    (rwnd通告)   │
│                 │                    │                  │
└─────────────────┴────────────────────┴──────────────────┘
                  ↑                    ↑
              已读指针              窗口边界

rwnd = 缓冲区大小 - 待读取数据量
```

### 2.2 窗口通告机制

```
发送方                              接收方
   │                                   │
   ├──── 数据 Seq=1, len=1000 ────────>│
   │                                   │  rcv_buffer: 4000 bytes
   │<──── ACK=1001, Window=3000 ───────┤  已用1000, 剩余3000
   │                                   │
   ├──── 数据 Seq=1001, len=1000 ─────>│
   │                                   │  应用读取500字节
   │<──── ACK=2001, Window=2500 ───────┤  已用1500, 剩余2500+500读取
   │                                   │
   │           ...                     │
   │                                   │
   │<──── ACK=N, Window=0 ─────────────┤  缓冲区满！
   │                                   │
   │    发送方停止发送,等待窗口更新     │
   │                                   │
   │<──── ACK=N, Window=1000 ──────────┤  窗口更新通告
   │                                   │
   ├──── 继续发送 ────────────────────>│
```

### 2.3 有效窗口计算

```
发送方可发送的数据量 = min(cwnd, rwnd)

其中:
- cwnd: 拥塞窗口（拥塞控制决定）
- rwnd: 接收窗口（流量控制决定）

发送窗口（Effective Window）:
                    ┌──────────────────────┐
                    │      已确认部分      │      可发送部分      │
已发送已确认 │ 已发送未确认 │ 可发送未发送 │ 不可发送 │
═══════════════════════════════════════════════════════════
            │←────── 发送窗口(usable) ──────→│
            │←─ 已发送 →│←─── 可用 ────→│
            
usable_window = rwnd - (SND.NXT - SND.UNA)
```

## 三、算法实现详解

### 3.1 窗口数据提取

```python
def get_window_evolution(self, conn_id):
    """
    获取窗口大小变化数据
    
    从每个数据包中提取窗口字段，形成时间序列
    
    参数:
        conn_id: TCP连接标识
        
    返回:
        list: 窗口数据列表
        [
            {
                'time': 时间戳,
                'window': 窗口大小,
                'direction': 数据方向
            },
            ...
        ]
    """
    packets = self.get_connection_packets(conn_id)
    
    window_data = []
    
    for pkt in packets:
        window_data.append({
            'time': pkt['time'],
            'window': pkt['window'],           # TCP首部的窗口字段
            'direction': f"{pkt['src_ip']}:{pkt['src_port']}"  # 记录方向
        })
    
    return window_data
```

### 3.2 窗口统计分析

```python
def analyze_window_statistics(window_data):
    """
    分析窗口统计信息
    
    返回:
        dict: {
            'min_window': 最小窗口,
            'max_window': 最大窗口,
            'avg_window': 平均窗口,
            'zero_window_count': 零窗口出现次数,
            'by_direction': 按方向统计
        }
    """
    if not window_data:
        return None
    
    windows = [d['window'] for d in window_data]
    
    min_window = min(windows)
    max_window = max(windows)
    avg_window = sum(windows) / len(windows)
    
    # 统计零窗口
    zero_window_count = sum(1 for w in windows if w == 0)
    
    # 按方向分组统计
    by_direction = {}
    for d in window_data:
        direction = d['direction']
        if direction not in by_direction:
            by_direction[direction] = {
                'windows': [],
                'zero_count': 0
            }
        by_direction[direction]['windows'].append(d['window'])
        if d['window'] == 0:
            by_direction[direction]['zero_count'] += 1
    
    # 计算每个方向的统计
    for direction, stats in by_direction.items():
        windows = stats['windows']
        stats['min'] = min(windows)
        stats['max'] = max(windows)
        stats['avg'] = sum(windows) / len(windows)
    
    return {
        'min_window': min_window,
        'max_window': max_window,
        'avg_window': avg_window,
        'zero_window_count': zero_window_count,
        'by_direction': by_direction
    }
```

### 3.3 零窗口检测

```python
def detect_zero_window_events(window_data):
    """
    检测零窗口事件
    
    零窗口事件表示接收方缓冲区已满，
    发送方需要停止发送并等待窗口更新。
    
    返回:
        list: 零窗口事件列表
        [
            {
                'start_time': 开始时间,
                'end_time': 结束时间,
                'duration': 持续时间,
                'direction': 方向
            },
            ...
        ]
    """
    events = []
    zero_start = None
    current_direction = None
    
    for d in window_data:
        if d['window'] == 0:
            if zero_start is None:
                # 开始一个零窗口周期
                zero_start = d['time']
                current_direction = d['direction']
        else:
            if zero_start is not None:
                # 结束零窗口周期
                events.append({
                    'start_time': zero_start,
                    'end_time': d['time'],
                    'duration': d['time'] - zero_start,
                    'direction': current_direction
                })
                zero_start = None
    
    return events
```

### 3.4 窗口缩放因子

```python
"""
TCP窗口缩放（Window Scaling）

问题: TCP窗口字段只有16位，最大65535字节
解决: RFC 1323引入窗口缩放选项

窗口缩放选项在三次握手时协商:
SYN: Window Scale = 7  → 实际窗口 = 窗口字段 × 2^7

实际窗口大小 = 窗口字段值 × 2^(缩放因子)
最大可达: 65535 × 2^14 ≈ 1GB
"""

def calculate_actual_window(window_field, scale_factor):
    """
    计算实际窗口大小
    
    参数:
        window_field: TCP首部窗口字段值(16位)
        scale_factor: 窗口缩放因子(0-14)
        
    返回:
        int: 实际窗口大小
    """
    return window_field << scale_factor  # 等价于 window_field × 2^scale_factor
```

## 四、可视化实现

### 4.1 窗口变化曲线

```python
class FlowControlWidget(QWidget):
    """流量控制组件"""
    
    def update_view(self, window_data):
        """更新视图"""
        if not window_data:
            return
        
        # 提取数据
        times = []
        windows = []
        directions = {}
        
        start_time = window_data[0]['time']
        
        for data in window_data:
            relative_time = data['time'] - start_time
            times.append(relative_time)
            windows.append(data['window'])
            
            # 按方向分组
            direction = data['direction']
            if direction not in directions:
                directions[direction] = {'times': [], 'windows': []}
            directions[direction]['times'].append(relative_time)
            directions[direction]['windows'].append(data['window'])
        
        # 计算统计信息
        if windows:
            min_window = min(windows)
            max_window = max(windows)
            avg_window = sum(windows) / len(windows)
            
            self.min_window_label.setText(f"最小窗口: {min_window} bytes")
            self.max_window_label.setText(f"最大窗口: {max_window} bytes")
            self.avg_window_label.setText(f"平均窗口: {avg_window:.0f} bytes")
        
        # 绘制图表
        self.figure.clear()
        ax = self.figure.add_subplot(111)
        
        # 如果有多个方向，分别绘制
        colors = ['#1f77b4', '#ff7f0e', '#2ca02c', '#d62728']
        for idx, (direction, data) in enumerate(directions.items()):
            color = colors[idx % len(colors)]
            label = direction.split(':')[0]  # 只显示IP
            ax.plot(data['times'], data['windows'], '.-',
                   label=f'{label}', color=color, linewidth=2, markersize=4)
        
        ax.set_xlabel('时间 (秒)')
        ax.set_ylabel('窗口大小 (bytes)')
        ax.set_title('TCP接收窗口大小变化')
        ax.grid(True, alpha=0.3)
        
        if len(directions) > 1:
            ax.legend()
        
        # 标注零窗口事件
        zero_windows = [(t, w) for t, w in zip(times, windows) if w == 0]
        if zero_windows:
            zero_times = [t for t, w in zero_windows]
            zero_vals = [0 for t, w in zero_windows]
            ax.plot(zero_times, zero_vals, 'ro', markersize=8,
                   label='零窗口', zorder=10)
            ax.legend()
        
        self.figure.tight_layout()
        self.canvas.draw()
```

## 五、零窗口处理机制

### 5.1 零窗口探测

```
问题: 如果窗口更新ACK丢失怎么办?

发送方                              接收方
   │                                   │
   │<──── ACK, Window=0 ───────────────┤
   │                                   │
   │   发送方停止发送                   │  应用读取数据
   │                                   │  窗口恢复
   │                                   │
   │         ACK, Window=1000 ───────X │  丢失!
   │                                   │
   │   双方陷入死锁!                    │
   │                                   │

解决方案: 零窗口探测 (Zero Window Probe)

发送方                              接收方
   │                                   │
   │<──── ACK, Window=0 ───────────────┤
   │                                   │
   │       启动探测定时器               │
   │                                   │
   ├──── ZWP(1字节) ───────────────────>│  零窗口探测
   │                                   │
   │<──── ACK, Window=1000 ────────────┤  返回当前窗口
   │                                   │
   ├──── 继续发送 ────────────────────>│
```

### 5.2 Silly Window Syndrome

```
问题: 糊涂窗口综合症

场景: 应用程序每次只读1字节
发送 Seq=1, len=1
ACK Window=1
发送 Seq=2, len=1
ACK Window=1
...

效率极低! 每个1字节数据需要40字节TCP/IP头部

解决方案:
1. 接收方(Clark算法): 
   - 窗口小于MSS或缓冲区一半时，通告窗口为0
   
2. 发送方(Nagle算法):
   - 有未确认数据时，延迟发送小数据
   - 累积到MSS或收到ACK后再发送
```

## 六、知识点总结

### 6.1 流量控制核心概念

| 概念 | 说明 |
|------|------|
| rwnd | 接收窗口，接收方通告的可接收数据量 |
| 窗口通告 | 每个ACK携带当前窗口大小 |
| 有效窗口 | min(cwnd, rwnd) |
| 零窗口 | 接收方缓冲区满，通告窗口为0 |

### 6.2 关键机制

| 机制 | 说明 |
|------|------|
| 滑动窗口 | 窗口随数据确认向前滑动 |
| 窗口缩放 | 通过缩放因子扩大窗口上限 |
| 零窗口探测 | 防止窗口更新丢失导致死锁 |
| Nagle算法 | 避免发送大量小包 |

### 6.3 实现要点

| 要点 | 说明 |
|------|------|
| 方向区分 | 双方各自通告自己的接收窗口 |
| 时序分析 | 窗口随时间变化反映缓冲区状态 |
| 零窗口检测 | 零窗口表示接收方压力大 |
| 统计分析 | 平均窗口反映连接的整体状况 |
