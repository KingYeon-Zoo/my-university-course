# TCP重传检测算法 - 算法实现逻辑

## 一、TCP重传机制概述

TCP是**可靠传输协议**，通过**重传机制**保证数据可靠交付。当发送方检测到数据丢失时，会重新发送未被确认的数据段。

## 二、触发重传的场景

### 2.1 超时重传（Timeout Retransmission）

```
发送方                              接收方
   │                                   │
   ├──── 数据包 Seq=100 ─────────X     │  丢失!
   │                                   │
   │      启动重传计时器 RTO            │
   │                                   │
   │           ... 等待 ...            │
   │                                   │
   │      RTO超时！                    │
   │                                   │
   ├──── 数据包 Seq=100 (重传) ───────>│  重传成功
   │                                   │
   │<──── ACK = 200 ───────────────────┤  收到确认
```

**超时时间（RTO）计算**：

```
SRTT = (1 - α) × SRTT + α × RTT_sample
RTTVAR = (1 - β) × RTTVAR + β × |SRTT - RTT_sample|
RTO = SRTT + 4 × RTTVAR

典型参数: α = 0.125, β = 0.25
```

### 2.2 快速重传（Fast Retransmission）

```
发送方                              接收方
   │                                   │
   ├──── Seq=100 ──────────────────────>│
   ├──── Seq=200 ────────────────X      │  丢失!
   ├──── Seq=300 ──────────────────────>│
   ├──── Seq=400 ──────────────────────>│
   ├──── Seq=500 ──────────────────────>│
   │                                   │
   │<──── ACK=200 (第1次) ──────────────┤  收到Seq=100
   │<──── ACK=200 (第2次,重复) ─────────┤  收到Seq=300,期望200
   │<──── ACK=200 (第3次,重复) ─────────┤  收到Seq=400,期望200
   │<──── ACK=200 (第4次,重复) ─────────┤  收到Seq=500,期望200
   │                                   │
   │   收到3个重复ACK,立即重传!        │
   │                                   │
   ├──── Seq=200 (快速重传) ───────────>│
   │                                   │
   │<──── ACK=600 ──────────────────────┤  累积确认到Seq=600
```

**3个重复ACK触发重传的原理**：

1. 1个重复ACK：可能是正常乱序
2. 2个重复ACK：可能还是乱序
3. **3个重复ACK**：大概率是丢包，立即重传（无需等待超时）

### 2.3 选择性重传（SACK）

```
TCP选项: SACK (Selective Acknowledgment)

发送方                              接收方
   │                                   │
   ├──── Seq=100-199 ──────────────────>│
   ├──── Seq=200-299 ────────X          │  丢失
   ├──── Seq=300-399 ──────────────────>│
   ├──── Seq=400-499 ──────────────────>│
   │                                   │
   │<── ACK=200, SACK=[300-500] ────────┤
   │                                   │
   │   只需重传Seq=200-299             │
   │                                   │
   ├──── Seq=200-299 (重传) ───────────>│
```

## 三、重传检测算法实现

### 3.1 核心检测算法

```python
def detect_retransmission(self, conn_id):
    """
    检测TCP重传
    
    算法原理:
    在同一方向上,如果相同序列号的数据包出现多次,
    后面出现的就是重传包。
    
    关键步骤:
    1. 获取连接的所有数据包
    2. 按发送方向分组
    3. 在每个方向上检测重复序列号
    4. 记录原始包和重传包的信息
    
    参数:
        conn_id: TCP连接标识
        
    返回:
        list: 重传信息列表
        [
            {
                'original': 原始数据包,
                'retransmit': 重传数据包,
                'direction': 数据流方向
            },
            ...
        ]
    """
    packets = self.get_connection_packets(conn_id)
    retransmissions = []
    
    # 步骤1: 按方向分组
    # 方向定义: "源IP:源端口 -> 目的IP:目的端口"
    direction_seqs = defaultdict(list)
    
    for pkt in packets:
        # 构造方向标识
        direction = f"{pkt['src_ip']}:{pkt['src_port']}->{pkt['dst_ip']}:{pkt['dst_port']}"
        
        # 只考虑有数据的包（纯ACK包不参与重传检测）
        if pkt['length'] > 0:
            direction_seqs[direction].append(pkt)
    
    # 步骤2: 在每个方向检测重传
    for direction, pkts in direction_seqs.items():
        # 记录每个序列号首次出现的数据包
        seen_seqs = {}
        
        for pkt in pkts:
            seq = pkt['seq']
            
            if seq in seen_seqs:
                # 发现重传!
                # 相同序列号再次出现,说明是重传
                retransmissions.append({
                    'original': seen_seqs[seq],  # 原始包
                    'retransmit': pkt,           # 重传包
                    'direction': direction
                })
            else:
                # 首次出现,记录
                seen_seqs[seq] = pkt
    
    return retransmissions
```

### 3.2 方向分组详解

为什么需要按方向分组？

```
场景分析:
A → B: 发送 Seq=100 的数据
B → A: 发送 Seq=100 的数据（B也可能使用相同序列号）

如果不区分方向,会误判为重传!

正确做法:
方向1: A:5000 -> B:80  检测A发送的重传
方向2: B:80 -> A:5000  检测B发送的重传
```

```python
def create_direction_key(pkt):
    """
    创建方向键
    
    格式: "源IP:源端口->目的IP:目的端口"
    
    示例:
    - 客户端发送: "192.168.1.1:5000->10.0.0.1:80"
    - 服务器发送: "10.0.0.1:80->192.168.1.1:5000"
    """
    return f"{pkt['src_ip']}:{pkt['src_port']}->{pkt['dst_ip']}:{pkt['dst_port']}"
```

## 四、重传类型识别

### 4.1 超时重传 vs 快速重传

```python
def classify_retransmission(retrans, ack_data):
    """
    分类重传类型
    
    判断依据:
    - 超时重传: 重传间隔接近RTO
    - 快速重传: 重传前有3个重复ACK
    
    参数:
        retrans: 重传信息
        ack_data: ACK数据列表
        
    返回:
        str: 'timeout' 或 'fast_retransmit'
    """
    original = retrans['original']
    retransmit = retrans['retransmit']
    
    # 计算重传间隔
    interval = retransmit['time'] - original['time']
    
    # 检查是否有3个重复ACK
    dup_ack_count = 0
    expected_ack = original['seq']
    
    for ack in ack_data:
        if original['time'] < ack['time'] < retransmit['time']:
            if ack['ack'] == expected_ack:
                dup_ack_count += 1
    
    if dup_ack_count >= 3:
        return 'fast_retransmit'
    else:
        return 'timeout'
```

### 4.2 重传统计分析

```python
def analyze_retransmission_stats(retransmissions, total_packets):
    """
    分析重传统计信息
    
    返回:
        dict: {
            'count': 重传次数,
            'rate': 重传率(%),
            'avg_interval': 平均重传间隔(ms),
            'by_direction': 按方向统计
        }
    """
    if not retransmissions:
        return {
            'count': 0,
            'rate': 0.0,
            'avg_interval': 0.0,
            'by_direction': {}
        }
    
    # 计算重传次数
    count = len(retransmissions)
    
    # 计算重传率
    rate = (count / total_packets) * 100
    
    # 计算平均重传间隔
    intervals = []
    for r in retransmissions:
        interval = (r['retransmit']['time'] - r['original']['time']) * 1000  # ms
        intervals.append(interval)
    avg_interval = sum(intervals) / len(intervals)
    
    # 按方向统计
    by_direction = defaultdict(int)
    for r in retransmissions:
        by_direction[r['direction']] += 1
    
    return {
        'count': count,
        'rate': rate,
        'avg_interval': avg_interval,
        'by_direction': dict(by_direction)
    }
```

## 六、算法优化

### 6.1 处理序列号回绕

```python
def seq_less_than(seq1, seq2, window=2**31):
    """
    比较序列号大小（处理32位回绕）
    
    TCP序列号是32位无符号整数，会发生回绕：
    4294967295 + 1 = 0
    
    使用半窗口法判断大小关系
    """
    diff = (seq1 - seq2) % (2**32)
    return diff > window
```

### 6.2 处理同一包的多次重传

```python
def detect_multiple_retransmissions(direction_seqs):
    """
    检测同一数据包的多次重传
    
    场景: 数据包丢失多次，导致多次重传
    """
    retransmissions = []
    
    for direction, pkts in direction_seqs.items():
        seq_packets = defaultdict(list)
        
        for pkt in pkts:
            seq_packets[pkt['seq']].append(pkt)
        
        for seq, pkt_list in seq_packets.items():
            if len(pkt_list) > 1:
                # 按时间排序
                pkt_list.sort(key=lambda x: x['time'])
                
                # 第一个是原始包，后面的都是重传
                original = pkt_list[0]
                for retrans in pkt_list[1:]:
                    retransmissions.append({
                        'original': original,
                        'retransmit': retrans,
                        'direction': direction,
                        'retrans_count': len(pkt_list) - 1
                    })
    
    return retransmissions
```

## 七、知识点总结

### 7.1 重传机制核心要点

| 知识点 | 说明 |
|--------|------|
| 超时重传 | RTO超时后重传，RTO基于RTT计算 |
| 快速重传 | 3个重复ACK立即重传，无需等待超时 |
| SACK | 选择性重传，只重传丢失的段 |
| 重传次数 | 超过最大重传次数会放弃连接 |

### 7.2 检测算法关键

| 关键点 | 实现方式 |
|--------|----------|
| 方向分组 | 按源→目标分组，避免误判 |
| 只检测数据包 | 过滤length=0的纯ACK包 |
| 序列号匹配 | 相同序列号再次出现即为重传 |
| 时间差计算 | 用于估算RTO和分类重传类型 |

### 7.3 重传对性能的影响

| 影响 | 说明 |
|------|------|
| 增加延迟 | 重传需要等待超时或重复ACK |
| 降低吞吐量 | 带宽被重传数据占用 |
| 触发拥塞控制 | 重传表示网络拥塞，触发降速 |
