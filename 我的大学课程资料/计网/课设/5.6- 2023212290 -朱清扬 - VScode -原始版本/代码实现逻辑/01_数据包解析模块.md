# 数据包解析模块 - 算法实现逻辑

## 一、模块概述

数据包解析模块（`packet_parser.py`）是整个系统的**核心基础模块**，负责从Wireshark捕获的pcap/pcapng文件中读取原始网络数据包，并按照TCP/IP协议栈进行分层解析，提取TCP连接信息。

## 二、TCP/IP协议栈分层解析原理

### 2.1 协议栈层次结构

```
┌─────────────────────────────────────────────────────────────┐
│  应用层 (Application Layer)                                  │
│  HTTP, FTP, SMTP, DNS 等应用协议数据                         │
└─────────────────────────────────────────────────────────────┘
                          ▲
                          │ 解封装

│  │ ├── 确认号 Ack (32位)                                    ││

│  │ ├── 窗口大小 Window (16位)                               ││

                          ▼

│  ┌─────────────────────────────────────────────────────────┐│
│  │ IP首部 (20字节 + 可选项)                                 ││
│  │ ├── 版本(4位) + 首部长度(4位) + 服务类型(8位)            ││
│  │ ├── 总长度 (16位)                                        ││
│  │ ├── 标识(16位) + 标志(3位) + 片偏移(13位)                ││
│  │ ├── TTL(8位) + 协议(8位) + 首部校验和(16位)              ││

                          ▲

                          ▼

│  │ 以太网帧首部 (14字节)                                    ││
│  │ ├── 目的MAC地址 (48位)                                   ││
│  │ ├── 源MAC地址 (48位)                                     ││
│  │ └── 类型字段 (16位) - 标识上层协议类型                   ││
│  └─────────────────────────────────────────────────────────┘│
│  + 帧载荷 (IP数据报) + FCS校验                               │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 TCP标志位详解

TCP首部包含6个重要的**控制标志位**，用于控制TCP连接状态和数据传输：

| 标志位 | 数值 | 名称 | 作用 |
|--------|------|------|------|
| URG | 0x20 | Urgent | 紧急指针有效，优先传输 |
| ACK | 0x10 | Acknowledge | 确认号有效 |
| PSH | 0x08 | Push | 推送数据给应用层 |
| RST | 0x04 | Reset | 重置连接 |
| SYN | 0x02 | Synchronize | 同步序列号，建立连接 |
| FIN | 0x01 | Finish | 结束连接 |

**常见标志组合**：
- `SYN (0x02)`: 连接请求
- `SYN+ACK (0x12)`: 连接确认
- `ACK (0x10)`: 纯确认或数据确认
- `FIN+ACK (0x11)`: 关闭连接请求
- `RST (0x04)`: 强制重置连接

## 三、TCP连接识别算法

### 3.1 四元组唯一标识原理

在TCP/IP协议中，一个TCP连接由**四元组**唯一确定：

```
TCP连接 = (源IP地址, 源端口号, 目的IP地址, 目的端口号)
```

**为什么需要四元组？**

1. **源IP地址**：标识发送方主机
2. **源端口号**：标识发送方应用进程
3. **目的IP地址**：标识接收方主机
4. **目的端口号**：标识接收方应用进程

四元组的任何一个元素不同，都代表不同的TCP连接。

### 3.2 连接标识规范化算法

由于TCP是**全双工**协议，同一连接的双向数据包四元组互为反向。为了将双向数据包归到同一连接，需要对四元组进行**规范化**：

```python
def normalize_connection_id(src_ip, src_port, dst_ip, dst_port):
    """
    连接标识规范化算法
    
    核心思想：选择一个确定的排序规则，使得双向数据包生成相同的连接ID
    
    排序规则：将较小的(IP, Port)元组放在前面
    """
    # 比较元组大小
    if (src_ip, src_port) < (dst_ip, dst_port):
        # 源端较小，正序
        conn_id = f"{src_ip}:{src_port} <-> {dst_ip}:{dst_port}"
    else:
        # 目的端较小，反序
        conn_id = f"{dst_ip}:{dst_port} <-> {src_ip}:{src_port}"
    
    return conn_id
```

**示例**：

| 数据包方向 | 四元组 | 规范化后的连接ID |
|------------|--------|------------------|
| A → B | (192.168.1.1, 5000, 10.0.0.1, 80) | 10.0.0.1:80 <-> 192.168.1.1:5000 |
| B → A | (10.0.0.1, 80, 192.168.1.1, 5000) | 10.0.0.1:80 <-> 192.168.1.1:5000 |

两个方向的数据包生成**相同的连接ID**，实现双向归并。

### 3.3 完整的连接提取算法

```python
def _extract_tcp_connections(self):
    """
    TCP连接提取算法
    
    输入: 原始数据包列表 self.packets
    输出: 按连接分组的数据包字典 self.tcp_connections
    
    算法复杂度: O(n)，n为数据包数量
    """
    # 使用defaultdict自动初始化空列表
    conn_packets = defaultdict(list)
    
    for idx, pkt in enumerate(self.packets):
        # 步骤1: 过滤非TCP数据包
        if TCP in pkt and IP in pkt:
            
            # 步骤2: 提取四元组信息
            src_ip = pkt[IP].src       # 源IP地址
            dst_ip = pkt[IP].dst       # 目的IP地址
            src_port = pkt[TCP].sport  # 源端口
            dst_port = pkt[TCP].dport  # 目的端口
            
            # 步骤3: 生成规范化连接ID
            if (src_ip, src_port) < (dst_ip, dst_port):
                conn_id = f"{src_ip}:{src_port} <-> {dst_ip}:{dst_port}"
            else:
                conn_id = f"{dst_ip}:{dst_port} <-> {src_ip}:{src_port}"
            
            # 步骤4: 提取TCP首部关键字段
            packet_info = {
                'index': idx,                                    # 原始索引
                'time': float(pkt.time),                        # 时间戳
                'src_ip': src_ip,                               # 源IP
                'dst_ip': dst_ip,                               # 目的IP
                'src_port': src_port,                           # 源端口
                'dst_port': dst_port,                           # 目的端口
                'seq': pkt[TCP].seq,                            # 序列号
                'ack': pkt[TCP].ack,                            # 确认号
                'flags': pkt[TCP].flags,                        # 标志位
                'window': pkt[TCP].window,                      # 窗口大小
                'length': len(pkt[TCP].payload) if pkt[TCP].payload else 0,  # 载荷长度
                'packet': pkt                                   # 原始数据包
            }
            
            # 步骤5: 按连接ID分组存储
            conn_packets[conn_id].append(packet_info)
    
    # 步骤6: 生成连接列表，包含统计信息
    for conn_id, packets in conn_packets.items():
        if len(packets) > 0:
            self.tcp_connections[conn_id] = packets
            
            # 计算连接时间范围
            start_time = min(p['time'] for p in packets)
            end_time = max(p['time'] for p in packets)
            
            self.connection_list.append({
                'id': conn_id,
                'packet_count': len(packets),
                'start_time': start_time,
                'end_time': end_time,
                'duration': end_time - start_time
            })
```

## 四、Scapy库数据包处理

### 4.1 pcap文件读取

Scapy提供`rdpcap()`函数读取pcap/pcapng文件：

```python
from scapy.all import rdpcap, TCP, IP

def load_pcap(self, filename):
    """
    加载pcap/pcapng文件
    
    Scapy支持的文件格式:
    - pcap: 经典libpcap格式
    - pcapng: 下一代pcap格式，支持更多元数据
    
    返回: PacketList对象，可像列表一样遍历
    """
    try:
        self.packets = rdpcap(filename)
        print(f"成功加载 {len(self.packets)} 个数据包")
        return True
    except Exception as e:
        print(f"加载文件失败: {e}")
        return False
```

### 4.2 协议层访问

Scapy使用**协议层索引**访问各层字段：

```python
# 访问IP层字段
pkt[IP].src      # 源IP地址
pkt[IP].dst      # 目的IP地址
pkt[IP].ttl      # 生存时间

# 访问TCP层字段
pkt[TCP].sport   # 源端口
pkt[TCP].dport   # 目的端口
pkt[TCP].seq     # 序列号
pkt[TCP].ack     # 确认号
pkt[TCP].flags   # 标志位
pkt[TCP].window  # 窗口大小
pkt[TCP].payload # TCP载荷数据

# 检查协议层是否存在
if TCP in pkt and IP in pkt:
    # 确认是TCP/IP数据包
    pass
```

## 五、数据存储结构

### 5.1 数据包信息字典

每个TCP数据包被解析为以下字典结构：

```python
packet_info = {
    'index': int,       # 在原始文件中的索引位置
    'time': float,      # Unix时间戳（秒）
    'src_ip': str,      # 源IP地址，如 "192.168.1.1"
    'dst_ip': str,      # 目的IP地址
    'src_port': int,    # 源端口号，如 5000
    'dst_port': int,    # 目的端口号，如 80
    'seq': int,         # 32位序列号
    'ack': int,         # 32位确认号
    'flags': int/str,   # TCP标志位，可能是整数或字符串
    'window': int,      # 16位窗口大小
    'length': int,      # TCP载荷数据长度（字节）
    'packet': Packet    # Scapy原始数据包对象
}
```

### 5.2 连接信息存储

连接使用字典存储，支持O(1)时间复杂度的查找：

```python
# tcp_connections: {连接ID: 数据包列表}

    "192.168.1.2:6000 <-> 10.0.0.2:443": [packet_info1, packet_info2, ...],
    ...
}

# connection_list: 连接汇总信息列表

    {
        'id': "192.168.1.1:5000 <-> 10.0.0.1:80",
        'packet_count': 156,
        'start_time': 1699600000.123456,
        'end_time': 1699600010.654321,
        'duration': 10.530865

    ...
]
```

## 六、算法性能分析

| 操作 | 时间复杂度 | 空间复杂度 | 说明 |
|------|------------|------------|------|
| 文件读取 | O(n) | O(n) | n为数据包数量 |
| 连接提取 | O(n) | O(n) | 单次遍历 |
| 连接查询 | O(1) | - | 使用字典哈希 |
| 数据包排序 | O(k log k) | O(k) | k为单连接包数 |

## 七、关键技术要点

1. **协议分层解析**：遵循TCP/IP协议栈的分层结构，从底层到高层逐层解封装
2. **四元组识别**：使用(源IP, 源端口, 目IP, 目端口)唯一标识TCP连接
3. **连接ID规范化**：通过排序保证双向数据包归并到同一连接
4. **高效存储**：使用字典实现O(1)查找，使用列表保持数据包时序
5. **惰性计算**：只在需要时才执行分析计算，避免资源浪费
