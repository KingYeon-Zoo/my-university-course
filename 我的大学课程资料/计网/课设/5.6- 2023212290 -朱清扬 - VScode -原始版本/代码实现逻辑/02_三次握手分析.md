# TCP三次握手分析 - 算法实现逻辑

## 一、TCP三次握手概述

TCP三次握手（Three-Way Handshake）是TCP建立可靠连接的核心机制，通过三次报文交互完成以下目标：

1. **同步序列号**：双方交换初始序列号（ISN），为后续数据传输建立编号基准
2. **确认可达性**：验证双方都能正常收发数据
3. **协商参数**：交换窗口大小、MSS（最大段大小）等连接参数

## 二、三次握手协议流程

### 2.1 详细流程图

```
     客户端 (Client)                          服务器 (Server)
         │                                        │
         │  状态: CLOSED                          │  状态: LISTEN
         │                                        │
    时刻T1 ├───────────── SYN ─────────────────────>│
         │  Seq = x                               │
         │  Flags = SYN (0x02)                    │
         │                                        │
         │  状态: SYN_SENT                        │  状态: SYN_RECEIVED
         │                                        │
    时刻T2 │<──────────── SYN-ACK ──────────────────┤
         │              Seq = y                   │
         │              Ack = x + 1               │
         │              Flags = SYN+ACK (0x12)    │
         │                                        │
    时刻T3 ├───────────── ACK ─────────────────────>│
         │  Seq = x + 1                           │
         │  Ack = y + 1                           │
         │  Flags = ACK (0x10)                    │
         │                                        │
         │  状态: ESTABLISHED                     │  状态: ESTABLISHED
         │                                        │
         │<════════════ 数据传输 ═════════════════>│
```

### 2.2 各步骤详细说明

#### 第一次握手 (SYN)

**发送方**: 客户端
**目的**: 请求建立连接，同步客户端ISN

| 字段 | 值 | 说明 |
|------|-----|------|
| 序列号 Seq | x | 客户端的初始序列号（ISN） |
| 确认号 Ack | 0 | 未设置，因为还没有收到对方数据 |
| 标志位 Flags | SYN (0x02) | 同步标志，表示请求连接 |
| 窗口大小 Window | wc | 客户端接收缓冲区大小 |

**状态转换**:
- 客户端: CLOSED → SYN_SENT

#### 第二次握手 (SYN-ACK)

**发送方**: 服务器
**目的**: 确认客户端请求，同步服务器ISN

| 字段 | 值 | 说明 |
|------|-----|------|
| 序列号 Seq | y | 服务器的初始序列号（ISN） |
| 确认号 Ack | x + 1 | 确认收到客户端SYN，期望下一个字节 |
| 标志位 Flags | SYN+ACK (0x12) | 同步+确认标志 |
| 窗口大小 Window | ws | 服务器接收缓冲区大小 |

**状态转换**:
- 服务器: LISTEN → SYN_RECEIVED

#### 第三次握手 (ACK)

**发送方**: 客户端
**目的**: 确认服务器响应，完成连接建立

| 字段 | 值 | 说明 |
|------|-----|------|
| 序列号 Seq | x + 1 | 客户端下一个序列号 |
| 确认号 Ack | y + 1 | 确认收到服务器SYN，期望下一个字节 |
| 标志位 Flags | ACK (0x10) | 确认标志 |

**状态转换**:
- 客户端: SYN_SENT → ESTABLISHED
- 服务器: SYN_RECEIVED → ESTABLISHED

## 三、为什么需要三次握手？

### 3.1 两次握手的问题

如果只有两次握手（客户端SYN，服务器SYN-ACK），会导致**历史连接问题**：

```
场景：网络延迟导致旧的SYN请求到达

时刻T1: 客户端发送 SYN(x=100)，但网络延迟
时刻T2: 客户端超时，重发 SYN(x=200)
时刻T3: 服务器收到 SYN(x=200)，回复 SYN-ACK(y=300, ack=201)
时刻T4: 连接建立，正常通信
时刻T5: 客户端关闭连接
时刻T6: 旧的 SYN(x=100) 终于到达服务器
时刻T7: 服务器收到，回复 SYN-ACK(y=400, ack=101) ← 问题！
        服务器认为建立了新连接，但客户端已关闭
```

### 3.2 三次握手的解决方案

第三次握手（ACK）允许客户端**确认或拒绝**连接：

```
时刻T6: 旧的 SYN(x=100) 到达服务器
时刻T7: 服务器回复 SYN-ACK(y=400, ack=101)
时刻T8: 客户端收到但发现序列号不匹配
时刻T9: 客户端发送 RST 重置连接
结果：历史连接被正确拒绝
```

### 3.3 三次握手的核心作用

| 作用 | 说明 |
|------|------|
| 防止历史连接 | 第三次握手可以拒绝无效的旧连接请求 |
| 序列号同步 | 双方都能确认对方的初始序列号 |
| 双向可达验证 | 确认双方都能正确收发数据 |
| 资源分配时机 | 服务器在确认客户端活跃后再分配资源 |

## 四、算法实现详解

### 4.1 握手分析核心算法

```python
def analyze_handshake(self, conn_id):
    """
    分析TCP三次握手
    
    算法流程:
    1. 获取连接的所有数据包
    2. 在前N个包中搜索SYN、SYN-ACK、ACK
    3. 验证时序和确认号的正确性
    4. 返回握手信息
    
    参数:
        conn_id: TCP连接标识
        
    返回:
        dict: 包含syn、syn_ack、ack三个数据包信息
        None: 如果未检测到完整握手
    """
    packets = self.get_connection_packets(conn_id)
    
    # 少于3个包无法完成握手
    if len(packets) < 3:
        return None
    
    # 初始化三个握手包的引用
    syn_packet = None
    syn_ack_packet = None
    ack_packet = None
    
    # 只在前10个包中查找（握手通常发生在连接开始）
    for pkt in packets[:10]:
        flags = pkt['flags']
        
        # 检测 SYN 包 (flags = 2 或 'S')
        # SYN标志位: 0x02 = 00000010
        if flags == 2 or flags == 'S':
            if syn_packet is None:
                syn_packet = pkt
        
        # 检测 SYN-ACK 包 (flags = 18 或 'SA')
        # SYN+ACK标志位: 0x12 = 00010010
        elif flags == 18 or flags == 'SA':
            if syn_ack_packet is None:
                syn_ack_packet = pkt
        
        # 检测 ACK 包 (flags = 16 或 'A')
        # ACK标志位: 0x10 = 00010000
        elif flags == 16 or flags == 'A':
            # ACK包必须在SYN和SYN-ACK之后才是第三次握手
            if syn_packet and syn_ack_packet and ack_packet is None:
                ack_packet = pkt
    
    # 检验三次握手是否完整
    if syn_packet and syn_ack_packet and ack_packet:
        return {
            'syn': syn_packet,
            'syn_ack': syn_ack_packet,
            'ack': ack_packet,
            'complete': True
        }
    
    return None
```

### 4.2 标志位识别逻辑

```python
def is_syn_packet(flags):
    """
    判断是否为SYN包
    
    SYN包特征:
    - 仅设置SYN标志位
    - 不设置ACK标志位
    
    标志位值: 0x02 (二进制: 00000010)
    """
    if isinstance(flags, int):
        # SYN=1且ACK=0
        return (flags & 0x02) != 0 and (flags & 0x10) == 0
    elif isinstance(flags, str):
        return flags == 'S'
    return False

def is_syn_ack_packet(flags):
    """
    判断是否为SYN-ACK包
    
    SYN-ACK包特征:
    - 同时设置SYN和ACK标志位
    
    标志位值: 0x12 (二进制: 00010010)
    """
    if isinstance(flags, int):
        # SYN=1且ACK=1
        return (flags & 0x12) == 0x12
    elif isinstance(flags, str):
        return flags == 'SA' or set(flags) == {'S', 'A'}
    return False

def is_ack_packet(flags):
    """
    判断是否为纯ACK包
    
    纯ACK包特征:
    - 仅设置ACK标志位
    - 不设置SYN、FIN标志位
    
    标志位值: 0x10 (二进制: 00010000)
    """
    if isinstance(flags, int):
        # ACK=1且SYN=0且FIN=0
        return (flags & 0x10) != 0 and (flags & 0x03) == 0
    elif isinstance(flags, str):
        return flags == 'A'
    return False
```

### 4.3 确认号验证算法

```python
def validate_handshake_sequence(syn, syn_ack, ack):
    """
    验证三次握手的序列号和确认号是否正确
    
    正确的握手应满足:
    1. SYN-ACK.ack == SYN.seq + 1
    2. ACK.seq == SYN.seq + 1
    3. ACK.ack == SYN-ACK.seq + 1
    4. 时间顺序: SYN.time < SYN-ACK.time < ACK.time
    
    参数:
        syn: 第一次握手数据包
        syn_ack: 第二次握手数据包
        ack: 第三次握手数据包
        
    返回:
        bool: 是否为有效的三次握手
    """
    # 验证时序
    if not (syn['time'] < syn_ack['time'] < ack['time']):
        return False
    
    # 验证SYN-ACK确认了SYN
    # SYN-ACK的确认号应该是SYN序列号+1
    if syn_ack['ack'] != (syn['seq'] + 1) % (2**32):
        return False
    
    # 验证ACK确认了SYN-ACK
    # ACK的确认号应该是SYN-ACK序列号+1
    if ack['ack'] != (syn_ack['seq'] + 1) % (2**32):
        return False
    
    return True
```

### 5.2 动画定时器控制

```python
def start_animation(self, mode='handshake'):
    """
    启动握手动画
    
    使用QTimer控制动画播放速度
    每800毫秒更新一帧
    """
    self.animation_mode = mode
    self.animation_step = 0
    
    # 创建定时器
    self.animation_timer = QTimer()
    self.animation_timer.timeout.connect(self.next_animation_step)
    self.animation_timer.start(800)  # 800ms/帧

def next_animation_step(self):
    """
    动画帧更新
    
    三次握手共6步:
    - Step 1-2: SYN + 状态
    - Step 3-4: SYN-ACK + 状态
    - Step 5-6: ACK + 状态
    """
    max_steps = 6
    
    if self.animation_step < max_steps:
        self.animation_step += 1
        self.update()  # 触发重绘
    else:
        self.animation_timer.stop()
```

## 六、关键知识点总结

### 6.1 三次握手核心要点

| 要点 | 说明 |
|------|------|
| SYN标志 | 同步标志，用于建立连接，消耗一个序列号 |
| ISN | 初始序列号，应选择随机值以防止攻击 |
| 确认号含义 | 期望收到的下一个字节序号 |
| 状态转换 | CLOSED → SYN_SENT → ESTABLISHED |
| 超时重传 | SYN包丢失会触发重传机制 |

### 6.2 算法实现要点

| 要点 | 说明 |
|------|------|
| 标志位匹配 | 支持整数(2/18/16)和字符串('S'/'SA'/'A') |
| 时序验证 | 确保三个包按正确顺序到达 |
| 确认号验证 | 验证ack = seq + 1的关系 |
| 搜索范围 | 只在前10个包中查找握手包 |
| 异常处理 | 返回None表示未检测到完整握手 |

### 6.3 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 未找到完整握手 | 抓包开始晚于连接建立 | 提示用户连接已在进行中 |
| SYN重传 | 网络延迟或丢包 | 检测多个SYN包，取第一个 |
| RST包干扰 | 连接被重置 | 识别RST并标记连接失败 |
