# TCP拥塞控制分析 - 算法实现逻辑

## 一、拥塞控制概述

TCP**拥塞控制（Congestion Control）**是一种端到端的控制机制，目的是**防止发送方发送过快导致网络拥塞**。

拥塞控制 vs 流量控制：
- **流量控制**：防止发送方淹没接收方（端到端）
- **拥塞控制**：防止发送方淹没网络（端到网络）

## 二、拥塞控制核心算法

### 2.1 四大核心算法

TCP拥塞控制包含四个核心算法（RFC 5681）：

```
┌─────────────────────────────────────────────────────────────┐
│                    TCP拥塞控制算法                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 慢启动 (Slow Start)                                     │
│     ├── 初始cwnd = 1-10 MSS                                 │
│     ├── 每收到一个ACK: cwnd += 1 MSS (指数增长)             │
│     └── 终止条件: cwnd >= ssthresh 或 检测到丢包             │
│                                                             │
│  2. 拥塞避免 (Congestion Avoidance)                         │
│     ├── 触发: cwnd >= ssthresh                              │
│     ├── 每个RTT: cwnd += 1 MSS (线性增长)                   │
│     └── 终止条件: 检测到丢包                                │
│                                                             │
│  3. 快速重传 (Fast Retransmit)                              │
│     ├── 触发: 收到3个重复ACK                                │
│     └── 动作: 立即重传,无需等待超时                         │
│                                                             │
│  4. 快速恢复 (Fast Recovery)                                │
│     ├── 触发: 快速重传后                                    │
│     ├── ssthresh = cwnd / 2                                 │
│     ├── cwnd = ssthresh + 3 MSS                             │
│     └── 收到新ACK后: cwnd = ssthresh                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 慢启动详解

```python
"""
慢启动算法 (Slow Start)

目的: 快速探测网络可用带宽

算法:
1. 初始: cwnd = IW (Initial Window, 通常1-10 MSS)
2. 每收到一个ACK: cwnd = cwnd + 1 MSS
3. 效果: 每个RTT，cwnd翻倍（指数增长）

RTT 1: cwnd = 1, 发送1个包, 收到1个ACK → cwnd = 2
RTT 2: cwnd = 2, 发送2个包, 收到2个ACK → cwnd = 4
RTT 3: cwnd = 4, 发送4个包, 收到4个ACK → cwnd = 8
...

增长速度: O(2^n)
"""

def slow_start_simulation(ssthresh=64, max_rtts=10):
    """模拟慢启动过程"""
    cwnd = 1  # 初始窗口
    results = []
    
    for rtt in range(max_rtts):
        results.append({
            'rtt': rtt,
            'cwnd': cwnd,
            'phase': 'slow_start' if cwnd < ssthresh else 'congestion_avoidance'
        })
        
        if cwnd < ssthresh:
            # 慢启动: 指数增长
            cwnd *= 2
        else:
            # 拥塞避免: 线性增长
            cwnd += 1
    
    return results
```

### 2.4 拥塞避免详解

```python
"""
拥塞避免算法 (Congestion Avoidance)

目的: 缓慢增加cwnd，试探网络边界

算法:
1. 触发: cwnd >= ssthresh
2. 每收到一个ACK: cwnd = cwnd + MSS²/cwnd
   (近似为每个RTT增加1个MSS)

增长速度: O(n) 线性增长
"""

def congestion_avoidance_update(cwnd, mss=1460):
    """
    拥塞避免阶段的cwnd更新
    
    RFC公式: cwnd = cwnd + MSS * MSS / cwnd
    每个RTT: cwnd增加约1个MSS
    """
    # 收到一个ACK时的增量
    increment = mss * mss / cwnd
    return cwnd + increment
```

### 2.5 快速重传和快速恢复

```python
"""
快速重传 (Fast Retransmit)

触发: 收到3个重复ACK
原因: 重复ACK表示后续数据包到达，但某个包丢失
动作: 立即重传，不等待超时

快速恢复 (Fast Recovery)

目的: 快速重传后快速恢复发送速率
算法:
1. ssthresh = cwnd / 2
2. cwnd = ssthresh + 3 (3个重复ACK表示3个包已到达)
3. 每收到重复ACK: cwnd += 1
4. 收到新ACK: cwnd = ssthresh (退出快速恢复)
"""

def fast_recovery(current_cwnd, mss=1460):
    """
    快速恢复状态机
    """
    # 进入快速恢复
    ssthresh = current_cwnd // 2
    cwnd = ssthresh + 3 * mss  # 3个重复ACK
    
    return {
        'new_ssthresh': ssthresh,
        'new_cwnd': cwnd,
        'state': 'fast_recovery'
    }
```

## 三、算法实现详解

### 3.1 拥塞窗口估算

由于cwnd是发送方的内部状态，无法从抓包中直接获取，需要**估算**：

```python
def analyze_congestion_control(self):
    """
    分析拥塞控制
    
    挑战: cwnd是发送方内部状态，无法直接获取
    方法: 根据数据包发送模式和窗口变化进行估算
    """
    if not self.packets:
        return
    
    # 估算拥塞窗口大小
    times = []
    estimated_cwnd = []
    windows = []
    
    start_time = self.packets[0]['time']
    
    # 简化的拥塞窗口估算
    current_cwnd = 1  # 初始MSS
    ssthresh = 64     # 初始慢启动阈值
    
    data_packets_count = 0
    last_ack_time = start_time
    
    for pkt in self.packets:
        relative_time = pkt['time'] - start_time
        times.append(relative_time)
        windows.append(pkt['window'])
        
        # 基于数据包模式估算cwnd
        if pkt['length'] > 0:
            data_packets_count += 1
            
            # 检测是否收到ACK（简化判断）
            if pkt['time'] - last_ack_time > 0.1:  # 100ms间隔
                if current_cwnd < ssthresh:
                    # 慢启动阶段：指数增长
                    current_cwnd *= 2
                else:
                    # 拥塞避免阶段：线性增长
                    current_cwnd += 1
                
                last_ack_time = pkt['time']
            
            # 检测可能的超时（简化）
            if pkt['time'] - last_ack_time > 1.0:  # 超过1秒可能超时
                ssthresh = max(current_cwnd / 2, 2)
                current_cwnd = 1
        
        estimated_cwnd.append(min(current_cwnd, 100))  # 限制最大值
    
    # 判断当前阶段
    if current_cwnd < ssthresh:
        phase = "慢启动 (Slow Start)"
    else:
        phase = "拥塞避免 (Congestion Avoidance)"
    
    return {
        'times': times,
        'estimated_cwnd': estimated_cwnd,
        'windows': windows,
        'ssthresh': ssthresh,
        'phase': phase
    }
```

### 3.2 吞吐量分析

```python
def update_performance_analysis(self):
    """
    更新性能分析
    
    分析吞吐量与拥塞控制的关系
    """
    if not self.packets:
        return
    
    # 计算吞吐量随时间的变化
    time_windows = {}
    start_time = self.packets[0]['time']
    
    for pkt in self.packets:
        if pkt['length'] > 0:
            relative_time = pkt['time'] - start_time
            time_bin = int(relative_time * 10) / 10  # 100ms分辨率
            
            if time_bin not in time_windows:
                time_windows[time_bin] = {'bytes': 0, 'packets': 0}
            
            time_windows[time_bin]['bytes'] += pkt['length']
            time_windows[time_bin]['packets'] += 1
    
    # 排序并转换
    if time_windows:
        times = sorted(time_windows.keys())
        throughputs = [time_windows[t]['bytes'] * 10 / 1024 for t in times]  # KB/s
        
        # 计算移动平均
        window_size = min(10, len(throughputs))
        if len(throughputs) >= window_size:
            moving_avg = np.convolve(throughputs, 
                                     np.ones(window_size)/window_size, 
                                     mode='valid')
        
        return {
            'times': times,
            'throughputs': throughputs,
            'moving_avg': moving_avg,
            'peak': max(throughputs)
        }
```

def plot_congestion_window(self, times, estimated_cwnd, ssthresh, windows):
    """绘制拥塞窗口演化图"""
    self.cwnd_figure.clear()
    
    # 创建两个子图
    ax1 = self.cwnd_figure.add_subplot(211)
    ax2 = self.cwnd_figure.add_subplot(212)
    
    # 绘制拥塞窗口估算
    ax1.plot(times, estimated_cwnd, 'b-', linewidth=2, 
            label='估算拥塞窗口 (cwnd)')
    ax1.axhline(y=ssthresh, color='r', linestyle='--', linewidth=1.5,
               label=f'慢启动阈值 (ssthresh={ssthresh})')
    
    ax1.set_xlabel('时间 (秒)')
    ax1.set_ylabel('拥塞窗口 (MSS)')
    ax1.set_title('TCP拥塞窗口演化')
    ax1.grid(True, alpha=0.3)
    ax1.legend()
    
    # 填充慢启动阶段背景
    slow_start_region = [t for t, c in zip(times, estimated_cwnd) if c < ssthresh]
    if slow_start_region:
        ax1.axvspan(0, max(slow_start_region), alpha=0.2, color='blue',
                   label='慢启动阶段')
    
    # 绘制接收窗口
    ax2.plot(times, windows, 'g-', linewidth=2, label='接收窗口 (rwnd)')
    ax2.set_xlabel('时间 (秒)')
    ax2.set_ylabel('窗口大小 (bytes)')
    ax2.set_title('TCP接收窗口变化')
    ax2.grid(True, alpha=0.3)
    ax2.legend()
    
    self.cwnd_figure.tight_layout()
    self.cwnd_canvas.draw()

def plot_throughput(self, times, throughputs, moving_avg):

        max_idx = throughputs.index(max_throughput)

                   xy=(times[max_idx], max_throughput),
                   xytext=(times[max_idx] + 0.5, max_throughput + 5),
                   arrowprops=dict(arrowstyle='->', color='red'))
    
    self.perf_figure.tight_layout()
    self.perf_canvas.draw()

## 六、知识点总结

### 6.1 拥塞控制核心概念

| 概念 | 说明 |
|------|------|
| cwnd | 拥塞窗口，发送方维护，限制发送速率 |
| ssthresh | 慢启动阈值，区分慢启动和拥塞避免 |
| MSS | 最大段大小，cwnd的基本单位 |
| BDP | 带宽延迟积，理想的cwnd上限 |

### 6.2 四大算法对比

| 算法 | 触发条件 | cwnd变化 | 目的 |
|------|----------|----------|------|
| 慢启动 | 初始/超时后 | 指数增长 | 快速探测带宽 |
| 拥塞避免 | cwnd≥ssthresh | 线性增长 | 稳定高吞吐 |
| 快速重传 | 3个重复ACK | - | 快速恢复丢失 |
| 快速恢复 | 快速重传后 | 减半后恢复 | 快速恢复速率 |

### 6.3 丢包响应

| 丢包类型 | 响应 | 新cwnd | 新ssthresh |
|----------|------|--------|------------|
| 超时 | 重进入慢启动 | 1 MSS | cwnd/2 |
| 3重复ACK | 快速恢复 | ssthresh+3 | cwnd/2 |

### 6.4 实现关键

| 关键点 | 说明 |
|--------|------|
| cwnd估算 | 无法直接获取，需根据发送模式估算 |
| 阶段识别 | 比较cwnd和ssthresh判断阶段 |
| 吞吐量关联 | 吞吐量反映拥塞控制效果 |
| 可视化 | 图表展示窗口演化和吞吐量变化 |
