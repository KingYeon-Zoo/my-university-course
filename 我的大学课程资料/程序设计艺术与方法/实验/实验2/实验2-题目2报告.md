# 实验2-题目2报告：货币系统

**一、实验目的和要求**

本题目要求简化货币系统，找到与原系统等价的最小货币系统。

**问题定义**：
- 货币系统(n, a)：n种货币，面额数组a[1..n]
- 完善的货币系统：每个非负整数金额都可以被表示
- 等价货币系统：对于任意金额x，要么都能表示，要么都不能表示
- 目标：找到最小的m，使得(m, b)与(n, a)等价

**输入要求**：
- 第一行：整数T，表示测试组数
- 对于每组数据：
  - 第一行：正整数n，货币种数
  - 第二行：n个正整数，各货币面额

**输出要求**：
- 对于每组数据，输出最小的m值

**二、解题思路和复杂度分析**

**解题思路**：

**关键观察**：
1. 如果一个面额可以由其他面额组合得到，那么这个面额是**冗余的**
2. 只需保留那些**无法由其他面额组合得到**的面额
3. 这样得到的货币系统与原系统等价，且面额数最少

**算法步骤**：
1. **排序**：将货币面额从小到大排序
2. **逐个检查**：
   - 对于每个面额，检查它是否可以由前面已选中的面额组成
   - 如果不能组成，则这个面额是必需的，加入结果集
   - 如果能组成，则这个面额是冗余的，丢弃
3. **返回结果**：返回必需面额的个数

**为什么从小到大检查？**
- 小面额更基础，大面额可能由小面额组成
- 如果从大到小，可能错误地保留可由小面额组成的大面额

**完全背包DP**：
- 用于判断某个金额是否可以由给定面额组成
- `dp[i]`表示金额i是否可以组成
- 状态转移：`dp[i] = dp[i] OR dp[i-coin]`（对于每个coin）

**示例分析**（样例1：[3, 19, 10, 6]）：
```
排序后：[3, 6, 10, 19]

检查3：essential=[]，3不能由[]组成 → 加入essential
  essential = [3]

检查6：6能由[3]组成吗？
  dp[0]=T, dp[3]=T, dp[6]=T → 能组成 → 不加入

检查10：10能由[3]组成吗？
  dp[0]=T, dp[3]=T, dp[6]=T, dp[9]=T, dp[10]=F → 不能组成 → 加入
  essential = [3, 10]

检查19：19能由[3, 10]组成吗？
  可以：10+9=19，而9=3×3 → 能组成 → 不加入

结果：essential = [3, 10]，m = 2
```

**复杂度分析**：

**can_represent函数（完全背包）**：
- 时间复杂度：O(n × V)，其中n是已选面额数，V是目标金额
- 空间复杂度：O(V)

**find_minimum_currency_system函数**：
- 时间复杂度：O(n × ∑currencies[i])
  - 排序：O(n log n)
  - 对每个面额i，运行背包DP：O(i × |essential|)
  - 总计：O(n × max_value)
- 空间复杂度：O(max_value)

**整体算法**：
- 时间复杂度：O(n × M)，M是最大面额
- 空间复杂度：O(M)

**优化可能性**：
- 对于大面额，DP数组可能很大
- 可以优化判断逻辑，但基本思路不变

**三、解题过程（流程图/伪代码）**

**伪代码**：

```
函数 can_represent(coins, target):
    如果 coins为空 或 target <= 0:
        返回 False
    
    // 完全背包DP
    dp = [False] * (target + 1)
    dp[0] = True
    
    对于 coins中的每个coin:
        对于 i 从 coin 到 target:
            如果 dp[i - coin]:
                dp[i] = True
    
    返回 dp[target]

函数 find_minimum_currency_system(n, currencies):
    // 排序
    currencies.sort()
    
    essential = []
    
    对于 currencies中的每个current:
        // 检查current是否可以由essential组成
        如果 not can_represent(essential, current):
            // 不能组成，是必需的
            essential.append(current)
    
    返回 len(essential)

主函数:
    读取 t
    
    重复 t 次:
        读取 n
        读取 currencies数组
        
        result = find_minimum_currency_system(n, currencies)
        输出 result
```

**输入**：
```
2
4

5
11 29 13 19 17
```

**输出**：
```
2
5
```

**分析**：

**第1组：[3, 19, 10, 6]**
- 排序：[3, 6, 10, 19]
- 检查3：essential=[]，不能组成 → 加入，essential=[3]
- 检查6：能由[3]组成（3+3=6） → 不加入
- 检查10：不能由[3]组成 → 加入，essential=[3, 10]
- 检查19：能由[3, 10]组成（10+3+3+3=19） → 不加入
- 结果：m=2

**第2组：[11, 29, 13, 19, 17]**
- 排序：[11, 13, 17, 19, 29]
- 检查11：essential=[]，不能组成 → 加入，essential=[11]
- 检查13：不能由[11]组成 → 加入，essential=[11, 13]
- 检查17：不能由[11, 13]组成 → 加入，essential=[11, 13, 17]
- 检查19：不能由[11, 13, 17]组成 → 加入，essential=[11, 13, 17, 19]
- 检查29：不能由[11, 13, 17, 19]组成 → 加入，essential=[11, 13, 17, 19, 29]
- 结果：m=5

**结果正确** ✓

- 检查13：2+2+3+3+3=13 → 不加入

**算法正确性证明**：
- 如果一个面额能由其他面额组成，删除它不影响可表示的金额集合
- 如果一个面额不能由其他面额组成，删除它会导致某些金额无法表示
- 因此，保留所有不能被组成的面额，得到的就是最小等价系统

**总结**：
本题成功实现了货币系统的简化。通过动态规划判断面额的可组合性，筛选出必需的面额。算法核心是完全背包问题，思路清晰，实现简洁。该问题在实际中对应货币设计、资源配置等场景，具有实际应用价值。
