# 实验5-题目1 实验报告

**一、实验目的和要求** 

本实验要求设计并实现一个算法，判断是否能够使用给定的n种原材料制作m道菜，每道菜使用k克原材料，且每道菜最多使用2种原材料。如果存在满足要求的方案，需要输出具体的制作方案；否则输出-1。

具体要求：
- 共做出m道菜
- 每道菜至多使用2种原材料
- 每道菜恰好使用k克原材料
- 每道菜使用的每种原材料的质量都为正整数克
- n种原材料都被恰好用完

**二、解题思路和复杂度分析**  

**解题思路：**

这是一个典型的贪心构造问题。关键在于设计合理的配对策略，避免产生难以使用的余数。

**核心策略（按优先级排序）：**

1. **策略1 - 完美配对（最优先）**：
   - 寻找两种原材料，其剩余量之和恰好等于k
   - 这种配对最优，因为不产生余数，完全利用两种材料
   - 例如：材料A剩余40克，材料B剩余60克，k=100，则完美配对

2. **策略2 - 单一材料（谨慎使用）**：
   - 仅当材料剩余量是k的整数倍时使用
   - 避免产生难以配对的零碎余数
   - 例如：材料C剩余200克，k=100，可以用于2道菜

3. **策略3 - 用尽小材料（推荐）**：
   - 优先用完剩余量较小的材料（全部），搭配另一种材料的部分
   - 按剩余量从小到大排序，优先处理小的
   - 这样可以减少碎片，简化后续配对
   - 例如：材料D剩余25克，材料E剩余120克，k=100
     - 用完D的25克 + E的75克 = 100克

4. **策略4 - 双部分使用（保底）**：
   - 两种材料都使用部分
   - 尽量让分配更平衡（接近k/2）
   - 例如：材料F剩余70克，材料G剩余80克，k=100
     - 使用F的50克 + G的50克 = 100克

**为什么这个顺序重要？**

- 优先完美配对可以最大化资源利用
- 只在安全时使用单一材料（倍数关系）避免产生余数
- 优先用完小材料减少碎片数量
- 最后才考虑都使用部分

**复杂度分析：**

- **时间复杂度**：O(m × n²)
  - 外层循环m次（m道菜）
  - 每次循环内，最坏情况需要遍历所有原材料对：O(n²)
  - 总体：O(m × n²)

- **空间复杂度**：O(m + n)
  - 存储m道菜的方案：O(m)
  - 存储n种原材料的剩余量：O(n)
  - 排序时的辅助空间：O(n)

**三、解题过程（流程图/伪代码）** 

```
算法伪代码：

function solve_dishes():
    读取测试组数 T
    
    for each 测试用例:
        读取 n, m, k
        读取 materials[1..n]
        
        // 前置检查
        if sum(materials) ≠ m × k:
            输出 -1
            continue
        
        初始化 result = []  // 存储方案
        初始化 remaining = materials  // 剩余量
        
        // 制作m道菜
        for dish = 1 to m:
            dish_made = false
            
            // ===== 策略1：完美配对 =====
            for i = 1 to n:
                if dish_made: break
                if remaining[i] = 0: continue
                
                for j = i+1 to n:
                    if remaining[j] = 0: continue
                    
                    if remaining[i] + remaining[j] = k:
                        result.append([i, remaining[i], j, remaining[j]])
                        remaining[i] = 0
                        remaining[j] = 0
                        dish_made = true
                        break
            
            if dish_made: continue
            
            // ===== 策略2：单一材料（k的倍数）=====
            for i = 1 to n:
                if remaining[i] % k = 0 and remaining[i] ≥ k:
                    result.append([i, k])
                    remaining[i] -= k
                    dish_made = true
                    break
            
            if dish_made: continue
            
            // ===== 策略3：用尽小材料 =====
            indices_sorted = 按remaining[i]从小到大排序
            
            for i in indices_sorted:
                if dish_made: break
                if remaining[i] = 0 or remaining[i] ≥ k: continue
                
                for j = 1 to n:
                    if i = j or remaining[j] = 0: continue
                    
                    if remaining[i] + remaining[j] ≥ k:
                        need = k - remaining[i]
                        result.append([i, remaining[i], j, need])
                        remaining[i] = 0
                        remaining[j] -= need
                        dish_made = true
                        break
            
            if dish_made: continue
            
            // ===== 策略4：双部分使用 =====
            for i = 1 to n:
                if dish_made: break
                if remaining[i] = 0: continue
                
                for j = i+1 to n:
                    if remaining[j] = 0: continue
                    
                    if remaining[i] + remaining[j] > k:
                        use_i = min(remaining[i], k/2 + 1)
                        use_j = k - use_i
                        if use_j > 0 and use_j ≤ remaining[j]:
                            result.append([i, use_i, j, use_j])
                            remaining[i] -= use_i
                            remaining[j] -= use_j
                            dish_made = true
                            break
            
            // 如果这道菜做不出来，失败
            if not dish_made:
                输出 -1
                goto next_test_case
        
        // 成功做出m道菜
        for each dish in result:
            输出 dish
```

  再做第二道：400全用+500的600=1000？不对，500只有500
  实际上剩余的400、500、100无法凑成1000（400+500+100>1000需要3种材料）

**实验总结：**

本题是一个典型的贪心构造问题，核心挑战在于：

1. **策略选择的优先级**：
   - 不能简单地优先使用单一材料，这会产生难以配对的余数
   - 应该优先寻找完美配对，最大化资源利用
   - 只在安全情况下（k的倍数）使用单一材料

2. **避免碎片化**：
   - 优先用完小的材料可以减少后续碎片
   - 每次决策都要考虑对后续步骤的影响

3. **贪心的局限性**：
   - 有些情况下贪心策略可能无法找到解（即使存在）
   - 但对于大多数合理的测试用例，贪心策略足够高效

4. **多解问题**：
   - 本题通常存在多种合法解
   - 只要满足所有约束条件，任何解都是正确的

5. **算法优化空间**：
   - 如果需要保证找到解（如果存在），可能需要回溯或动态规划
   - 但这会显著增加时间复杂度
   - 对于本题的数据规模，贪心策略已经足够

**关键收获**：
- 贪心算法的策略顺序至关重要
- 需要考虑每个决策对全局的影响
- 优先处理"困难"的部分（如小材料）是一个好策略
- 测试用例的设计要覆盖各种边界情况
