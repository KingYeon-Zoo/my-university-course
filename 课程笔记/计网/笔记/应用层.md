### 第一部分：简单文件传送协议 (TFTP)

**位置：** 学校课件 7.5 节后半部分 1

**1. 定义与特点**

- **定义**：TFTP (Trivial File Transfer Protocol) 是一个很小且易于实现的文件传送协议 2。
    
- **传输层协议**：使用 **UDP** 数据报传输数据（注意：FTP使用的是TCP） 3。
    
- **工作模式**：客户/服务器 (C/S) 方式 4。
    
- **局限性**：
    
    - 只支持文件传输，**不支持交互** 5。
        
    - 没有庞大的命令集，**没有列目录的功能** 6。
        
    - **不能**对用户进行身份鉴别 7。
        
- **优点**：代码占用内存小，开销小，适用于UDP环境 8。
    

**2. 协议细节 (常考填空/选择)**

- **端口号**：熟知端口为 **69** 9。
    
- **数据块大小**：每次传送的数据 PDU 中有 **512字节** 的数据 10。
    
    - 若文件长度恰好是 512B 的整数倍，最后需发送一个只含首部无数据的数据 PDU 作为结束标志 11。
        
    - 若不足 512B，则该不足的数据块即为文件结束标志 12。
        
- **编号**：每个块按序编号，从 **1** 开始 13。
    
- **工作原理**：类似 **停止等待协议** 14。
    
    - 发送完一个文件块后，必须等待对方确认 15。
        
    - 规定时间内收不到确认，重发数据 PDU 16。

### 第二部分：远程终端协议 (TELNET)

**位置：** 学校课件 7.6 节 17

**1. 定义与功能**

- **定义**：一个简单的远程终端协议，是因特网正式标准 18。
    
- **功能**：用户可以在本地通过 TCP 连接注册（登录）到远地的另一个主机上（使用主机名或 IP 地址） 19。
    
- **透明性**：服务是透明的，用户感觉键盘和显示器就像直接连在远地主机上一样 20。
    

**2. 工作原理与核心概念 (重点)**

- **网络虚拟终端 (NVT)**：这是 TELNET 的核心。为了适应不同计算机和操作系统的差异（例如回车换行的定义不同），TELNET 定义了 **NVT 格式** 21。
    
    - 客户软件把用户击键转换成 NVT 格式发送 22。
        
    - 服务器软件把收到的 NVT 格式转换成远地系统所需的格式 23。
        
    - 返回数据时，服务器将数据转换为 NVT 格式，本地客户再将其转换为本地系统格式 24。

### 第三部分：简单网络管理协议 (SNMP)

**位置：** 学校课件 7.7 节 25

**1. 网络管理的五大功能 (必背)**

1. **性能管理**：收集数据、分析基线、确定性能阈值 26。
    
2. **故障管理**：检测、记录、定位故障，启用备用资源，修复故障 27。
    
3. **配置管理**：初始化对象，启动/关闭对象，定义新资源，监视资源关系 28。
    
4. **计费管理**：记录资源使用情况，核算费用，统计效益 29。
    
5. **安全管理**：控制资源访问，保证敏感信息安全，记录非法访问 30。
    

**2. SNMP 系统的组成**

- **网络管理站 (Manager)**：包含图形显示工作站和网络管理应用，负责处理数据和发出指令 31。
    
- **被管理设备**：包含 **管理代理 (Agent)**，在后台运行 32。
    
- **管理代理 (Agent)**：向管理站提供信息，接收控制信息 33。
    
- **网络管理协议**：定义信息交换的格式 34。
    
- **管理信息库 (MIB)**：被管理对象的信息集合（注：课件中提及了MIB树 35）。
    

**3. SNMP 协议细节**

- **指导思想**：尽可能简单 36。
    
- **通信方式**：C/S 方式，基于 **UDP** 373737。
    
    - **代理 (Agent)** 监听端口：**161** (用于接收查询/设置命令) 38。
        
    - **管理站 (Manager)** 监听端口：**162** (用于接收 Trap 中断信息) 39。
        
- **工作方式**：
    
    - **轮询 (Polling)**：管理程序定期向代理查询信息 40。
        
    - **中断 (Trap)**：发生异常时，代理主动向管理站发送报警 41。
        

4. 五种协议数据单元 (PDU) (重点)

SNMP v1 定义了 5 种 PDU 42：

1. **get-request**：查询一个或多个变量的值。
    
2. **get-next-request**：在 MIB 树上检索下一个变量。
    
3. **set-request**：设置一个或多个变量的值。
    
4. **get-response**：代理对 get/set 命令作出的响应。
    
5. **trap**：代理向管理进程报告发生的事件（中断）。

### 第四部分：应用进程跨越网络的通信 (Socket)

**位置：** 学校课件 7.8 节 43

**1. 基本概念**

- **系统调用 (System Call)**：应用程序和操作系统之间传递控制权的机制 44。
    
- **应用编程接口 (API)**：应用进程控制权和操作系统控制权进行转换的接口 45。
    
- **Socket 与 API 的区别**：
    
    - **Socket**：是应用进程和网络之间的接口，包含 **IP地址 + 端口号** 46。
        
    - **API**：是应用程序和操作系统之间的接口，定义了标准函数 47。
        
- **控制权**：Socket 以上由应用程序控制，Socket 以下（TCP/IP协议软件、缓存等）由操作系统控制 48。
    

**2. 常用系统调用函数 (常考匹配或简答)**

- `socket()`：创建一个 socket，返回一个整数描述符 49。
    
- `bind()`：将 socket 绑定到本地 IP 地址和端口号 50。
    
- `listen()`：(**仅服务器**) 将 socket 变为被动监听状态，准备接受连接 51。
    
- `accept()`：(**仅服务器**) 从入队列提取连接请求，**创建一个新的 socket** (接受socket) 用于通信 52。
    
- `connect()`：(**客户进程**) 向远地服务器请求建立连接 53。
    
- `recvfrom()` / `sendto()`：用于 UDP 数据报的接收和发送 54。
    
- `read()` / `write()`：通过 TCP 连接读取或发送数据 55。
    
- `close()`：关闭 socket 56。
