### **计算机体系结构（课程简介）考点目录**

#### **1. 计算机体系结构基础概念**
*   **抽象层次（Abstraction Layers）**
    *   **计算的分层模型**：应用(App) $\rightarrow$ 算法(Algorithm) $\rightarrow$ 编程语言(Language) $\rightarrow$ 系统软件(OS/Compiler) $\rightarrow$ **ISA** $\rightarrow$ **微架构(Microarch)** $\rightarrow$ 逻辑电路 $\rightarrow$ 器件。
    *   **核心定义**：
        *   **ISA (指令集体系结构)**：软件与硬件之间的接口/契约（Interface/Contract）。程序员可见的属性。
        *   **微架构 (Microarchitecture)**：ISA的具体实现方式（同一ISA可以有不同的微架构，如Intel和AMD都实现x86 ISA）。
*   **体系结构的定义**
    *   设计、选择和互连硬件组件，以及设计软硬件接口的科学与艺术。
    *   **设计目标**：功能、性能、能耗、成本等。

#### **2. 计算机的分类 (Classes of Computers)**
*需掌握各类计算机强调的关键指标（Key Metrics）*
*   **个人移动设备 (PMD)**：强调能效、价格、实时性（如手机）。
*   **桌面计算机 (Desktop)**：强调性价比（Price-performance）。
*   **服务器 (Server)**：强调可用性（Availability）、可扩展性（Scalability）、吞吐率（Throughput）。
*   **集群/数据仓库级计算机 (WSC/Cluster)**：强调可用性、性价比、SaaS应用。
*   **嵌入式计算机 (Embedded)**：强调价格（成本敏感），种类多量大。

#### **3. 计算机体系结构的八大伟大思想 (8 Great Ideas)**
*这也是后续课程贯穿的核心，务必记忆*
1.  **Design for Moore’s Law**：面向摩尔定律的设计。
2.  **Use Abstraction to Simplify Design**：利用抽象简化设计。
3.  **Make the Common Case Fast**：加速大概率事件（大概率事件优先）。
4.  **Performance via Parallelism**：通过并行提高性能。
5.  **Performance via Pipelining**：通过流水线提高性能。
6.  **Performance via Prediction**：通过预测提高性能（如分支预测）。
7.  **Hierarchy of Memories**：存储层次结构（Cache-Memory-Disk）。
8.  **Dependability via Redundancy**：通过冗余提高可靠性。


> **摩尔抽象经常快，**  
> **并行流水预测准，**  
> **存储层次冗余稳。**

- **摩尔**：Design for **Moore**’s Law（面向摩尔定律）
    
- **抽象**：Use **Abstraction**（利用抽象）
    
- **经常快**：Make the **Common Case** Fast（加速大概率/常用事件）
    
- **并行**：Performance via **Parallelism**（并行）
    
- **流水**：Performance via **Pipelining**（流水线）
    
- **预测**：Performance via **Prediction**（预测）
    
- **存储**：Hierarchy of **Memories**（存储层次）
    
- **冗余**：Dependability via **Redundancy**（冗余提高可靠性）

#### **4. 性能与功耗 (Performance, Power & Energy)**
*本章最核心的计算与分析考点*
*   **影响性能的三要素**：
    1.  半导体工艺 (Technology/PUSH)
    2.  体系结构创新 (Architecture/FEEDBACK)
    3.  应用需求 (Applications/PULL)
*   **功耗墙 (Power Wall) 与 能耗物理公式**：
    *   **动态能耗 (Dynamic Energy)**：$Energy \propto \frac{1}{2} \times C \times V^2$
    *   **动态功耗 (Dynamic Power)**：$Power \propto \frac{1}{2} \times C \times V^2 \times f$
        *   $C$: 负载电容
        *   $V$: 电压
        *   $f$: 开关频率
    *   **关键结论**：降低频率($f$)可以降低**功耗**，但不一定能降低完成任务的总**能耗**（因为时间变长了）。
*   **静态功耗 (Static Power)**：
    *   主要来源于漏电流 (Leakage Current)。
    *   随晶体管数量增加而增加，约占总功耗的25-50%。
    *   降低方法：Power Gating（电源门控）。
*   **降低功耗的技术**：
    *   DVFS (动态电压频率调整)。
    *   关闭不用的核心 (Dark Silicon)。

#### **5. 技术趋势与发展历史**
*   **摩尔定律 (Moore’s Law)**：集成电路上可容纳的晶体管数量约每18-24个月翻一番。
    *   现状：晶体管密度还在增加，但**特征尺寸 (Feature Size)** 缩小带来的线延迟 (Wire Delay) 并不随之减小，反而成为瓶颈。
*   **性能增长的驱动力演变**：
    *   早期：依靠频率提升。
    *   中期：依靠指令级并行 (ILP)。
    *   后期（当前）：由于功耗墙限制，转向**多核 (Multicore)** 和 **领域专用架构 (DSA/Accelerator)**。
*   **前沿架构 (Trends)**：
    *   TPU (Google)、NPU、WSE-2 (Cerebras, 晶圆级芯片)。
    *   趋势：从通用CPU转向异构计算和加速器（Domain-Specific Architecture）。

### 1. Design for Moore’s Law (面向摩尔定律的设计)
*   **核心含义**：芯片设计通常需要几年时间。架构师不能基于“当下”的工艺设计，而要预测芯片量产时（几年后）晶体管数量会翻倍，资源会更丰富，从而提前设计规模更大的系统。
*   **产生的具体方法/技术**：
    *   **多核处理器 (Multicore)**：既然晶体管变多了，单核又受限于功耗墙，那就把多出来的晶体管做成更多的核。
    *   **更大的缓存 (Larger Caches)**：利用充裕的晶体管增加片上缓存（L2, L3 Cache），减少访问内存的次数。
    *   **复杂的加速器 (Accelerators)**：如 PDF 中提到的 **TPU** 和 **NPU**，利用多余的晶体管做专门的矩阵运算单元。

### 2. Use Abstraction to Simplify Design (利用抽象简化设计)
*   **核心含义**：通过隐藏底层的实现细节，向高层提供简洁的接口，使得软硬件可以独立发展。
*   **产生的具体方法/技术**：
    *   **ISA (指令集体系结构)**：这是最重要的抽象。软件不需要知道底层是晶体管还是真空管，只需要针对ISA编程。
    *   **高级编程语言**：Java/C++ 抽象了汇编语言。
    *   **虚拟内存 (Virtual Memory)**：抽象了物理内存，让程序以为自己拥有连续的大内存。

### 3. Make the Common Case Fast (加速大概率事件)
*   **核心含义**：根据 Amdahl 定律，优化系统中占比最大的部分（大概率事件），能获得最高的整体性能提升。不要把资源浪费在很少发生的情况上。
*   **产生的具体方法/技术**：
    *   **Cache (缓存)**：因为程序访问数据具有局部性（大概率访问最近用过的数据），所以加个Cache能极大提升速度。
    *   **RISC (精简指令集)**：优先优化那些使用频率最高的简单指令（如Load/Store/Add），而不是复杂的生僻指令。
    *   **TLB (快表)**：加速大概率发生的虚拟地址到物理地址的转换。

### 4. Performance via Parallelism (通过并行提高性能)
*   **核心含义**：既然一个人干活慢，那就多个人同时干。
*   **产生的具体方法/技术**：
    *   **数据级并行 (DLP)**：**SIMD** 指令（单指令多数据）、**GPU**、向量处理器。
    *   **指令级并行 (ILP)**：**多发射 (Multiple Issue)**、超标量架构（一个时钟周期发多条指令）。
    *   **任务/线程级并行 (TLP)**：**多核 CPU**、**集群 (Clusters/WSC)**。

### 5. Performance via Pipelining (通过流水线提高性能)
*   **核心含义**：一种特殊的并行。像工厂流水线一样，把指令执行过程切分成多个阶段（取指、译码、执行...），让不同指令的不同阶段重叠进行。
*   **产生的具体方法/技术**：
    *   **指令流水线 (Instruction Pipelining)**：经典的5级流水线。
    *   **超流水线 (Super-pipelining)**：将流水线切得更细（如10级、20级），以提升主频。

### 6. Performance via Prediction (通过预测提高性能)
*   **核心含义**：与其傻傻等待结果出来再决定下一步做什么，不如先“猜”一个结果接着往下跑。猜对了就赚了，猜错了再撤销。
*   **产生的具体方法/技术**：
    *   **分支预测 (Branch Prediction)**：遇到 `if-else` 或循环，CPU会预测跳转方向，提前把指令取进来执行。
    *   **推测执行 (Speculative Execution)**：在不知道数据是否准备好之前，先尝试执行后续指令。
    *   **数据预取 (Data Prefetching)**：预测CPU马上要用什么数据，提前从内存拉到Cache里。

### 7. Hierarchy of Memories (存储层次结构)
*   **核心含义**：想让存储器既像硬盘一样大（便宜），又像寄存器一样快（昂贵）。物理上做不到，只能通过层次结构来“伪造”这种错觉。
*   **产生的具体方法/技术**：
    *   **金字塔结构**：寄存器 $\rightarrow$ L1 Cache $\rightarrow$ L2 Cache $\rightarrow$ L3 Cache $\rightarrow$ 主存 (DRAM) $\rightarrow$ 硬盘 (Disk)。
    *   利用**局部性原理**，将热点数据放在顶层，冷数据放在底层。

### 8. Dependability via Redundancy (通过冗余提高可靠性)
*   **核心含义**：任何物理器件都会坏。为了保证系统不出错，必须准备备份部件。
*   **产生的具体方法/技术**：
    *   **ECC 内存**：多加几位校验位，发现并纠正内存反转错误。
    * 
    *   **RAID (磁盘阵列)**：多块硬盘互为备份，坏了一块数据不丢。
    *   **冗余芯片/系统**：如 PDF 第12页提到的 **Tesla Autopilot**，使用双芯片冗余设计，一个坏了另一个顶上，确保自动驾驶安全。

---

**总结记忆法：**
在复习时，试着把这些技术反向对应回去。
*   看到 **Cache** $\rightarrow$ 想到 “加速大概率” 和 “存储层次”。
*   看到 **多核** $\rightarrow$ 想到 “摩尔定律” 和 “并行”。
*   看到 **分支预测** $\rightarrow$ 想到 “预测”。
*   看到 **RAID/ECC** $\rightarrow$ 想到 “冗余”。

#### 四、 简答题
1.  **ISA vs 微架构**：
    *   **ISA**：是软件和硬件之间的接口/契约，定义了程序员可见的指令集、寄存器等属性（有限性、确定性、可计算性）。
    *   **微架构**：是ISA的具体硬件实现。
    *   **关系**：同一个ISA可以有多种不同的微架构实现（如不同性能、不同功耗的实现）。

2.  **Transistors vs Wires**：
    *   随着特征尺寸缩小，**晶体管**性能线性增加，密度平方级增加。
    *   但是，**导线 (Wire)** 的延迟并没有随之减小（甚至相对变慢）。
    *   **挑战**：连线延迟成为性能瓶颈，限制了主频的提升。

3.  **八大思想 (选4个)**：
    *   Design for Moore’s Law
    *   Use abstraction to simplify design
    *   Make the common case fast
    *   Performance via parallelism
    *   Performance via pipelining
    *   Performance via prediction
    *   Hierarchy of memories
    *   Dependability via redundancy
    *   **Make the common case fast含义**：优先优化最常发生的情况（大概率事件），这样能获得最大的整体性能提升。

#### 五、 计算与分析题
1.  **(1) 计算**：
    $P_{new} / P_{old} = \frac{C \times (0.9)^2 \times 1.5}{C \times (1.2)^2 \times 2.0}$
    $= \frac{0.81 \times 1.5}{1.44 \times 2.0} = \frac{1.215}{2.88} \approx \mathbf{0.42}$
    **答：新功耗约为原功耗的 0.42 倍（或下降了58%）。**

    **(2) 解释**：
    能耗 $Energy = Power \times Time$。虽然降低频率 $f$ 使得功率 $P$ 下降，但处理同一个任务所需的时间 $Time$ 会成比例增加。如果是理想情况，动态能耗不变；但考虑到静态功耗（Static Power）随时间累积，总能耗甚至可能增加。

2.  **(1) 停滞原因**：
    遇到了**功耗墙 (Power Wall)**。芯片产生的热量（约130W）达到了风冷散热的物理极限，无法通过继续提高电压和频率来提升性能，否则芯片会过热烧毁。

    **(2) 创新手段**：
    转向**多核处理器 (Multicore Processors)** 和 **领域专用架构 (Domain-Specific Architecture / Accelerators)**，利用并行性来提升性能，而不是单纯依赖提升单核主频。
