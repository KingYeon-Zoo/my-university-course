### **计算机体系结构：指令级并行（ILP）I - 考点目录**

#### **一、 ILP基础理论与概念 (Page 3-11)**
1.  **基本定义**
    *   **指令级并行 (ILP)**：流水线中指令之间潜在的并行性（重叠处理）。
    *   **循环级并行 (LLP)**：循环体之间的并行性，是提升ILP的重点（程序80%的时间在循环中）。
2.  **性能度量指标**
    *   **流水线实际CPI公式**：$CPI_{流水线} = CPI_{理想} + \text{各类停顿开销}$。
    *   **CPI与IPC**：两者互为倒数关系。
3.  **相关性与流水线冒险**
    *   **区别**：相关是程序固有属性（依赖关系）；冒险是流水线具体实现导致的停顿。
    *   **程序顺序 vs 执行顺序**：为了性能可以改变执行顺序，但必须保持结果正确性。
4.  **保持正确性的两个关键属性**
    *   **保持数据流 (Data Flow)**：必须保持数据相关和控制相关，确保消费者指令拿到正确产生者的数据。
    *   **保持异常行为 (Exception Behavior)**：指令重排不能导致新的异常发生。
5.  **控制相关 (Control Dependence)**
    *   分支指令导致数据流具有动态性。
    *   **特殊场景调度**：如果能确保不改变数据流且不产生新异常（如推测执行），可以跨越分支进行调度。

#### **二、 基础指令调度技术 (Instruction Scheduling) (Page 13-21)**
1.  **编译器调度的限制条件**
    *   程序固有的ILP。
    *   流水线功能部件的延迟（Latency）。
2.  **MIPS流水线调度案例分析**
    *   **假设条件**：浮点延迟（如ADD需3周期，Load需1周期），分支延迟槽（1周期）。
    *   **未调度代码分析**：识别“空转（Stall）”周期，计算单次循环总耗时（案例中为10个周期）。
    *   **调度策略**：
        *   填充“空转”时间（将不相关的指令填入等待期）。
        *   利用**分支延迟槽**（将指令放入Branch之后执行）。
        *   调整指令顺序与偏移量（Offset）。
    *   **调度后性能**：减少空转，提升效率（案例优化至6个周期）。

#### **三、 循环展开技术 (Loop Unrolling) (Page 22-25)**
1.  **基本原理**
    *   复制循环体多次，按顺序排列。
    *   调整循环结束条件。
2.  **优化目标**
    *   **减少循环控制开销**：降低分支指令（BNE）和索引更新（DADDIU）在总指令中的占比。
    *   **扩大调度空间**：为编译器提供更多可调度的无关指令。
3.  **关键技术：寄存器重命名**
    *   在展开的循环体中，使用不同的寄存器（如F0, F6, F10...）以消除“名相关”（Name Dependence），避免资源冲突。
4.  **单纯展开（无调度）的性能**
    *   虽然减少了循环控制开销，但如果没有指令调度，流水线停顿（Stall）依然存在。

#### **四、 综合优化：循环展开 + 指令调度 (Page 26-28)**
1.  **综合应用流程**
    *   先展开循环（利用寄存器重命名）。
    *   再进行指令交叉调度（将Load、Add、Store交错排列）。
2.  **性能极限分析 (考点核心)**
    *   **计算方法**：统计展开并调度后的总周期数 / 展开次数 = 平均每个元素的耗时。
    *   **案例结果**：从原始的10周期/元素，优化至 **3.5周期/元素**。
3.  **注意事项**
    *   **正确性**：必须正确修改循环控制代码和内存偏移量。
    *   **有效性**：利用循环体间的无关性。
    *   **新相关性**：展开后要注意同一次大循环内部带来的新相关性。

### **考点一：指令级并行（ILP）基础理论**

#### **1. 什么是ILP (Instruction-Level Parallelism)**
*   **定义**：指通过硬件或软件技术，让指令流水线中的多条指令**重叠执行（Overlap）**。
*   **目标**：在单位时间内执行更多的指令，从而减少程序的执行时间。
*   **循环级并行 (Loop-Level Parallelism)**：
    *   这是ILP最主要的来源。
    *   **原理**：循环的每一次迭代（Iteration）通常是相互独立的（或者可以处理成独立的）。
    *   **重要性**：程序80%-90%的执行时间花在循环上，因此优化循环是提升整体性能的关键。

#### **2. 流水线性能公式与度量**
这是计算题的基础，务必背熟。

*   **公式**：
    $$CPI_{流水线} = CPI_{理想} + \text{停顿(Stalls)}$$
    *   **CPI (Cycles Per Instruction)**：执行一条指令所需的平均时钟周期数。
    *   **IPC (Instructions Per Cycle)**：每个时钟周期执行的指令数。
    *   **关系**：$IPC = \frac{1}{CPI}$。
*   **停顿（Stalls）的来源**：
    1.  **结构冲突 (Structural Hazard)**：硬件资源不够（如：只有一个内存端口，同时读写）。
    2.  **数据冲突 (Data Hazard)**：需要等待数据准备好（如：上一条指令还没算完，下一条就要用）。
    3.  **控制冲突 (Control Hazard)**：分支指令导致的等待（如：不知道下一条该取哪里的指令）。

> **【补充知识 - 理想CPI】**
> *   对于**单发射**流水线（Scalar），理想CPI = 1。
> *   对于**多发射**流水线（Superscalar，如4-issue），理想CPI = 0.25 (即IPC=4)。
> *   题目如果问“最大加速比”，通常就是假设停顿为0时的性能。

#### **3. 相关 (Dependence) vs 冒险 (Hazard)**
这是一个常考的**概念辨析题**。

| 概念 | 定义 | 性质 | 关系 |
| :--- | :--- | :--- | :--- |
| **相关 (Dependence)** | 程序中指令之间逻辑上的依赖关系（如：指令B用了指令A的结果）。 | **程序固有属性**。与硬件无关，只与代码逻辑有关。 | **相关 $\rightarrow$ 潜在的冒险**。<br>有相关不一定产生冒险（看硬件怎么处理）。 |
| **冒险 (Hazard)** | 流水线无法在下一个周期执行下一条指令的现象。 | **硬件实现属性**。与流水线结构、是否有Forwarding技术有关。 | **冒险 $\rightarrow$ 停顿 (Stall)**。<br>发生冒险必须暂停流水线或通过技术解决。 |

> **【补充知识 - 三种数据相关】**
> 虽然PPT这部分没细讲，但分析ILP时必须知道：
> 1.  **RAW (Read After Write)**：真数据相关（必须保持顺序）。
> 2.  **WAR (Write After Read)**：反相关（Anti-dependence），可通过寄存器重命名消除。
> 3.  **WAW (Write After Write)**：输出相关（Output dependence），可通过寄存器重命名消除。

#### **4. 程序顺序 vs 执行顺序 (关键考点)**
*   **程序顺序 (Program Order)**：源代码决定的、串行的指令排列顺序。
*   **执行顺序 (Execution Order)**：CPU实际处理指令的顺序。
*   **核心思想**：为了提高性能（ILP），我们允许**乱序执行 (Out-of-Order Execution)**，即：执行顺序 $\neq$ 程序顺序。
*   **底线（Constraint）**：不管怎么乱序，必须保证**最终结果正确**。

#### **5. 保持程序正确性的两个“金标准”**
要改变指令顺序，必须遵守以下两个条件（PPT Page 7 重点）：

**条件 A：保持数据流 (Preserving Data Flow)**
*   **含义**：数据必须从**正确的产生者 (Producer)** 流向 **正确的消费者 (Consumer)**。
*   **为什么难**：
    *   分支指令（Branch）的存在使得数据流是动态的。
    *   *例子*：
        ```assembly
        if (x > 0)
             R1 = 5  (路径A)
        else
             R1 = 10 (路径B)
        ...
        R2 = R1 + 1  (消费者)
        ```
    *   消费者 `R2` 到底用哪个 `R1`？这取决于分支的结果。因此，**保持控制相关**是保持数据流的前提。

**条件 B：保持异常行为 (Preserving Exception Behavior)**
*   **含义**：乱序执行不能导致程序发生**原本不会发生**的异常，也不能吞掉**原本应该发生**的异常。
*   **典型场景**：
    *   不能把一条可能报错的指令（如除法、内存读取）调度到分支判断之前（Speculative Execution）。
    *   *例子*：
        ```assembly
        BEQZ R2, L1    ; 如果R2是0，跳转（保护逻辑）
        LW R1, 0(R2)   ; 如果R2是0，这句会发生空指针异常
        ```
    *   如果你为了加速，强行把 `LW` 提到 `BEQZ` 前面执行，程序就会崩溃。这就是“改变了异常行为”。

#### **6. 解决控制相关的特殊场景 (PPT Page 10)**
这是一个**高级考点**，解释了为什么有时候可以跨越分支进行调度。

*   **原则**：如果我们能确定某条指令**既不影响数据流，也不会产生异常**，那么它就可以不受控制相关的束缚。
*   **PPT中的例子分析**：
    ```assembly
    BEQZ R12, Skip   ; 分支
    DSUBU R4, R5, R6 ; 被跳过的指令
    ...
    Skip: OR R7, R8, R9
    ```
*   **分析**：
    *   如果 `DSUBU`（减法）计算出的 `R4` 在 `Skip` 后面根本没人用（即：它是死代码，或者后续R4被覆盖了），那么它就不影响数据流。
    *   减法指令通常不会产生致命异常（不像除以0或内存访问）。
    *   **结论**：这种情况下，即使分支可能跳过它，我们也可以把它搬到分支前面去执行（为了填补流水线空缺）。这是**推测执行 (Speculation)** 的雏形。

### **考点二：基础指令调度技术 (Instruction Scheduling)**

#### **1. 核心原理与目标**
*   **定义**：编译器通过重新排列指令的执行顺序，将“不相关的指令”插入到“正在等待数据的指令”之间（即插入到延迟槽中）。
*   **目标**：
    1.  **隐藏延迟（Hide Latency）**：消除因数据相关导致的流水线停顿（Stall）。
    2.  **利用延迟槽（Delay Slot）**：特指分支延迟槽，避免CPU空转。
*   **前提**：调度后的代码必须保证数据流和异常行为的正确性（即上一节讲的理论基础）。

#### **2. 关键参数：流水线延迟表 (Page 14 考点)**
做题时必须严格遵守题目给定的延迟数据。本课件的假设如下（**MIPS 5段流水线**）：

| 生产者指令 (Producer)   | 消费者指令 (Consumer)   | **延迟 (Latency)** | **含义 (需要停顿几个周期)** |
| :----------------- | :----------------- | :--------------- | :---------------- |
| **浮点 Load (L.D)**  | **浮点 ALU (ADD.D)** | **1**            | 必须空 1 拍才能用数据      |
| **浮点 ALU (ADD.D)** | **浮点 ALU**         | **3**            | 必须空 3 拍才能做下一次计算   |
| **浮点 ALU (ADD.D)** | **浮点 Store (S.D)** | **2**            | 必须空 2 拍才能存数据      |
| **整数运算**           | **任何**             | **0**            | 不需要停顿（全流水）        |

> **【补充考点 - 分支延迟】**
> *   **分支延迟 (Branch Delay)**：课件设定为 **1个时钟周期**。
> *   这意味着：分支指令（BNE）后面的那一条指令（位于延迟槽中）**总是会被执行**，无论分支是否跳转。

#### **3. 经典案例分析：向量加常数 (Page 16-21)**

**源代码 (C语言)**：
```c
for (i=1; i<=1000; i++)
    x[i] = x[i] + s;
```

**未调度的汇编代码与性能分析 (In-order)**
这是“原始状态”，考试通常让你先写出这个，算算它有多慢。

*   **代码逻辑**：
    1.  `L.D F0, 0(R1)`    : 取数
    2.  `ADD.D F4, F0, F2` : 加法 (依赖F0)
    3.  `S.D F4, 0(R1)`    : 存数 (依赖F4)
    4.  `DADDIU R1, R1, -8`: 指针移动
    5.  `BNE R1, R2, Loop` : 循环判断

*   **停顿分析 (Page 18 重点)**：
    *   `L.D` 后紧跟 `ADD.D` $\rightarrow$ 产生 **1个Stall** (Load延迟)。
    *   `ADD.D` 后紧跟 `S.D` $\rightarrow$ 产生 **2个Stalls** (ALU延迟)。
    *   `BNE` 后面的延迟槽没东西放 $\rightarrow$ 产生 **1个Stall** (空转)。
    *   **总计**：5个执行周期 + 5个停顿周期 = **10个时钟周期/元素**。

---

#### **4. 优化的指令调度 (Scheduled)**
这是“进阶状态”，考试要求你画出调度后的指令序列。

**调度策略 (Page 19-20)：**
1.  **填补 Load 延迟**：`L.D` 和 `ADD.D` 之间空了1拍。
    *   *动作*：把后面的 `DADDIU R1, R1, -8`（改变指针） 提上来。
    *   *理由*：`DADDIU` 和前面的浮点操作无关，完全可以插队。
2.  **填补 分支延迟槽**：`BNE` 后面必须执行一条指令。
    *   *动作*：把 `S.D`（存数） 搬到 `BNE` 后面。
    *   *理由*：只要能处理好内存地址偏移量，存数指令在哪执行都行。
3.  **修正偏移量 (关键陷阱)**：
    *   因为我们将 `DADDIU R1, R1, -8` 提到了 `S.D` 之前执行，此时 R1 的值已经变小了8。
    *   所以，原来的 `S.D F4, 0(R1)` 必须修改为 `S.D F4, 8(R1)`，以此来抵消 R1 的变化，保证存入正确的内存地址。

**调度后的代码序列 (Page 21)：**
```assembly
Loop:
1. L.D    F0, 0(R1)      ; 取数
2. DADDIU R1, R1, -8     ; 【提前执行】更新指针，填补Load延迟
3. ADD.D  F4, F0, F2     ; 加法，现在此时F0已经准备好了(隔了1条指令)
4. (Stall)               ; 这里的停顿无法避免，因为ADD到S.D需要2个延迟，中间只隔了BNE
5. BNE    R1, R2, Loop   ; 分支
6. S.D    F4, 8(R1)      ; 【延迟槽】存数，注意偏移量从0变成了8！
```

*   **性能分析**：
    *   实际执行指令：5条。
    *   停顿：1个 (ADD.D到S.D需要2个延迟，中间只有BNE填了1个，还缺1个)。
    *   **总计**：**6个时钟周期/元素**。
    *   **提升**：从10周期降到6周期，加速比 $10/6 \approx 1.67$。

#### **5. 本考点总结与局限性 (Page 22)**
*   **结论**：通过简单的指令重排，我们显著提升了性能。
*   **存在的问题**：
    1.  **Stall未完全消除**：仍然剩下1个无法消除的停顿（ADD结果出来得太慢）。
    2.  **有效工作占比低**：在6个周期里，真正干活的只有 `L.D`, `ADD.D`, `S.D` (3条指令)。另外3个周期是 `DADDIU` (循环控制), `BNE` (循环控制) 和 Stall。
    3.  **有效利用率**：只有 50% 的时间在做浮点运算相关的工作。

这就引出了下一个考点：**如何进一步消除循环控制开销并填满流水线？ $\rightarrow$ 循环展开 (Loop Unrolling)。**

#### **💡 考试避坑指南 (必看)**

1.  **偏移量修正 (Offset Adjustment)**：
    *   这是指令调度题最容易扣分的地方。
    *   如果你把 `DADDIU R1, R1, -8` 提到了 `L.D` 或 `S.D` 之前，**务必检查**所有使用 `R1` 的指令，其偏移量是否需要 $+8$ 或 $-8$。
    *   *口诀*：指针提前减，偏移要加回；指针推后减，偏移不用动。

2.  **分支延迟槽 (Branch Delay Slot)**：
    *   题目如果没明确说“无延迟槽”，默认MIPS体系结构是有延迟槽的。
    *   调度时，放在 `BNE` 下面的指令是**属于当前循环迭代**的，不要把它当成下一次循环的指令。

3.  **计算周期数**：
    *   数清楚指令条数。
    *   严格按延迟表数停顿。
    *   别忘了加上指令本身的执行周期（通常也就是流出时间）。

4.  **WAR/WAW 冲突**：
    *   在单次循环调度中一般不明显，但在**循环展开**（下一节）中，寄存器复用会导致严重的WAR/WAW冲突，必须通过**寄存器重命名**解决。这一节暂未涉及，但要有心理准备。


### **考点三：循环展开技术 (Loop Unrolling)**

#### **1. 为什么要进行循环展开？**
在上一节的“基础调度”中，我们把每次循环的耗时从10个周期压缩到了6个周期。但还有两个痛点没解决：
1.  **有效工作比例低**：在6个周期里，真正做浮点运算（L.D, ADD.D, S.D）的只有3个周期。剩下的3个周期（DADDIU, BNE, Stall）全是**循环控制开销（Loop Overhead）**。50%的性能都浪费在“为了循环而循环”上。
2.  **调度空间有限**：只有3条有用指令，想填满流水线很难，那个剩下的1个Stall怎么也消不掉。

**解决思路**：既然循环控制太费事，那就**少做几次判断**。把循环体内部的代码复制多份，做完一批再判断。

#### **2. 核心技术：寄存器重命名 (Register Renaming)**
这是循环展开中**最关键**的步骤，也是考试常考的**填空/改错点**。

*   **问题**：如果只是简单复制粘贴代码，会导致所有指令都争抢同一个寄存器（比如都用 `F0`）。
    *   这会导致 **WAW (写后写)** 和 **WAR (读后写)** 冒险，迫使流水线停顿。
*   **解决方法**：为每一次展开的循环体分配**不同**的寄存器。
    *   *示例（PPT Page 23）*：
        *   第1次迭代：用 `F0`, `F4`
        *   第2次迭代：用 `F6`, `F8`
        *   第3次迭代：用 `F10`, `F12`
        *   第4次迭代：用 `F14`, `F16`
*   **目的**：消除“名相关”（Name Dependence），让这4组操作在逻辑上完全独立，从而可以并行执行。

#### **3. 状态一：只展开，不调度 (Page 24)**
这是中间状态，考试可能会让你计算这个状态的性能，用来和最终优化做对比。

*   **操作**：将循环展开4次，消除3次 `DADDIU` 和 `BNE`，只保留最后的一组循环控制。
*   **性能表现**：
    *   虽然减少了循环控制指令，但因为指令是挨着放的（Load 紧挨着 Add），**数据相关的停顿（Stall）依然存在**。
    *   *PPT数据*：总共耗时 **28个时钟周期**。
    *   *平均耗时*：$28 \div 4 = 7$ 个周期/元素。
    *   **结论**：比原始的10周期快，但比未展开仅调度的6周期还要慢！这说明**光展开不调度是不够的**。

---

### **考点四：终极优化——循环展开 + 指令调度**

这是本章的**最高潮**，也是考试中**满分答案**的标准写法。

#### **1. 调度策略：流水线式的交错排列 (Page 26)**
为了彻底消除停顿，编译器会将不同迭代的指令打散、交错排列。这里的逻辑非常像流水线：

*   **第一步：批量取数 (Load)**
    *   连续发射4条 `L.D` 指令。
    *   因为是不同的寄存器（F0, F6...），且内存系统通常支持流水线读取，这4条可以背靠背执行。
    *   *效果*：当第一条 `ADD.D` 需要数据时，第一条 `L.D` 早就执行完了（因为中间隔了好几条其他的L.D），**完美隐藏了Load延迟**。

*   **第二步：批量计算 (Add)**
    *   连续发射4条 `ADD.D` 指令。
    *   *效果*：同样利用指令间隔，隐藏了ALU的计算延迟。

*   **第三步：批量存数 (Store)**
    *   连续发射4条 `S.D` 指令。

*   **第四步：一次性收尾**
    *   做一次 `DADDIU`（减去32，即8字节*4）和一次 `BNE`。

#### **2. 偏移量调整 (Offset Adjustment) —— 高频考点**
在写汇编代码时，必须注意内存地址的偏移量。
由于我们一次性处理了4个元素（索引 $i, i+1, i+2, i+3$），且此时 `R1` 还没有更新，所以：
*   第1个元素偏移量：`0(R1)`
*   第2个元素偏移量：`-8(R1)`  (注意MIPS是按字节寻址，double是8字节)
*   第3个元素偏移量：`-16(R1)`
*   第4个元素偏移量：`-24(R1)`
*   最后更新R1：`DADDIU R1, R1, #-32`

#### **3. 性能极限计算 (Page 27)**
这个数字 **3.5** 必须记住，并且要会算。

*   **指令统计**：
    *   4条 Load
    *   4条 Add
    *   4条 Store
    *   1条 DADDIU
    *   1条 BNE
    *   **合计**：14条指令。
*   **停顿统计**：
    *   由于大量的交错执行，Load和Use之间、Add和Store之间的距离足够远，**所有的数据相关停顿（Stall）全部消除**。
    *   **停顿数 = 0**。
*   **最终性能**：
    *   总耗时：14个时钟周期。
    *   处理元素数：4个。
    *   **平均CPI**：$14 \div 4 = 3.5$ 周期/元素。
*   **对比**：
    *   原始代码：10周期。
    *   基础调度：6周期。
    *   展开+调度：3.5周期（**速度提升接近3倍**）。

### **💡 考试避坑指南 (必看)**

1.  **寄存器不够用怎么办？**
    *   PPT第28页提到了“注意有效性”。循环展开是用**空间换时间**（代码变长，寄存器用得多）。
    *   如果题目说“只有4个浮点寄存器可用”，你就不能展开4次（因为需要存L.D结果和S常数，寄存器不够分配）。这是这类题目的一种变体约束。

2.  **剩余元素处理 (Loop Remainder)**
    *   如果数组有 1002 个元素，展开4次（$1002 \div 4 = 250 \dots 2$），最后剩下的2个怎么办？
    *   **考点**：编译器必须生成一段**修补代码 (Clean-up code)**，用普通的慢速循环处理剩下的这2个元素。虽然PPT只是简单提了一句“假设是4的倍数”，但如果简答题问到“局限性”或“实际实现”，答出这一点会加分。

3.  **代码书写顺序**
    *   在写“展开+调度”的代码时，千万不要写成：
        `L.D`, `ADD.D`, `S.D` (第一组)
        `L.D`, `ADD.D`, `S.D` (第二组)
        ...
        这样写虽然展开了，但没调度，全是Stall，老师会直接扣分。
    *   **正确写法**：
        `L.D` ...
        `L.D` ...
        `ADD.D` ...
        `ADD.D` ...
        `S.D` ...
        `S.D` ...

4.  **别忘了 S.D 的偏移量！**
    *   很多人Load和Add写得很顺手，最后写 `S.D` 的时候，直接照抄 Load 的偏移量。
    *   一般情况下是对的（因为R1没变）。
    *   但如果你为了填补延迟槽，把 `DADDIU` 提到了最前面，那么所有的 Offset 都要修正。最稳妥的方法是：**把 DADDIU 放在指令序列的最后（BNE之前或延迟槽中），这样中间计算 Offset 比较不容易出错。**

## 三、 简答题
1.  **答**：
    因为为了提升性能（ILP），流水线需要重叠执行或乱序执行指令。
    底线原则是：必须保持**数据流（Data Flow）**，即保证数据的生产者和消费者关系不变；必须保持**异常行为（Exception Behavior）**，即改变执行顺序不能产生新的异常，也不能忽略原有的异常。

2.  **答**：
    **原理**：通过复制多次循环体并重排指令，利用不同迭代之间的无关性来填充流水线延迟。
    **消除开销**：减少了循环控制指令（如分支和索引自减）在总指令中的比例。
    **带来机会**：扩大了基本块的大小，给编译器提供了更多的指令调度空间，使其能更灵活地安排指令以隐藏延迟。

    *(注：PPT Page 18 认为是10个周期，其中包含了一个额外的分支延迟槽空转。如果按照PPT原题逻辑，BNE本身占1拍，延迟槽占1拍（空转），总共就是 5指令+1+2+1+1(分支槽空转) = 10周期。**建议按PPT Page 18 答案：10周期**)*。

### 题目 2：基本指令调度
1.  **调度策略**：将 `DADDIU` 提至 `L.D` 后填补 Load 延迟；将 `S.D` 放入分支延迟槽。
2.  **代码**：
    ```assembly
    Loop:
        L.D     F0, 0(R1)
        DADDIU  R1, R1, #-8   ; 填补Load延迟，R1变了！
        ADD.D   F4, F0, F2
        BNE     R1, R2, Loop
        S.D     F4, 8(R1)     ; 放入延迟槽，偏移量由0改为8
    ```
    *(注意：ADD.D到S.D需要2个延迟，中间隔了BNE，还缺1个延迟，仍有1个Stall)*
3.  **周期数**：
    5条指令 + 1个Stall (ADD后) = **6个周期**。

### 题目 3：循环展开 + 调度
1.  **代码序列** (参考 PPT Page 26)：
    ```assembly
    Loop:
        L.D     F0, 0(R1)
        L.D     F6, -8(R1)
        L.D     F10, -16(R1)
        L.D     F14, -24(R1)    ; 连续发射4个Load
        ADD.D   F4, F0, F2
        ADD.D   F8, F6, F2
        ADD.D   F12, F10, F2
        ADD.D   F16, F14, F2    ; 连续发射4个Add
        S.D     F4, 0(R1)
        S.D     F8, -8(R1)
        DADDIU  R1, R1, #-32    ; 更新索引
        S.D     F12, 16(R1)     ; 注意：此时R1已减32，原偏移-16变为+16
        BNE     R1, R2, Loop
        S.D     F16, 8(R1)      ; 延迟槽，原偏移-24变为+8
    ```
    *(注：偏移量修改方式不唯一，只要逻辑正确即可。例如也可以把DADDIU放在最后)*

2.  **平均周期**：
    总指令数：4(L)+4(A)+4(S)+1(D)+1(B) = 14条。
    停顿数：0 (交错执行隐藏了所有延迟)。
    平均周期 = 14 / 4 = **3.5 周期/元素**。

3.  **加速比**：
    $10 \div 3.5 \approx \mathbf{2.86}$ **倍**。
