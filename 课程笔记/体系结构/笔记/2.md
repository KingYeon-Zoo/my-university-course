## 目录

### 1. 基础性能指标 (Basic Metrics)
*   **不同角色的关注点：**
    *   **用户 (User)**：关注**响应时间 (Response Time)** / 执行时间 (Execution Time)。
        *   公式：$t_{response} = t_{end} - t_{start}$
    *   **管理者 (Manager)**：关注**吞吐率 (Throughput)**。
        *   定义：单位时间内完成的任务数量。
*   **性能的定义：**
    *   性能与执行时间成反比：$Performance = \frac{1}{Execution\_Time}$
    *   **CPU Time** vs **Wall Clock Time**：
        *   响应时间 = CPU时间 (用于运行程序) + I/O时间 (等待)。
        *   体系结构设计主要关注 **CPU Time**。
    *   **能耗 (Energy/Power)**：虽然课件重点在时间，但也提到了能耗重要性日益增加。

### 2. 性能比较 (Performance Comparison)
*   **加速比 (Speedup) 计算：**
    *   机器A比机器B快 $n$ 倍：
        $$n = \frac{Performance_A}{Performance_B} = \frac{Execution\_Time_B}{Execution\_Time_A}$$
    *   机器A比机器B快 $x\%$：
        $$\frac{Performance_A}{Performance_B} = 1 + \frac{x}{100}$$

### 3. 核心性能公式：The Iron Law (重点)
这是本章节最重要的计算部分，必须熟练掌握。

*   **CPU Time 计算公式：**
    $$\text{CPU Time} = \frac{\text{Instructions}}{\text{Program}} \times \frac{\text{Cycles}}{\text{Instruction}} \times \frac{\text{Seconds}}{\text{Cycle}}$$
    即：
    $$T = IC \times CPI \times T_{clk}$$
    *   **IC (Instruction Count)**：指令数。
    *   **CPI (Cycles Per Instruction)**：每条指令的平均时钟周期数。
    *   **Cycle Time ($T_{clk}$)**：时钟周期时间 (主频的倒数)。

*   **影响三要素的因素 (理解题)：**
    *   **指令数 (IC)**：由算法、编译器、指令集架构 (ISA) 决定。
    *   **CPI**：由 ISA、CPU 组织结构 (如流水线) 决定。
    *   **时钟周期 ($T_{clk}$)**：由硬件技术、微架构组成、电路设计决定。

*   **优化原则 (Trade-off)：**
    *   优化时必须考虑三要素的**乘积**最小化，而不仅是单项。
    *   *陷阱示例*：修改 ISA 减少了指令数，但可能导致硬件变复杂，从而增加了 CPI 或时钟周期，最终得不偿失。

### 4. 基准测试 (Benchmarks)
*   **基本概念：**
    *   使用一组公认的程序 (Workloads) 来评测性能，而非单一程序。
    *   通常选取一台**参照机器 (Reference Machine)** 进行归一化对比。
*   **常见的 Benchmark：**
    *   **SPEC CPU** (如 SPEC2000, SPEC2017)：用于测试 CPU 的整数和浮点性能。
    *   **LINPACK**：主要用于超级计算机 (TOP500) 的浮点运算测试。
*   **存在的问题：**
    *   代表性 (Representativeness)、时效性 (Too old)、"Benchmarketing" (厂商针对测试跑分优化)。

### 5. 性能数据的平均值计算 (Mean)
如何汇总多组测试数据是常见的计算考点。

*   **算术平均值 (Arithmetic Mean)**：适用于直接的时间求和，**不能**用于比率 (Ratios)。
*   **几何平均值 (Geometric Mean)**：**专门用于处理比率 (Ratios)** (如 SPEC 分数)。
    *   公式：$GM = \sqrt[n]{\prod_{i=1}^{n} ratio_i}$
    *   **特点**：结果独立于参照机器的选择；与具体执行时间不成正比。

### 6. 阿姆达尔定律 (Amdahl’s Law) (难点/计算大题)
*   **核心思想**：Make the common case fast (加速常见的操作)。
*   **加速比公式**：
    $$Speedup = \frac{\text{Old Time}}{\text{New Time}} = \frac{1}{(1-f) + \frac{f}{s}}$$
    *   $f$ (fraction)：系统中被加速部分所占的时间比例 ($0 \le f \le 1$)。
    *   $s$ (speedup)：被改进部分的加速倍数。
*   **极限情况**：
    *   当 $s \to \infty$ (某部分无限加速) 时，系统加速比的极限是 $\frac{1}{1-f}$。
    *   **意义**：系统的整体性能提升受限于**未被加速的部分** (串行瓶颈)。

## 三、 简答题
1.  **答案要点**：
    *   **公式**：$CPU \ Time = \frac{Instructions}{Program} \times CPI \times \frac{Time}{Cycle}$
    *   **原因**：三要素是相关的（Coupled）。例如，为了减少指令数（第一项）而改变ISA，可能会导致CPU硬件设计变复杂，从而增加 CPI（第二项）或 延长时钟周期（第三项）。如果后两项增加的幅度超过了指令数减少的幅度，总时间反而会变长。因此需要最小化三者的乘积。(参考 PPT P14)

2.  **答案要点**：
    *   **定义**：基准测试是一组公认的程序（workloads），用来评测性能，通常选择一个参照机器作为比较对象。(PPT P19)
    *   **问题**：
        1.  **缺乏代表性**：如测试I/O性能选了计算密集的Benchmark。
        2.  **时效性 (Too Old)**：程序太老，不再代表当前主流应用。
        3.  **Benchmarketing**：厂商针对特定Benchmark进行过度优化（作弊或trick），导致分数虚高。(PPT P28)

## 四、 计算与综合分析题

### 1. Iron Law 综合计算
**解析：**
1.  **比较速度**：
    假设指令数为 $N$。
    Time(A) = $N \times 1.5 \times 2ns = 3N (ns)$
    Time(B) = $N \times 2.5 \times 1ns = 2.5N (ns)$
    因为 Time(B) < Time(A)，所以 **机器 B 更快**。
    (加速比：$3N / 2.5N = 1.2$ 倍)

2.  **求 CPI(B)**：
    要使性能相同，即 Time(B) = Time(A) = $3N$。
    $N \times CPI_{new} \times 1ns = 3N$
    $CPI_{new} = 3.0$
    (注：这里原题问的是降低，但实际上机器B本来就快，如果还要和A一样慢，CPI其实是增加。如果题目意思是“如果A是1ns，CPI 1.5；B是2ns，CPI 1.2”那种反过来的情况，逻辑同理。根据本题数据，B要变慢才和A一样。**如果题目意图是让B更快达到某个高性能标准，逻辑也是代入公式求解**。这里按“获得相同性能”计算，结果为3.0)

3.  **优化后的加速比**：
    Old Time(A) = $3N$
    New Instr = $0.8N$
    New CPI = $1.5 \times 1.1 = 1.65$
    Cycle Time = $2ns$ (不变)
    New Time(A) = $0.8N \times 1.65 \times 2ns = 2.64N$
    Speedup = $3N / 2.64N = 1.136$
    **答：加速比约为 1.14 倍。**

### 2. Amdahl 定律应用
**解析：**
1.  **计算整体加速比**：
    $f = 0.4$ (可改进部分), $s = 5$
    Speedup = $\frac{1}{(1-0.4) + \frac{0.4}{5}} = \frac{1}{0.6 + 0.08} = \frac{1}{0.68} \approx 1.47$
    **答：整体加速比约为 1.47 倍。**

2.  **计算极限加速比**：
    当 $s \to \infty$：
    Speedup = $\frac{1}{1 - 0.4} = \frac{1}{0.6} \approx 1.67$
    **答：理论最大加速比为 1.67 倍。**

3.  **求 s 以达到 2 倍加速**：
    $2 = \frac{1}{0.6 + \frac{0.4}{s}}$
    $1.2 + \frac{0.8}{s} = 1$
    $\frac{0.8}{s} = -0.2$
    $s = -4$ (无解/物理上不可能)
    **或者直接分析**：由第 2 问可知，即使浮点部分时间为 0，最大加速比也只有 1.67 倍，无法达到 2.0 倍。
    **答：无法实现。因为根据 Amdahl 定律，即使将浮点单元加速无限倍，受限于剩余 60% 的串行部分，系统极限加速比仅为 1.67，达不到 2.0。**
