### 《计算机体系结构：多核处理器入门》考点复习目录

#### 一、 多核处理器的产生背景 (Motivation)
*   **传统性能提升方法的瓶颈** (Slide 2)
    *   流水线技术的局限（并不是越深越好）。
    *   提高时钟频率的困难（物理极限）。
*   **多核产生的核心驱动力** (Slide 3-4)
    *   **摩尔定律 (Moore's Law)**：晶体管数量增加，尺寸变小。
    *   **功耗墙 (Power Wall) —— 重中之重**：
        *   动态功耗公式：$Power = Capacitance \times Voltage^2 \times Frequency$。
        *   限制因素：无法进一步降低电压（漏电流 leakage power 增加）、散热限制（风冷极限）。
    *   **ILP (指令级并行) 的局限性**：单核挖掘指令并行的空间已非常有限。
*   **多核的优势论证** (Slide 6)
    *   对比单核超频 (+20%频率) 与双核降频 (-20%频率) 的能效比。
    *   结论：多核在功耗更低的情况下能提供更好的性能。

#### 二、 多核与多线程架构 (Architecture & SMT)
*   **基本概念**
    *   **SMP (Shared Memory Multiprocessor)**：共享存储多处理器，所有核共享单一物理地址空间 (Slide 24)。
*   **超线程/同时多线程 (Hyperthreading / SMT)** (Slide 9-11)
    *   **定义**：允许在同一物理核上同时运行多个硬件线程。
    *   **硬件资源分配** (Slide 10-11)：
        *   **复制 (Replicated)**：程序计数器 (PCs)、寄存器 (Registers)。
        *   **共享 (Shared)**：功能单元 (Functional Units)、缓存 (Caches)。
    *   **架构对比** (Slide 11)：
        *   多核 (Multicore)：$N$ 个流水线，$N$ 个宽度。
        *   多发射 (Multi-issue)：$1$ 个流水线，$N$ 个宽度。
        *   超线程 (SMT)：让单核逻辑上看起来像多核，掩盖流水线停顿 (Stall)。

#### 三、 阿姆达尔定律与性能计算 (Amdahl's Law)
*   **基本原理** (Slide 16-19)
    *   任务构成：串行部分 (Serial part) + 并行部分 (Parallel part)。
    *   随着核数增加，并行部分时间趋近于0，但**串行部分时间保持不变**。
    *   **结论**：串行部分最终将主导任务的整体执行时间（性能瓶颈）。
*   **计算公式 (必考)** (Slide 18-19)
    *   $T_{improved} = \frac{T_{affected}}{improvement\_factor} + T_{unaffected}$
    *   **陷阱示例**：即使将程序中占80%的部分性能提升无限倍，总加速比也有上限（最高5倍）。
    *   核心启示：提升系统某一部分性能，很难获得成比例的整体性能提升。

#### 四、 并行程序设计的挑战 (Parallel Programming Challenges)
*   **软件困境** (Slide 13, 20)
    *   硬件有了多核，软件性能不会自动提升，必须重写为并行程序。
*   **主要困难** (Slide 13-15)
    *   **任务划分 (Partitioning)**：如何将大任务拆解。
    *   **负载均衡 (Load Balancing)**：理想情况 vs. 实际情况（避免某些核忙死，某些核闲死）。
    *   **通信与同步 (Communication & Synchronization)**：协调开销。

#### 五、 缓存一致性问题 (Cache Coherence Problem)
*   **问题定义** (Slide 23, 25)
    *   当多个处理器（或核心）拥有独立的私有缓存 (Private Cache)，并同时缓存了同一份共享数据时，如何保证数据值的一致性。
*   **典型场景分析 (代码示例)** (Slide 25-28)
    *   场景：线程 A 和 线程 B 同时对共享变量 `x` 执行 `x = x + 1`。
    *   **竞态条件 (Race Condition)**：
        *   如果没有同步机制，两个线程可能读取旧值，导致最终结果错误（例如预期是2，实际可能是1）。
        *   Slide 28 的选择题：结果可能是 6, 8, 10 中的任意一个（取决于读写交错的时机）。
*   **解决方案关键词** (Slide 26, 29)
    *   **原子操作 (Atomic Operation)**。
    *   **同步 (Synchronization)**。
    *   **内存一致性 (Memory Consistency)**。

### 考点一：多核处理器的产生背景 (详细展开)

#### 1. 传统单核性能提升的“三板斧”及其失效 (Slide 2)
在多核出现之前，设计人员主要通过以下三种方式提升CPU性能，但它们都遇到了瓶颈：

*   **流水线技术 (Pipelining)：**
    *   **原理解释**：将指令执行过程切分成更多的小步骤（级数），从而提高时钟频率。
    *   **瓶颈 (补充点)**：**并不是流水线越深越好**。
        *   **冒险 (Hazards) 代价变大**：流水线越深，一旦发生分支预测错误（Branch Misprediction），需要冲刷（Flush）的指令就越多，造成的性能损失（Penalty）越大。
        *   **逻辑开销**：每一级流水线都需要寄存器锁存数据，级数太多会导致锁存器的延迟占比过高。
*   **提高时钟频率 (Frequency Scaling)：**
    *   **瓶颈**：物理极限。信号在芯片内部传播需要时间，频率太快导致信号来不及到达，且高频带来巨大的发热。
*   **挖掘指令级并行 (ILP, Instruction-Level Parallelism)：**
    *   **原理解释**：通过超标量（Superscalar）、乱序执行（Out-of-order）让CPU在一个周期内发射多条指令。
    *   **瓶颈 (Slide 3)**：**边际效应递减**。
        *   程序本身能并发执行的指令是有限的（数据依赖关系）。
        *   为了挖掘最后一点点ILP，硬件控制逻辑（如分支预测器、重排序缓冲区）变得极端复杂，晶体管投入产出比极低。

#### 2. 根本驱动力与物理限制 (Slides 3-5)

这是本章最重要的物理背景，必须要理解其中的逻辑链条。

*   **摩尔定律 (Moore's Law) —— 既是机会也是挑战**
    *   **内容**：集成电路上可容纳的晶体管数目约每18-24个月增加一倍。
    *   **现状**：晶体管变得更小、更多、速度更快。这给了我们大量的“晶体管预算”，但我们不能再用它们来造一个更复杂的单核（因为上述的ILP瓶颈）。

*   **功耗墙 (Power Wall) —— 核心考点 (Slide 4)**
    *   **动态功耗公式 (必背)**：
        $$P_{dynamic} = C \times V^2 \times f$$
        *   $C$：电容负载 (Capacitance)
        *   $V$：工作电压 (Voltage)
        *   $f$：开关频率 (Frequency)
    *   **问题的死结**：
        1.  为了提升性能，过去我们主要靠提升频率 $f$。
        2.  高频通常需要维持较高的电压 $V$。
        3.  公式中 $V$ 是**平方项**，电压稍有增加，功耗就会爆炸式增长。
    *   **为什么不能继续降低电压？(补充解释 Slide 4 的 Leakage Power)**
        *   虽然降低 $V$ 能显著降低功耗，但晶体管是有物理极限的。当电压过低时，晶体管无法清晰区分“0”和“1”，且会导致**漏电流 (Leakage Power/Static Power)** 大幅增加。即使CPU不工作，也在漏电发热。
    *   **散热极限 (Slide 5)**：
        *   芯片的**功率密度 (Power Density, $W/cm^2$)** 增长太快。
        *   Slide 5 的图表显示，如果不加控制，CPU表面的热流密度将超过“核反应堆”甚至“太阳表面”。风冷散热器已经无法带走这么多热量。

#### 3. 多核的合理性论证 (Slide 6) —— 为什么多核能赢？

这是一个经典的**能效比 (Performance/Watt)** 权衡分析，极易出计算理解题。

*   **对比方案 A：单核超频 (Single-Core Overclocked)**
    *   假设将频率提升 20% (Overclocked +20%)。
    *   **性能提升**：约 1.2倍 (1.2x)。
    *   **功耗代价**：惊人的 1.7倍 (1.7x)。
    *   **结论**：得不偿失，功耗增长远快于性能增长。

*   **对比方案 B：双核降频 (Dual-Core Underclocked)**
    *   假设使用两个核心，但每个核心频率降低 20% (Underclocked -20%)。
    *   **单个核心功耗**：大幅下降到约 0.51倍（因为电压和频率都降了，$V^2 f$ 效应显著）。
    *   **总功耗**：两个核加起来 $0.51 \times 2 \approx 1.02x$（几乎与原来单核持平）。
    *   **总性能**：即使单核变慢了，但两个核一起干活，理想情况下性能约为 $0.8 \times 2 = 1.6x$。
    *   **结论**：**多核架构在同等功耗下，提供了更高的吞吐量性能。**

### 补充总结（作为答题的“金句”）

如果您在考试中遇到关于“为什么转向多核”的问题，可以按以下逻辑组织语言：

1.  **技术瓶颈**：单核架构挖掘指令级并行 (ILP) 的收益已趋于饱和，且流水线深度和时钟频率已达物理极限。
2.  **物理限制 (功耗墙)**：动态功耗与电压的平方成正比 ($P \propto V^2 f$)。高频单核导致功耗和发热失控，且因漏电流限制无法通过降低电压来补偿。
3.  **解决方案**：摩尔定律提供了海量的晶体管，多核架构利用这些晶体管，通过**“人多力量大” (并行处理)** 代替 **“一个人跑得快” (高频)**。
4.  **优势**：多核可以在较低的频率和电压下运行，从而在保持总功耗可控的前提下（Slide 6 案例），显著提升系统的吞吐量性能。

### 考点二：多核与多线程架构 (详细展开)

#### 1. 宏观架构：SMP (共享存储多处理器) (Slide 24)
首先要理解多核在系统层面的组织方式。
*   **定义**：**SMP (Shared Memory Multiprocessor)**。
*   **核心特征**：
    *   **单一物理地址空间 (Single Physical Address Space)**：这是最关键的概念。无论系统中有多少个核，它们访问内存地址 `0x1000` 时，指代的都是同一个物理内存单元。
    *   **通信方式**：通过**读写共享变量**在内存中进行通信（而非显式的发送消息）。这也是后续“缓存一致性”问题产生的根源。
*   **硬件结构**：
    *   每个核通常有私有的 L1/L2 Cache。
    *   所有核共享 L3 Cache（通常情况）和主内存 (DRAM)。
    *   通过互连网络 (Interconnect/Bus) 连接。

---

#### 2. 微观架构：SMT (同时多线程) / Hyperthreading (超线程)

这是本章的技术核心（Slide 9-11）。

**A. 产生的动机 (Motivation)**
*   **问题**：现代处理器通常是“多发射”的（Multi-issue，一个周期能发射多条指令），但单个程序的指令之间存在依赖关系，很难填满所有的发射槽（Pipeline bubbles）。同时，一旦发生 **Cache Miss (缓存未命中)**，流水线会停顿数百个周期，造成巨大的资源浪费。
*   **解决思路**：与其让流水线空转，不如在停顿的时候切到另一个线程去执行。

**B. 三种多线程模式的演进 (Slide 10 图解补充)**
你需要区分三种模式，这是常见的辨析题：
1.  **粗粒度多线程 (Coarse-grained)**：只有在发生长延迟事件（如 L2 Cache Miss）时才切换线程。缺点是切换有开销，且无法掩盖短暂停顿。
2.  **细粒度多线程 (Fine-grained)**：每个时钟周期强制轮转切换线程（Cycle 1 跑线程 A，Cycle 2 跑线程 B）。缺点是如果线程 A 需要全速运行，会被强行拖慢。
3.  **同时多线程 (SMT / Simultaneous Multithreading)** —— **即 Intel 的超线程 (Hyperthreading)**：
    *   **核心**：在一个时钟周期内，同时发射来自多个线程的指令。
    *   **优势**：最大化利用了流水线的宽度，填补了所有可能的空闲槽位。

**C. SMT 的硬件实现 (Hardware Implementation) (必考点 - Slide 10-11)**
SMT 不是免费的，它是在“多核”和“单核”之间的一个折中方案。

*   **我们要复制什么？ (Replicated Resources)**
    *   **架构状态 (Architectural State)**：为了让操作系统觉得我有两个核，必须复制所有描述程序运行状态的东西。
    *   **具体包括**：**程序计数器 (PCs)**、**寄存器堆 (Registers)**、重命名表 (Renaming Tables)。
    *   *补充解释*：这两个线程必须拥有独立的上下文，不能混用寄存器。

*   **我们要共享什么？ (Shared Resources)**
    *   **执行资源**：为了省钱（晶体管），大块头的逻辑单元是共享的。
    *   **具体包括**：**功能单元 (ALU, FPU)**、**缓存 (Caches, L1/L2/L3)**、**分支预测器 (Branch Predictor)**、TLB（部分共享或分区）。

*   **SMT 的本质公式 (Slide 11)**
    *   **HT $\approx$ 多发射架构 + 额外的 PC/寄存器 - 线程间的相关性检测**
    *   *解释*：相比于制造两个完整的物理核，SMT 只需要增加约 5% 的晶体管（用于复制状态），就能带来约 20%-30% 的性能提升（利用率提升）。

#### 4. 需要补充的深度知识点 (Exams often ask "Why/What if")

为了拿高分，你需要理解以下 Slide 未详细展开但隐含的逻辑：

1.  **操作系统视角的欺骗**：
    *   开启超线程后，操作系统（OS）会看到物理核数量 $\times 2$ 的逻辑处理器。
    *   *考点*：OS 调度器需要意识到这是 SMT，否则可能会把两个计算密集型任务调度到同一个物理核的两个逻辑线程上，导致它们争抢 ALU，性能反而下降。

2.  **资源争用 (Resource Contention)**：
    *   因为 SMT 共享 Cache，如果线程 A 把 Cache 占满了（Cache Thrashing），线程 B 的性能会剧烈下降。这也是为什么有时候关闭超线程游戏性能反而更好的原因。

3.  **垂直浪费 vs. 水平浪费 (Vertical vs. Horizontal Waste)**：
    *   *这是一个非常专业的补充概念，建议掌握*。
    *   **垂直浪费**：指完全空闲的时钟周期（例如发生 Cache Miss 时整个流水线停顿）。SMT 通过切换线程解决这个问题。
    *   **水平浪费**：指在一个周期内，多发射宽度没有用满（例如 4 发射的机器只找到了 1 条指令执行）。SMT 通过在这个周期塞入另一个线程的指令来解决这个问题。

#### 总结
*   **多核** = 物理上的多个 CPU，有独立的执行单元和 L1 Cache。
*   **超线程 (SMT)** = **逻辑上的**多个 CPU，**共享**执行单元和 Cache，只**复制**了状态寄存器和 PC。
*   **目的** = 掩盖流水线停顿，榨干硬件性能。

### 考点三：阿姆达尔定律与性能计算 (Amdahl's Law)

这一部分对应课件的 **Slide 16-19**。它不仅仅是一个公式，更是理解并行计算局限性的数学基础。考试中通常会给出一个具体的场景，让你计算加速比，或者判断某个性能目标是否能够实现。

#### 1. 核心概念：任务的构成 (Slide 16)

任何一个计算机程序都可以被拆分为两部分：
1.  **串行部分 (Serial Part / $T_{unaffected}$)**：
    *   必须按顺序执行，无法利用多核加速。
    *   例如：初始化代码、依赖前一步结果的计算、单个主线程的任务分发、I/O操作等。
    *   **关键特性**：无论核数增加多少，这部分时间 **保持不变 (Remains the same)**。
2.  **并行部分 (Parallel Part / $T_{affected}$)**：
    *   可以拆分成多个片段同时在不同核上运行。
    *   例如：矩阵乘法中的各个块、图像处理中的像素点。
    *   **关键特性**：随着核数增加，这部分时间理论上 **趋近于零 (Goes to zero)**。

#### 2. 必考公式 (Slide 18)

课件中给出的是基于“执行时间”的通用形式，这个形式比单纯的加速比公式更直观，做题时推荐使用这个：

$$T_{new} = \frac{T_{affected}}{N} + T_{unaffected}$$

或者写作课件上的形式：
$$T_{improved} = \frac{T_{affected}}{improvement\_factor} + T_{unaffected}$$

*   $T_{new} / T_{improved}$：改进后的总执行时间。
*   $T_{affected}$：**可以被优化/并行化**的那部分原始时间（并行部分）。
*   $N / improvement\_factor$：改进倍数（通常指**核的数量**）。
*   $T_{unaffected}$：**不能被优化**的那部分原始时间（串行部分）。

**加速比 (Speedup) 公式**（虽然课件未直接列出，但常考）：
$$Speedup = \frac{T_{old}}{T_{new}} = \frac{1}{(1-P) + \frac{P}{N}}$$
($P$ 是并行部分占总时间的百分比)

---

#### 3. 深度分析：阿姆达尔定律的陷阱 (Slide 19)

这是最容易丢分的地方，也是**判断题**和**计算陷阱题**的高发区。

**核心结论**：系统的整体性能提升，受限于**不能被改进的那一部分 (The Unaffected Part)**。

**课件经典案例解析 (Slide 19)**：
*   **场景**：一个程序总运行时间 **100s**。其中乘法操作 (Multiply) 占用了 **80s** (这是 $T_{affected}$)，其他操作占 **20s** (这是 $T_{unaffected}$)。
*   **问题**：你需要把乘法操作的速度提升多少倍，才能让总程序的性能提升 **5倍**？
*   **计算步骤**：
    1.  **目标**：总性能提升5倍 $\rightarrow$ 目标总时间 $T_{new} = 100s / 5 = 20s$。
    2.  **列方程**：
        $$20s = \frac{80s}{n} + 20s$$
    3.  **求解**：
        $$20s - 20s = \frac{80s}{n}$$
        $$0 = \frac{80s}{n}$$
    4.  **结论**：只有当 $n \rightarrow \infty$ 时等式才成立。
*   **答案**：**Impossible! (不可能做到)**
    *   即使你把乘法操作的时间优化到 **0秒**（即性能提升无限倍），程序的总运行时间依然需要 **20s**（串行部分）。因此，总加速比永远无法超过 $100/20 = 5$ 倍。

**考试技巧**：
如果题目问“能否达到X倍加速”，先算一下 $1 / (串行比例)$。这就是理论上的最大加速比（哪怕你有无限个核）。如果目标加速比 $\ge$ 这个理论极限，直接回答“不可能”。

---

#### 4. 现实中的阿姆达尔定律 (Slide 17)

虽然理论上增加核数可以减少并行时间，但在现实中（Slide 17 的 "Real Scenario"），情况会更糟。

**补充考点：为什么现实比理论差？**
1.  **调度开销 (Overhead)**：分发任务和收集结果需要时间，核越多，这个开销越大。
2.  **通信开销**：核与核之间需要交换数据，导致总线拥堵。
3.  **负载不均衡 (Load Imbalance)**：如果要把10个任务分给8个核，必然有2个核要多干活，整个系统的完成时间取决于**最慢**的那个核。

---

#### 5. 总结记忆

*   **一句话定律**：串行部分决定了性能提升的天花板。
*   **做题策略**：
    1.  先找出哪部分是 $T_{affected}$（并行），哪部分是 $T_{unaffected}$（串行）。
    2.  套用公式 $T_{new} = T_{par}/N + T_{ser}$。
    3.  注意检查分母是否为0，判断是否存在理论极限。
好的，我们进入第四个核心考点。这一部分虽然公式不多，但在**简答题**和**概念理解题**中非常重要，因为它揭示了为什么有了多核处理器，软件速度却不会自动变快的原因。

### 考点四：并行程序设计的挑战 (Parallel Programming Challenges)

这一部分对应课件的 **Slide 13-15** 以及 **Slide 20**。

#### 1. 软硬件的断层 (The HW/SW Gap) (Slide 13, 20)

这是并行计算最基本的认知前提，常以**判断题**形式出现。

*   **问题**：拥有了多核处理器后，现有的应用程序性能会自动提升吗？
*   **答案**：**不能 (No)**。
*   **原因**：
    *   传统软件是串行的 (Sequential)，只为一个指令流设计。
    *   硬件变成了并行的 (Parallel)。
    *   **结论**：软件必须被**重写 (Rewrite)**，采用并行编程模型（如 Pthread, OpenMP, MPI）来显式地分配任务，否则它只能在一个核上跑，其他核都在围观。

#### 2. 四大核心困难 (Slide 13)

请务必背诵这四个关键词，这是描述并行编程难点的标准答案：

1.  **任务划分 (Partitioning)**：
    *   如何将一个巨大的任务拆解成 $N$ 个独立的小任务？
    *   这需要算法层面的重新设计（例如：将大矩阵拆分成小块）。
2.  **负载均衡 (Load Balancing)**：
    *   确保所有核都有事做，且工作量大致相等。
3.  **协调与同步 (Coordination & Synchronization)**：
    *   不同的核之间需要“对齐”进度（例如：所有人都做完 Step 1，才能开始 Step 2）。
    *   这涉及到锁 (Locks)、信号量 (Semaphores) 等机制。
4.  **通信开销 (Communication Overhead)**：
    *   数据在不同的核（或缓存）之间传输是需要时间的。如果通信时间 > 计算时间，并行反而会变慢。

---

#### 3. 重点深化：负载均衡 (Load Balancing) (Slide 14 vs. Slide 15)

这是课件中唯二用了图示对比的概念，考试中可能会让你**看图分析**。

**A. 理想情况 (Ideal Case - Slide 14)**
*   **图示**：所有绿色的条（任务时间）长度完全一致。
*   **含义**：将任务完美地均分给了8个核。
*   **结果**：所有核同时开始，同时结束，没有资源浪费。
*   **性能**：$T_{total} = T_{single\_task} / N$。

**B. 实际情况 (Actual Case - Slide 15)**
*   **图示**：绿色的条长短不一。有的核很快做完了，有的核还要跑很久。
*   **关键结论 (木桶效应)**：
    *   **整个系统的运行时间取决于最慢的那个核 (The slowest core determines the total execution time)。**
    *   那些早早做完任务的核，处于 **空闲/等待 (Idle/Stall)** 状态。这些空白时间就是算力的浪费。
*   **导致原因**：
    *   任务本身难以均匀拆分（有些数据处理起来更复杂）。
    *   系统干扰（OS调度、中断）。
    *   内存访问延迟的不确定性。

---

#### 4. 答题模板示例

如果题目问：**“简述开发多核并行程序的难点”** 或 **“为什么增加核数不一定能线性提升性能（除了Amdahl定律之外的原因）？”**

你可以这样回答：
1.  **软件重构成本**：旧代码需要重写以支持并行。
2.  **负载不均衡 (Load Imbalance)**：实际上很难保证所有核的工作量完全一致，整体速度受限于最慢的线程（参考 Slide 15）。
3.  **同步与通信开销**：线程间的协调（锁、屏障）和数据传输（Cache一致性流量）会消耗大量周期，甚至导致性能下降。

### 考点五：缓存一致性问题 (Cache Coherence Problem)

这一部分对应课件 **Slide 23, 25-28**。

#### 1. 问题的根源：私有缓存 (Private Caches) (Slide 23)

*   **物理架构**：在多核处理器中，为了快，每个核 (Core) 都有自己**私有的 L1/L2 Cache**。只有 L3 Cache 或主存 (Memory) 是共享的。
*   **现象**：当 Core 0 和 Core 1 都要读写同一个全局变量 `x` 时：
    1.  Core 0 会把 `x` 从内存读到自己的 L1 Cache 中。
    2.  Core 1 也会把 `x` 从内存读到自己的 L1 Cache 中。
    3.  **此时，系统中有了 3 份 `x` (内存一份，两个核的 Cache 各一份)。**
*   **冲突**：如果 Core 0 修改了自己 Cache 里的 `x`，而 Core 1 不知道，Core 1 继续用旧的 `x` 进行计算，结果就会出错。这就是**不一致 (Incoherent)**。

---

#### 2. 经典案例分析：`x = x + 1` (Slide 25-28) —— 必考场景

这是一个极具欺骗性的简单代码。

**场景设定**：
*   初始值：`x = 0` (存储在共享内存中)。
*   **Thread A (Core 0)**：循环执行 5 次 `x = x + 1`。
*   **Thread B (Core 1)**：循环执行 5 次 `x = x + 1`。
*   **预期结果**：总共加了 10 次，理论上 `x` 应该等于 **10**。

**微观指令分析 (Slide 27)**：
高级语言的一句 `x = x + 1`，在汇编层面其实是**三步走**：
1.  **LW (Load)**: 把 `x` 从内存/Cache 读入寄存器 `$t0`。
2.  **ADD (Add)**: 寄存器 `$t0` 加 1。
3.  **SW (Store)**: 把寄存器 `$t0` 的新值写回内存/Cache。

**竞态条件 (Race Condition) 演示**：
假设 Core 0 和 Core 1 同时执行第一次循环：

1.  **Core 0 执行 LW**：读取 `x`，得到 **0**。
2.  **Core 1 执行 LW**：读取 `x`，得到的也是 **0** (因为 Core 0 还没写回去)。
3.  **Core 0 执行 ADD**：计算 $0 + 1 = 1$。
4.  **Core 1 执行 ADD**：计算 $0 + 1 = 1$。
5.  **Core 0 执行 SW**：把 **1** 写回内存。
6.  **Core 1 执行 SW**：把 **1** 写回内存（覆盖了 Core 0 的写入）。

**后果**：两个核各跑了一次循环，明明加了两次，结果内存里只有 **1**。一次更新丢失了！

---

#### 3. 考试中的选择题解析 (Slide 28)

**题目**：当两个循环结束后，`x` 的值可能是多少？
*   A) 6
*   B) 8
*   C) 10
*   D) All of the above (以上都有可能)

**正确答案分析**：选 **D (All of the above)** 或者 **E (None.../Unpredictable)**，具体取决于选项设置，但核心逻辑是**“结果是不确定的”**。

*   **最好情况 (10)**：两个核完全串行执行。Core 0 跑完 5 次，`x` 变成 5；然后 Core 1 再跑 5 次，`x` 变成 10。
*   **最坏情况 (2-5)**：每次读写都发生严重的交错覆盖，丢失了大量更新。
*   **中间情况 (6, 7, 8, 9)**：部分指令交错，部分串行。

**结论**：在没有同步机制的情况下，多核并发修改共享变量，**结果是不可预测的 (Unpredictable)**。

---

#### 4. 解决方案 (Slide 26, 29)

虽然课件没有深入讲协议细节（如 MESI 协议），但提到了两个关键概念，这是解决问题的钥匙：

1.  **原子操作 (Atomic Operation)**：
    *   硬件提供特殊的指令，确保 "读-改-写" 这三个步骤是一个不可分割的整体。在执行期间，不允许其他核插入或干扰。
    *   *Slide 26 提问*：原子操作写的是哪一级存储？
    *   *答案*：虽然指令是在 CPU 执行，但原子性必须保证对**共享内存 (Shared Memory)** 视图的一致性。

2.  **同步原语 (Synchronization Primitives)** (Slide 21)：
    *   在编写软件时，使用 **锁 (Locks / Mutexes)**、**信号量** 或 **屏障 (Barriers)**。
    *   代码示例修改：
        ```c
        lock(mutex);   // 加锁
        x = x + 1;     // 进入临界区 (Critical Section)
        unlock(mutex); // 解锁
        ```

考虑课件 Slide 25-28 中提到的经典场景：
系统有两个核：Core 0 和 Core 1。
内存中有一个共享变量 `x`，初始值为 0。
两个线程分别运行在两个核上，代码如下：
```c
// Thread A (Core 0)      // Thread B (Core 1)
for(i=0; i<5; i++)        for(j=0; j<5; j++)
    x = x + 1;                x = x + 1;
```
汇编指令展开为：`LW` (Load), `ADD` (Add), `SW` (Store)。

**问题 (1)**：请描述一种具体的指令交错执行顺序（Trace），使得两个线程各执行一次 `x = x + 1` 后，内存中 `x` 的值最终为 **1** 而不是 2。请写出具体的 LW, ADD, SW 执行步骤。(6分)
**问题 (2)**：若两个循环全部执行完毕，`x` 的最终值有哪些可能性？(4分)
**问题 (3)**：为了保证结果正确（即 x=10），硬件和软件层面分别需要什么机制？(5分)

**2. 架构对比：SMT vs Multicore (15 分)**
课件 Slide 11 中对比了 Multicore, Multi-issue, 和 SMT (Hyperthreading)。
请画出或文字描述这三者在 **“流水线数量 (Num. Pipelines)”** 和 **“流水线宽度 (Pipeline Width)”** 上的区别。
并回答：为什么 Intel 的超线程技术 (HT) 被称为是“让单个核看起来像多个核”？它主要掩盖了什么类型的硬件浪费？

#### 二、 填空

#### 三、 计算
**1. Amdahl**
(1) 并行部分新时间 = 90/9 = 10s。串行部分 = 10s。总时间 = 20s。加速比 = 100/20 = **5倍**。
(2) 并行部分时间 -> 0s。串行部分 = 10s。总时间 = 10s。最大加速比 = 100/10 = **10倍**。
*解析：此题考察 Slide 19 的陷阱，即使某部分优化无限大，总性能仍受限于串行部分。*

**2. 能效**
*   **总功耗**：$0.51 \times 2 = 1.02x$ (几乎与单核持平)。
*   **总性能**：$0.8 \times 2 = 1.6x$ (性能提升显著)。
*   **简述**：单核超频导致功耗呈指数级增长(1.7x)但性能收益低；多核降频可以在保持总功耗不变(1.02x)的情况下，利用并行性获得更高的吞吐量(1.6x)，从而绕过功耗墙。

#### 四、 综合
**1. Cache Coherence**
(1) **Trace**:
   1. Core 0: LW $t0, x (读入0)
   2. Core 1: LW $t0, x (读入0，因为Core 0还没写回)
   3. Core 0: ADD $t0, 1 (t0=1)
   4. Core 1: ADD $t0, 1 (t0=1)
   5. Core 0: SW $t0, x (写入1)
   6. Core 1: SW $t0, x (写入1，覆盖了Core 0的写入) -> 最终 x=1。
(2) 2 到 10 之间的任何整数（取决于竞争激烈程度，Slide 28 选项分析）。
(3) 硬件：Cache Coherence 协议（确保各核看到一致的数据）；软件：Atomic Instructions / Locks (同步原语)。

**2. 架构对比**
*   **Multicore**: N Pipelines, 1 Width (物理上的N个核)。
*   **Multi-issue**: 1 Pipeline, N Width (单核多发射)。
*   **SMT**: 1 Pipeline, N Width (但在这一条流水线上跑N个线程)。
*   **HT解释**：逻辑上，OS看到多了PC和寄存器，认为有多个核。物理上，它共享了ALU。主要掩盖了由于 Cache Miss 或数据依赖导致的 **流水线停顿 (Stall)**，即“垂直浪费”和“水平浪费”。
