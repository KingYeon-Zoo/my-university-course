## 目录
### **考点一：冯·诺依曼模型 (Von Neumann Model)**
*   **核心概念**：
    *   **存储程序**：指令和数据均存放在有地址的存储器中。
    *   **PC (程序计数器)**：决定动态指令的处理顺序，通常指向下一条指令（PC+4）。
    *   **指令处理流程**：取指 (Fetch) $\rightarrow$ 译码 (Decode) $\rightarrow$ 读操作数 $\rightarrow$ 执行 (Execute) $\rightarrow$ 写回 (Write Output)。
*   **逻辑假定与现实**：逻辑上假设指令处理是原子的且顺序完成，但现代处理器为了性能并不严格遵守（如流水线、乱序执行）。

### **考点二：指令格式与编码 (Instruction Format)**
*   **编码长度分类**：
    *   **固定长度**（如MIPS）：32位或64位。
        *   *优*：译码简单，易于流水线实现，计算下一条PC方便。
        *   *缺*：代码密度低（空间浪费）。
    *   **可变长度**（如x86）：
        *   *优*：代码密度高。
        *   *缺*：译码逻辑极复杂。
    *   **混合型**（如MIPS16）。
*   **MIPS32 指令格式详解 (重点)**：
    1.  **R-type (寄存器型)**：`op(6) | rs(5) | rt(5) | rd(5) | shamt(5) | funct(6)`
        *   *特点*：Opcode通常为0，具体操作由`funct`决定。
    2.  **I-type (立即数/访存/分支)**：`op(6) | rs(5) | rt(5) | immediate(16)`
        *   *用途*：Load/Store, 立即数运算 (`addi`), 条件分支 (`beq`)。
    3.  **J-type (跳转型)**：`op(6) | target(26)`
        *   *用途*：无条件跳转 (`j`, `jal`)。

### **考点三：操作数模型 (Operand Models)**
*   **四种模型的对比 (必考)**：
    1.  **Memory-Only**：所有操作数直接来自内存 (`add A, B, C` $\rightarrow$ `mem[A]=mem[B]+mem[C]`)。
    2.  **Accumulator (累加器)**：隐式单寄存器 (`Load B`, `Add C`, `Store A`)。
    3.  **Stack (栈)**：隐式栈顶 (TOS) (`Push B`, `Push C`, `Add`, `Pop A`)。
    4.  **Register / Load-Store (通用寄存器)**：仅Load/Store访存，运算在寄存器间进行。
*   **性能指标排序**：
    *   **静态代码量 (Code Size)**：Memory-only < Register < Load-store (Load-store指令条数最多)。
    *   **内存流量 (Memory Traffic)**：Load-store < Register < Memory-only (Load-store访存最少)。
    *   **指令延迟 (Latency)**：Load-store < Register < Memory-only。

### **考点四：MIPS 操作数与寄存器**
*   **Load-Store 架构**：MIPS属于此类，只有`lw`/`sw`能访问内存。
*   **寄存器约定**：
    *   **$0 (zero)**：永远为0，写入无效。
    *   **$at**：汇编保留。
    *   **$v0-$v1**：返回值。
    *   **$a0-$a3**：参数。
    *   **$sp**：栈指针。
    *   **$ra**：返回地址 (由`jal`自动设置)。
*   **寻址模式**：
    *   MIPS主要使用 **偏移寻址 (Displacement)**：`lw $1, 100($2)` $\rightarrow$ `addr = $2 + 100`。
    *   其他模式（如寄存器间接）可以通过偏移量为0实现。

### **考点五：流程控制 (Control Flow)**
*   **分支条件的判断方法**：
    1.  **比较并分支 (Compare and Branch)**：MIPS采用。
        *   `beq`, `bne` (直接比较相等/不等)。
        *   `bgtz`, `bltz` (与0比较)。
        *   *优点*：不需要标志位 (Condition Codes)，减少隐式依赖。
    2.  **条件寄存器**：使用 `slt`, `slti` 将比较结果写入目标寄存器（显式依赖），再配合 `bne/beq` 使用。
*   **跳转目标的计算 (跳转范围)**：
    *   **PC-Relative (I-type)**：用于 `beq/bne`。
        *   目标 = `(PC+4) + (imm16 << 2)`。
        *   *注意*：是相对PC的偏移，且左移2位（因为指令对齐）。
    *   **Absolute (J-type)**：用于 `j/jal`。
        *   目标 = `(PC+4)[31:28] | (target26 << 2)`。
        *   *注意*：保留高4位，可视作伪绝对地址。
    *   **Indirect (Register)**：用于 `jr`。
        *   目标 = `寄存器值` (32位完整地址)。
        *   用于函数返回 (`jr $ra`) 或 动态跳转。

### **考点六：过程调用 (Procedure Call)**
*   **MIPS 机制**：
    *   **调用**：`jal address` (Jump and Link)。
        *   操作：`PC = address`; `$ra = PC + 4` (保存返回地址)。
    *   **返回**：`jr $ra` (Jump Register)。
        *   操作：`PC = $ra`。

### **考点七：数据类型**
*   **硬件视角**：数据只是比特，类型取决于操作指令（如 `add` vs `addu`）。
*   **MIPS支持**：
    *   字节(8b), 半字(16b), 字(32b)。
    *   提供 `lb`, `lbu` (零扩展), `lh`, `lhu` 等指令处理不同长度数据。
    *   **设计原则**：正交性 (Orthogonality) 和 规整性 (Regularity)。

## **考点一：冯·诺依曼模型 (Von Neumann Model)**

#### **1. 核心定义与“存储程序”概念**
*   **PPT原始内容**：
    *   它是所有当代基于指令集架构（ISA）的计算机的潜在模型。
    *   **存储程序（Stored Program）**：指令（代码）和数据均存放在**同一个**有地址的存储器（Memory）中。
    *   定义了计算，构成了算法。
*   **💡 重点补充（考试/理解关键）**：
    *   **统一编址**：冯·诺依曼结构最
    * 本质的特征是**指令和数据共享同一总线和存储空间**。这意味着CPU既要把内存里的东西当指令读出来（取指），也要把里面的东西当数据读写（访存）。
    *   **冯·诺依曼瓶颈**：由于指令和数据共用一条通道，CPU不能同时读取指令和读写数据，这成为了性能瓶颈（现代计算机通过L1 Cache分为指令缓存I-Cache和数据缓存D-Cache来在硬件层面缓解这个问题，但在逻辑模型上仍被视为统一）。

#### **2. 关键组件：程序计数器 (PC)**
*   **PPT原始内容**：
    *   PC是关键，决定了指令被动态处理的总体顺序。
    *   **PC的更新**：通常情况下，下一条指令地址 = `PC + 4`。
*   **💡 重点补充**：
    *   **为什么是 +4？**：这是因为MIPS（以及大多数RISC架构）采用**固定长度指令**，每条指令占32位（bit），即4个字节（Byte）。内存寻址通常是以字节为单位的，所以指向下一条指令需要跨过4个地址单元。
    *   **非 +4 的情况**：当遇到**分支指令**（如`beq`）且条件满足，或者**跳转指令**（如`j`, `jal`）时，PC会被修改为目标地址，而不是顺序+4，从而实现流程控制（if-else, loop, function call）。

#### **3. 处理器的逻辑循环 (The Instruction Cycle)**
*   **PPT原始内容**：处理器在逻辑上一直执行右图中的循环：
    1.  **Fetch I (取指)**：根据PC从内存取指令。
    2.  **Decode I (译码)**：分析这是什么指令，读取寄存器。
    3.  **Execute (执行)**：ALU进行计算。
    4.  **Read/Write Memory (访存)**：如果是Load/Store指令，访问内存。
    5.  **Write Output (写回)**：将结果写回寄存器。
    6.  **Next PC**：更新PC，开始下一轮。
*   **💡 重点补充（结合Slide 36的预览）**：
    *   这五个步骤对应了经典的**五级流水线**阶段：**IF** (Instruction Fetch), **ID** (Instruction Decode), **EX** (Execute), **MEM** (Memory), **WB** (Write Back)。复习时要将这个循环与后续流水线章节联系起来。

#### **4. 逻辑抽象 vs. 现代物理实现 (核心考点)**
*   **PPT原始内容**：
    *   **逻辑假定1**：指令的处理是**原子性**的（Atomic）。即一条指令完全做完，系统状态更新后，才开始做下一条。
    *   **逻辑假定2**：指令X在指令X+1开始处理之前完全完成。
    *   **现实**：**现代处理器不遵守上述两条约定！**
*   **💡 深度解析（为什么不遵守？）**：
    *   **性能（Performance）**：如果真的严格按照“取指->执行->写回”串行做完一条再做下一条，CPU大部分部件都会处于闲置状态（例如在执行ALU加法时，访存部件是闲着的）。
    *   **流水线（Pipelining）**：现代CPU像工厂流水线一样，当指令1在译码时，指令2已经在取指了。虽然**宏观上**看起来指令是顺序执行的（ISA承诺了这一点），但在**微观硬件实现**上，它们是重叠执行的。
    *   **乱序执行（Out-of-Order）**：如果指令A需要等待数据（如从内存读取慢速数据），现代CPU会先去执行指令A后面不依赖于A的指令B，只要最终结果看起来像是顺序执行的即可。
    *   **总结**：ISA（架构）提供了冯·诺依曼模型的**幻象（Illusion）**，而微架构（硬件）通过复杂的技术打破这个幻象来换取速度。

#### **5. 冯·诺依曼模型的数据流向**
*   **PPT描述**：
    *   值从指令X传递到指令Y。
    *   X将A作为输出，Y将A作为输入。
    *   Y在X之后处理。
*   **💡 补充理解**：
    *   这描述了**数据依赖（Data Dependency）**。例如：
        ```assembly
        add $t0, $s1, $s2  # X: 产生 $t0
        sub $t1, $t0, $s3  # Y: 使用 $t0
        ```
    *   在冯·诺依曼模型中，Y必须等X写回$t0$后才能读取。在后续流水线章节中，这种依赖会导致**数据冒险（Data Hazard）**，需要通过“前递/旁路（Forwarding/Bypassing）”技术来解决，而不需要真的暂停等待。

## **考点二：指令格式与编码**

#### **1. 为什么需要关注“编码长度”？(PPT Page 5)**
*   **固定长度编码 (Fixed-length Encoding)**
    *   **代表**：MIPS, RISC-V, ARM (传统模式)。
    *   **特征**：所有指令长度一样，通常是32位（4字节）或64位。
    *   **优点**：
        *   **硬件设计简单**：取指阶段（Fetch）不需要判断指令多长，直接无脑取4个字节即可；计算 `Next PC = PC + 4` 非常容易。
        *   **流水线优化**：译码阶段可以固定位置读取寄存器号，不需要等完全识别出是什么指令。
    *   **缺点**：**代码密度低 (Low Code Density)**。即使是一个简单的“返回”指令，也要占32位，浪费存储空间。
*   **可变长度编码 (Variable-length Encoding)**
    *   **代表**：x86 (Intel/AMD)。
    *   **特征**：指令长度从1字节到15+字节不等。
    *   **优点**：**代码密度高**。常用指令短，不常用指令长，节省内存。
    *   **缺点**：**译码极度复杂**。CPU必须先读第1个字节，判断是否需要读第2个，以此类推。这对高性能流水线是噩梦。
*   **💡 深度补充：为什么是32位？(回答PPT里的Why)**
    *   因为32位是一个完美的平衡点：
        1.  **操作码空间**：足够容纳基本的操作码（6位=64种）和功能码。
        2.  **寄存器寻址**：能够轻松容纳3个寄存器编号（每个5位，共15位）。
        3.  **立即数范围**：剩余的空间（16位）足够存放大多数常见的常数或偏移量（±32KB范围内）。
        4.  **硬件对齐**：2的幂次方（4字节）最适合内存总线和缓存行的读取。

#### **2. MIPS32 的三种核心格式 (PPT Page 6-11)**
MIPS为了保持硬件简单，严格限制只有3种指令格式。所有的指令（共100多条）都必须套用这3种模板之一。

##### **(1) R-type：寄存器类型 (Register)**
用于纯粹的寄存器运算（如 `add`, `sub`, `and`, `or`, `sll`）。

*   **结构**：
    `Op(6) | Rs(5) | Rt(5) | Rd(5) | Shamt(5) | Funct(6)`
*   **字段解析**：
    *   **Op (Opcode)**：操作码。**注意：对于R-type，Op永远是 000000**。
    *   **Rs (Source)**：第一个源操作数寄存器。
    *   **Rt (Target)**：第二个源操作数寄存器。
    *   **Rd (Destination)**：**目标寄存器**（存放结果）。
    *   **Shamt (Shift Amount)**：移位数。仅用于移位指令（如 `sll`），其他指令填0。
    *   **Funct (Function)**：功能码。因为Op是0，CPU通过查看这个域来区分是 `add` (32) 还是 `sub` (34) 等。
*   **💡 易错点补充**：
    *   **汇编 vs 机器码顺序**：
        *   汇编指令：`add $t0, $s1, $s2` (目标, 源1, 源2)
        *   机器编码：`op=0, rs=$s1, rt=$s2, rd=$t0`
        *   **一定要注意：机器码中目标寄存器 rd 在第三个位置，而不是第一个！**

##### **(2) I-type：立即数类型 (Immediate)**
用于涉及常数、内存访问、条件分支的指令。

*   **结构**：
    `Op(6) | Rs(5) | Rt(5) | Immediate(16)`
*   **字段解析**：
    *   **Immediate**：16位的立即数（可以是常数、偏移量）。
*   **I-type的三种不同用途 (PPT Page 9-10)**：
    1.  **运算类** (如 `addi $1, $2, 100`)：`Rt = Rs + Imm`。这里 `Imm` 是扩展到32位的有符号整数。
    2.  **访存类** (如 `lw $1, 100($2)`)：`Addr = Rs + Imm`。`Rs`是基址寄存器，`Imm`是偏移量，`Rt`是接受数据的目的寄存器。
    3.  **分支类** (如 `beq $1, $2, offset`)：`if (Rs == Rt) goto PC+4+offset`。
*   **💡 深度补充：16位够用吗？**
    *   16位有符号数的范围是 -32768 到 +32767。
    *   统计表明，程序中绝大多数（>90%）的常数和数组访问偏移量都能落在这个范围内。
    *   如果不够用怎么办？MIPS编译器会把它拆成两条指令：`lui` (加载高16位) + `ori` (或操作低16位)。

##### **(3) J-type：跳转类型 (Jump)**
用于长距离的无条件跳转（如 `j`, `jal`）。

*   **结构**：
    `Op(6) | Target(26)`
*   **目标地址计算 (重点难点)**：
    *   PPT中给出的公式：`目标地址 = (PC+4)[31:28] || target || 00`
*   **💡 详细拆解这个公式**：
    1.  **Target**：指令里只有26位。
    2.  **左移2位 (|| 00)**：因为指令在内存中是4字节对齐的，地址的最后2位永远是0。所以26位实际上代表了28位的跳转能力。因为 **MIPS 机器指令的长度是 4 字节（32 bit）**，并且 **所有指令都存放在 4 字节对齐的地址上**。
       |指令编号|地址（十六进制）|
		|0|0x00400000|
		|1|0x00400004|
		|2|0x00400008|
		|3|0x0040000C|
    3.  **补高4位**：跳转后的地址仍然需要32位。剩下的高4位从哪来？**从当前的 (PC+4) 的高4位借来**。
    4.  **后果**：这意味着 `j` 指令不能跳转到内存的任何地方，它只能在当前的 **256MB (2^28 bit)** 的内存块（Page/Block）内跳转。如果要跨越这个界限，必须使用寄存器跳转指令 `jr`。

#### **3. MIPS指令设计的“三大哲学” (贯穿考点的核心思想)**
在复习这个考点时，如果能理解背后的哲学，死记硬背就会变少：

1.  **简单源于规整 (Simplicity favors regularity)**
    *   **体现**：所有指令都是32位长；所有指令的操作码都在前6位；Rs和Rt寄存器位置在R型和I型中是固定的。这大大简化了硬件译码器的线路。
2.  **越小越快 (Smaller is faster)**
    *   **体现**：寄存器只有32个，而不是1000个。更少的寄存器意味着更短的访问距离和更快的时钟频率。
3.  **优秀的设计需要折中 (Good design demands good compromises)**
    *   **体现**：为了保持指令长度一致，不得不牺牲立即数的长度（只有16位）；为了支持长跳转，不得不采用伪绝对寻址（J-type借用PC高位）。

## **考点三：操作数模型 (Operand Models)**

#### **1. 问题背景 (Slide 15)**
假设我们要完成一个最简单的加法运算：`A = B + C`。
这涉及到3个操作数：2个源操作数（B, C）和1个目标操作数（A）。
**操作数模型**决定了这三个数存储在哪里，以及指令如何显式或隐式地指明它们。

#### **2. 四种经典模型详解 (Slide 16-19)**

我们以 `A = B + C` 的实现代码为例进行对比：

##### **(1) Memory-Only (存储器-存储器模型)**
*   **机制**：所有的操作数都直接来自内存，结果也写回内存。CPU内部没有对程序员可见的寄存器用于暂存数据。
*   **代码示例**：
    ```assembly
    add A, B, C   # Mem[A] = Mem[B] + Mem[C]
    ```
*   **特点**：
    *   指令非常紧凑（逻辑上只需1条指令）。
    *   **缺点**：CPU速度远快于内存，每次运算都要频繁访问慢速内存，导致瓶颈。早期的VAX机器支持这种模式。

##### **(2) Accumulator (累加器模型)**
*   **机制**：CPU中只有一个特殊的寄存器叫 **累加器 (ACC)**。
    *   PPT定义：**“Accumulator 就是一个具有单个元素的 Stack。”**
    *   运算时，一个源操作数隐式来自于ACC，另一个来自内存，结果写回ACC。
*   **代码示例**：
    ```assembly
    load B    # ACC = Mem[B]
    add  C    # ACC = ACC + Mem[C]  (隐式使用ACC)
    store A   # Mem[A] = ACC
    ```
*   **特点**：
    *   指令很短（只需要指定一个内存地址）。
    *   **缺点**：频繁将临时结果写回内存（因为ACC只有一个，存不下中间变量），导致总线流量大。

##### **(3) Stack (栈模型)**
*   **机制**：操作数存储在栈顶（Top of Stack, TOS）。
    *   运算指令（如 `add`）不需要指定操作数地址，**隐式**地弹出栈顶的两个元素，相加后将结果压回栈顶。
*   **代码示例**：
    ```assembly
    push B    # Stack[++TOS] = Mem[B]
    push C    # Stack[++TOS] = Mem[C]
    add       # Tmp1=Pop(), Tmp2=Pop(), Push(Tmp1+Tmp2)
    pop A     # Mem[A] = Pop()
    ```
*   **特点**：
    *   **零地址指令**：运算指令极短（如 `add` 只有一个操作码）。
    *   **应用**：Java虚拟机（JVM）和早期的HP计算器采用此模型。

##### **(4) Register / Load-Store (通用寄存器模型)**
*   **机制**：CPU包含一组通用寄存器（GPRs，如MIPS的32个）。
    *   **Load-Store架构（MIPS采用）**：**严格限制**只有 `load` 和 `store` 指令可以访问内存。所有的算术运算（`add`, `sub`）都**必须**在寄存器之间进行。
*   **代码示例** (MIPS风格)：
    ```assembly
    lw  $1, B     # $1 = Mem[B]
    lw  $2, C     # $2 = Mem[C]
    add $3, $1, $2 # $3 = $1 + $2  (全在寄存器中)
    sw  $3, A     # Mem[A] = $3
    ```
*   **特点**：
    *   指令条数最多，但每条指令最简单、执行最快。

---

#### **3. 三种模型的关键指标对比 (Slide 20 - 必考重点)**

PPT第20页给出了**Memory-only**、**Register**（通常指允许寄存器和内存混合运算的架构，如x86）、**Load-store**（MIPS）三者的排序。这是一个高频考点。

| 指标 | 排序关系 (从小到大) | 深度解析 (为什么？) |
| :--- | :--- | :--- |
| **静态代码量**<br>(Static Code Size) | **Memory-only < Register < Load-store** | **Memory-only** 完成 `A=B+C` 只需要 1 条指令，非常致密。<br>**Load-store** 需要 4 条指令（lw, lw, add, sw），代码体积最大。 |
| **数据存储器流量**<br>(Data Memory Traffic) | **Load-store < Register < Memory-only** | 这是Load-Store架构获胜的关键。<br>**Load-store** 将B和C加载到寄存器后，如果后续计算还需要用到B和C，可以直接复用寄存器，**无需再次访问内存**。<br>**Memory-only** 每次运算必须读写内存，没有“缓存”效应，流量最大。 |
| **指令处理延迟**<br>(Instruction Latency) | **Load-store < Register < Memory-only** | **Load-store** 将耗时的访存和快速的ALU计算解耦。编译器可以优化调度（例如在等待内存读取时执行其他不相关的ALU指令）。<br>**Memory-only** 指令必须等待内存读完才能算，算完必须写回，由于内存比CPU慢几百倍，导致每条指令执行时间极长。 |

---

#### **4. 为什么 MIPS 选择 Load-Store 模型？**
这是结合PPT内容和体系结构常识的补充，帮助理解：

1.  **寄存器比内存快得多**：现代CPU寄存器访问只需要1个时钟周期，而内存访问可能需要100+周期。将数据尽可能留在寄存器里能大幅提升性能。
2.  **简化硬件**：如果允许 `add` 指令访问内存（如 x86 的 `add eax, [ebx]`），那么在这个加法指令的执行过程中，如果发生**缺页中断**（Page Fault）或**缓存未命中**（Cache Miss），处理起来极其复杂。MIPS将访存专门交给 `lw/sw`，让运算指令（`add`）变得极度简单和确定。
3.  **编译器友好**：拥有大量通用寄存器（32个）让编译器更容易分配变量，减少“寄存器溢出（spilling）”到内存的情况。

    *   表达式：`A = B + C; D = A - B;`
    *   **问**：在 **Accumulator** 机器上，需要多少条指令？
    *   *思考*：
        1. `Load B`, `Add C`, `Store A` (完成第一步, ACC=A)
        2. `Sub B` (ACC = A - B = D), `Store D`

    *   **答**：**Memory-Only** 模型。因为它每一条指令都要去撞那个很慢的“内存墙”，完全没有利用寄存器来掩盖延迟。

3.  **概念辨析**：
    *   **问**：MIPS属于上述哪一种？x86属于哪一种？

## **考点四：MIPS的操作数模型与寻址模式**

#### **1. MIPS 寄存器模型 (Hardware View)**
**PPT Page 21** 明确指出 MIPS 是 Load-Store 模型，其核心资源如下：

*   **通用寄存器 (GPR, General Purpose Registers)**：
    *   **数量**：32个。
    *   **宽度**：32位 (32-bit)。
    *   **特殊硬件特性**：**0号寄存器 ($0) 永远为0**。
        *   *作用*：写入无效，读取永远返回0。
        *   *妙用*：实现了伪指令。例如 `move $1, $2` 实际上是 `add $1, $2, $0`；空操作 `nop` 实际上是 `sll $0, $0, 0`。
*   **浮点寄存器 (FPR)**：
    *   32个32位浮点寄存器。
    *   也可配对使用，作为16个64位（双精度）寄存器。
*   **专用寄存器**：
    *   **HI, LO**：用于存放乘法结果（64位，高32位在HI，低32位在LO）或除法结果（商在LO，余数在HI）。

---

#### **2. MIPS 寄存器使用约定 (Software View / ABI)**
**PPT Page 22** 非常重要。虽然硬件上除了$0和$31($ra)外，其他寄存器功能几乎一样，但为了让不同的函数能够互相调用，软件层面必须遵循一套**约定（Convention）**。

| 名称 (Name) | 编号 | 用途 (Usage) | **关键补充/考点** |
| :--- | :--- | :--- | :--- |
| **$zero** | 0 | 常数 0 | 硬件强制为0。 |
| **$at** | 1 | 汇编器临时保留 | **Assembler Temporary**。程序员不要手动使用它，它是给伪指令拆分用的（如 `blt` 拆成 `slt` + `bne` 时暂存结果）。 |
| **$v0 - $v1** | 2-3 | 函数返回值 | 存放函数的返回结果（Values）。 |
| **$a0 - $a3** | 4-7 | 函数参数 | 存放前4个参数（Arguments）。超过4个通常走栈。 |
| **$t0 - $t7** | 8-15 | **临时变量** | **Caller-saved (调用者保存)**。函数调用后，里面的值可能会被子函数改写，不可靠。 |
| **$s0 - $s7** | 16-23 | **保存变量** | **Callee-saved (被调用者保存)**。子函数必须保证用完后恢复原值，这对调用者是安全的。 |
| **$t8 - $t9** | 24-25 | 临时变量 | 同 $t0-$t7。 |
| **$k0 - $k1** | 26-27 | 操作系统保留 | **Kernel**。用于中断/异常处理，用户程序严禁触碰。 |
| **$gp** | 28 | 全局指针 | 指向静态数据区 (Static Data) 的中间，方便快速访问全局变量。 |
| **$sp** | 29 | **栈指针** | **Stack Pointer**。指向栈顶，随push/pop上下移动。 |
| **$fp** | 30 | 帧指针 | **Frame Pointer**。指向当前函数栈帧的底部，用于调试或访问局部变量。 |
| **$ra** | 31 | **返回地址** | **Return Address**。`jal` 指令会自动将 `PC+4` 存入这里。 |

*   **💡 考点提示**：考试常考 `$t` 和 `$s` 的区别。如果你写一个函数，需要使用 `$s1`，你必须先把它压栈保存，退出前恢复；但如果你用 `$t1`，则不需要保存（除非你调用了别的函数且之后还要用 `$t1`）。

---

#### **3. 寻址模式 (Addressing Modes)**

##### **(1) 理论上的寻址模式 (PPT Page 23)**
由于现代计算机使用虚拟地址（32位或64位），而指令编码空间有限（无法在指令里塞进一个完整的32位地址），因此需要“寻址模式”来计算有效地址。常见模式包括：
*   **Direct (直接)**: `Mem[Const]`
*   **Displacement (偏移)**: `Mem[Reg + Const]`
*   **Indexed (变址)**: `Mem[Reg1 + Reg2]`
*   **Memory-Indirect (内存间接)**: `Mem[Mem[Reg]]` (指针的指针)
*   **Scaled (比例变址)**: `Mem[Reg1 + Reg2 * Scale + Const]` (x86常用，用于数组访问)

##### **(2) MIPS 的选择：只有偏移寻址 (PPT Page 24)**
MIPS为了精简硬件，**只实现了一种**数据寻址模式：
*   **基址偏移寻址 (Base + Displacement)**
*   **格式**：`lw $rt, offset($rs)`
*   **计算**：`Address = $rs + Sign_Extend(offset_16bit)`

**💡 为什么只选这一种？(PPT Page 24数据支撑)**
*   **数据统计**：在VAX这种支持所有复杂寻址的机器上测试发现：
    *   偏移寻址 (Displacement) 占 **61%**。
    *   寄存器间接寻址 (Register Deferred) 占 **19%**。
    *   **合计 80%**。
*   **MIPS的应对策略**：
    *   偏移寻址直接支持。
    *   寄存器间接寻址（即访问指针 `*ptr`）可以通过 **偏移量为0** 的偏移寻址实现：`lw $1, 0($2)`。
    *   **剩下的20%怎么办？** (如 `Mem[Reg1+Reg2]`)
        *   **用多条指令组合实现**：先用 `add` 指令算出地址，再用 `lw`。
        *   RISC哲学：硬件做最常用的事（Make the common case fast），复杂的留给指令组合。

### **深度理解与扩展**

1.  **立即数寻址算是寻址模式吗？**
    *   虽然PPT主要讲访存的寻址，但在MIPS中，立即数（Immediate）本身也是一种获取操作数的方式（如 `addi $1, $2, 100`）。
2.  **PC相对寻址 (PC-relative)**
    *   这属于**流程控制**的寻址（用于分支跳转），而不是数据访问。将在下一个考点详细讨论，但在脑海中要区分开：
        *   `lw/sw` 用的是 **Base + Offset**。
        *   `beq/bne` 用的是 **PC + Offset**。
3.  **对齐要求 (Alignment)**
    *   PPT中虽未重墨，但MIPS作为一个严格的架构，`lw` 访问字（Word）地址必须是 **4的倍数**，`lh` 必须是 **2的倍数**。否则会触发异常（Exception）。这也是硬件简化的体现。

### **复习自测题**

1.  **寄存器约定**：如果我在汇编程序中写 `li $0, 100`（试图把100加载到$0），执行后 `$0` 的值是多少？
    *   **答**：仍然是 0。硬件直接忽略写入。
2.  **寻址转换**：MIPS 如何模拟 x86 的 Indexed 寻址 `MOV EAX, [EBX + ECX]`（访问基址+变址）？
    *   **答**：需要两条MIPS指令：
        ```assembly
        add $t0, $s1, $s2  # $t0 = base($s1) + index($s2)
        lw  $v0, 0($t0)    # load from $t0
        ```
3.  **ABI理解**：为什么汇编器需要一个保留寄存器 `$at`？
    *   **答**：因为MIPS只有16位立即数。如果程序员写 `lw $1, 0x12345678($2)`（32位偏移量），这在机器码中是不可能的一条指令。汇编器必须把它拆成：
        ```assembly
        lui $at, 0x1234      # 加载高位到 $at
        ori $at, $at, 0x5678 # 加载低位
        add $at, $at, $2     # 加上基地址
        lw  $1, 0($at)       # 加载
        ```
        如果没有 `$at` 供汇编器随意折腾，它就必须破坏用户的通用寄存器，这很危险。
这是为您详细解析并深度补充的第五个考点：**流程控制 (Control Flow)**。

这一考点探讨计算机如何改变指令的执行顺序（即修改PC的值），以实现 `if-else`、`for/while` 循环和函数调用。MIPS在这里的设计非常独特，为了保持流水线的高效，它做出了一些著名的“折中”。

## **考点五：流程控制 (Control Flow)**

#### **1. 核心问题之一：如何测试分支条件？(How to decide?)**

PPT (Page 29) 提出了三种实现策略，MIPS 采用了混合策略。

*   **策略对比**：
    1.  **比较并分支 (Compare and Branch)**：
        *   一条指令完成“比较”和“跳转”。
        *   *缺点*：如果比较很复杂（如检查 `A < B`），ALU需要做一次完整的减法运算，如果还要计算跳转地址，会拉长时钟周期，或者需要太多的硬件资源。
    2.  **隐式条件码 (Condition Codes, CC)**：
        *   ALU运算（如 `sub`）自动设置标志位（Zero, Negative, Overflow）。分支指令（如 `bz`）只检查标志位。
        *   *代表*：x86, ARM。
        *   *缺点*：**隐式依赖**。指令B依赖指令A产生的标志位，这让乱序执行和流水线调度变得复杂（即使指令A和B看起来没关系，也必须按序更新标志位）。
    3.  **条件寄存器 (Condition Registers)**：
        *   先用一条指令比较，结果写入通用寄存器（0或1）；再用分支指令检查该寄存器。
        *   *代表*：MIPS (部分采用)。
        *   *优点*：**显式依赖**，编译器和硬件都容易处理。

*   **MIPS 的选择 (PPT Page 30 - 必考设计哲学)**：
    *   **对于“相等/不等”**：使用 **策略1**。
        *   指令：`beq $s1, $s2, label` (Branch if Equal), `bne`。
        *   *原因*：判断两个数是否相等（XOR操作）非常快，不需要进位链，可以在译码阶段快速完成，不会拖慢时钟频率。
    *   **对于“小于/大于”**：使用 **策略3**。
        *   指令：组合拳。先用 `slt` (Set on Less Than)，再用 `bne`。
        *   *例子*：`if ($s1 < $s2) goto L`
            ```assembly
            slt  $t0, $s1, $s2   # 如果 $s1 < $s2，则 $t0 = 1，否则 = 0
            bne  $t0, $0, L      # 如果 $t0 != 0 (即条件成立)，跳转
            ```
        *   *原因*：Slide 31的数据显示，**>86%** 的分支只是简单的相等比较或与0比较。MIPS选择让常用的（==, !=）最快（1条指令），让不常用的（<, >）稍微慢点（2条指令），从而换取硬件设计的简化。

---

#### **2. 核心问题之二：跳多远？(How far / Where to go?)**

PPT (Page 32-33) 详细讲解了目标地址的计算方式，这是计算题的高发区。

##### **(1) PC-Relative (PC相对寻址) —— 用于条件分支 (beq/bne)**
*   **指令格式**：I-type (`Op | Rs | Rt | Immediate(16)`)
*   **计算公式**：
    $$Target = (PC + 4) + (SignExtend(Immediate) \times 4)$$
*   **💡 深度解析细节**：
    *   **为什么要 PC+4？**：硬件执行这条指令时，PC已经自增指向下一条了。
    *   **为什么要左移2位 (x4)？**：因为指令是字对齐的（4字节），最后两位永远是0。省略这两位，可以让16位的立即数表示更大的范围。
    *   **跳转范围**：$\pm 2^{15}$ 个字 = $\pm 2^{17}$ 字节 = **$\pm 128KB$**。
    *   *意义*：这对于 `if-else` 和短小的 `for` 循环足够了。

##### **(2) Pseudo-Direct (伪直接寻址) —— 用于无条件跳转 (j, jal)**
*   **指令格式**：J-type (`Op | Target(26)`)
*   **计算公式**：
    $$Target = (PC + 4)[31:28]\ \|\ (Target \times 4)$$
*   **💡 深度解析细节**：
    *   **取高4位**：跳转目标必须和当前的 `PC+4` 在同一个 256MB ($2^{28}$字节) 的区域内。
    *   **局限性**：如果程序跨越了 256MB 的边界，`j` 指令无法跳转过去。这时候链接器（Linker）会报错，或者需要改用 `jr` 指令。

##### **(3) Register Indirect (寄存器间接寻址) —— 用于远跳/返回 (jr)**
*   **指令格式**：R-type
*   **计算公式**：$Target = \$rs$
*   **用途**：
    *   函数返回 (`jr $ra`)。
    *   指针函数调用（虚函数表）。
    *   跨越 256MB 限制的长跳转。


---

### **深度总结：MIPS 分支设计的权衡**

*   **Question**: 为什么不像 x86 那样搞一个 `blt label` (Branch if Less Than) 指令？
*   **Answer**:
    1.  **硬件时钟**：`blt` 需要先做减法（慢），再决定是否跳转。如果还要在一个时钟周期内算出跳转地址，会显著拉长关键路径（Critical Path），导致整个CPU的主频降低。
    2.  **指令流水线**：将“比较”和“分支”拆开，可以让 `slt` 在执行段（EX）完成，结果写入寄存器；后续的 `bne` 在译码段（ID）读取寄存器值并判断，这更有利于流水线设计（Branch Resolution 甚至可以提前）。

        1.  PC+4 = `0x00001004`
        2.  Offset = 2, 左移2位 = 8 (字节)
        3.  Target = `0x00001004` + 8 = `0x0000100C`。
    *   *注意*：如果题目给的机器码中的立即数是负数（如 `0xFFFE` = -2），记得符号扩展后再计算。

2.  **编码题**：
    *   如何翻译 C 语言代码：`if (i <= j) f = g + h; else f = g - h;` (假设 i,j,f,g,h 对应 $s0-$s4)
    *   *思路*：
        ```assembly
             slt $t0, $s1, $s0  # 检查 j < i ? (即 i > j ?)
             bne $t0, $0, Else  # 如果 j < i (即 !(i<=j))，跳转到 Else
             add $s2, $s3, $s4  # f = g + h
             j Exit
        Else: sub $s2, $s3, $s4 # f = g - h
        Exit: ...
        ```
        *(注意逻辑反转：为了跳过if块，通常检测“反条件”)*

3.  **概念题**：
    *   为什么 MIPS 的分支指令需要左移2位？
    *   *答*：为了扩大跳转范围，且指令地址必须是字对齐的（最后2位必然为0）。


这是为您详细解析并深度补充的第六个考点：**过程调用 (Procedure Call)**。

在计算机体系结构中，支持函数（过程）调用是ISA必须具备的核心能力。这不仅涉及到指令跳转，更涉及到**状态保存与恢复**。MIPS在这里的设计非常经典，体现了“硬件提供机制，软件定义策略”的分层思想。

## **考点六：过程调用 (Procedure Call)**

#### **1. 核心机制：如何“去”和“回”？(Slide 34)**

普通的跳转（如 `j`）只能“去”，不能自动“回”。过程调用的核心在于：**必须记住调用发生时的位置，以便函数执行完后能跳回来。**

*   **硬件支持：Jump and Link (跳转并链接)**
    *   **指令**：`jal Target`
    *   **操作**：
        1.  **Jump**: `PC = Target` (去哪里)
        2.  **Link**: `$ra = PC + 4` (记住回家的路)
    *   **关键点**：MIPS硬件强制使用 **$31 ($ra)** 寄存器来保存返回地址。

*   **硬件支持：Return (返回)**
    *   **指令**：`jr $ra` (Jump Register)
    *   **操作**：`PC = $ra`
    *   **类型**：这是 R-type 指令，因为它跳转的目标存储在寄存器中。

---

#### **2. 进阶机制：嵌套调用与栈 (The Stack)**

**这是考试中最容易出大题的地方。**

*   **问题场景**：
    *   如果函数 `Main` 调用了函数 `A`，`A` 又调用了函数 `B`（非叶子过程）。
    *   执行流程：
        1. `Main` 执行 `jal A` $\rightarrow$ `$ra` 被修改为 `Main` 的地址。
        2. `A` 执行 `jal B` $\rightarrow$ **灾难发生！** `$ra` 被覆盖为 `A` 里的地址。`Main` 的返回地址丢失了。
        3. `B` 返回 $\rightarrow$ 回到 `A`。
        4. `A` 试图返回 $\rightarrow$ `jr $ra` 跳回了 `A` 自己刚才的位置（死循环），永远回不到 `Main`。

*   **解决方案：栈 (Stack)**
    *   寄存器 `$ra` 只有一个，无法容纳多层调用的历史记录。
    *   **规则**：任何函数，如果它还要调用别的函数，就必须先把当前的 `$ra` 值 **压入栈 (Push)** 保存，等别的函数返回后，再从栈中 **弹出 (Pop)** 恢复 `$ra`。

*   **栈指针 ($sp)**：
    *   MIPS的栈从高地址向低地址增长。
    *   **压栈**：`addi $sp, $sp, -4` 然后 `sw $ra, 0($sp)`。
    *   **出栈**：`lw $ra, 0($sp)` 然后 `addi $sp, $sp, 4`。

---

#### **3. 保存现场：Caller vs. Callee Saved (ABI 约定)**

除了 `$ra`，函数调用还会使用其他寄存器（如 `$s0`, `$t0`）。为了不互相打架，必须遵守约定（结合考点四的寄存器表格）：

*   **Caller-Saved (调用者保存)**：`$t0-$t9`, `$a0-$a3`, `$v0-$v1`
    *   *含义*：如果不保存，调用完别的函数回来，这些寄存器的值可能就变了（被子函数随意改写了）。
    *   *策略*：如果你（调用者）在调用后还需要用到这些值，**你自己负责**在调用前压栈，调用后恢复。

*   **Callee-Saved (被调用者保存)**：`$s0-$s7`, `$ra`, `$sp`, `$fp`
    *   *含义*：子函数承诺：虽然我可以用这些寄存器，但我保证在返回前把它们恢复原样。
    *   *策略*：如果你（子函数）想用 `$s0`，你必须先把它压栈，用完后恢复。这对调用者是透明安全的。

---

#### **4. 动态调用 (Dynamic Linking / Function Pointers)**

PPT Slide 34 提到了 **`jalr $rd, $rs`** 指令。

*   **场景**：C语言中的函数指针（Function Pointer），或者C++中的虚函数（Virtual Function）。此时编译时不知道要跳到哪里，地址算不出来。
*   **操作**：
    *   `$rd = PC + 4` (默认存入 `$ra`)：保存返回地址。
    *   `PC = $rs`：跳转到 `$rs` 寄存器指向的动态地址。
*   **区别**：
    *   `jal` 是跳到一个立即数地址（J-type）。
    *   `jalr` 是跳到一个寄存器地址（R-type）。

---

### **深度示例：汇编代码分析**

假设 C 代码如下：
```c
int leaf_example(int g, int h, int i, int j) {
    int f;
    f = (g + h) - (i + j);
    return f;
}
```

对应的 MIPS 汇编（**叶子过程 - 不需要动栈**）：
```assembly
leaf_example:
    # 参数 g,h,i,j 在 $a0, $a1, $a2, $a3
    add $t0, $a0, $a1  # $t0 = g + h
    add $t1, $a2, $a3  # $t1 = i + j
    sub $v0, $t0, $t1  # result = $t0 - $t1 (返回值放入 $v0)
    jr  $ra            # 返回
```

假设 C 代码如下（**非叶子过程 - 必须动栈**）：
```c
int non_leaf(int n) {
    return leaf_example(n, n, n, n);
}
```

对应的 MIPS 汇编：
```assembly
non_leaf:
    addi $sp, $sp, -4    # 1. 开辟栈空间
    sw   $ra, 0($sp)     # 2. 保存 $ra (因为我要调用别人)
    
    # 准备参数并调用
    add  $a1, $a0, $0    # copy n to $a1
    add  $a2, $a0, $0    # copy n to $a2
    add  $a3, $a0, $0    # copy n to $a3
    # $a0 已经是 n 了
    jal  leaf_example    # 3. 调用子函数 (覆盖了当前的 $ra)
    
    lw   $ra, 0($sp)     # 4. 恢复旧的 $ra
    addi $sp, $sp, 4     # 5. 释放栈空间
    jr   $ra             # 6. 返回上一级
```

### **复习自测题 (必做)**

1.  **概念判断**：
    *   **问**：所有的过程调用都需要访问内存（栈）来保存寄存器吗？
    *   **答**：错。**叶子过程 (Leaf Procedure)** 如果不使用 `$s` 寄存器，可以完全在寄存器内完成，不需要任何栈操作（如上面的第一个例子），效率极高。

2.  **计算题**：
    *   **问**：执行 `jal 0x00400020` 指令。假设当前 PC = `0x00400004`。
    *   执行后，PC = ?，`$ra` = ?
    *   **答**：
        *   `$ra` = 当前指令的下下条 = `0x00400004 + 4` = `0x00400008`。
        *   PC = `0x00400020`。

3.  **设计哲学**：
    *   **问**：为什么 MIPS 不像 x86 的 `CALL` 指令那样，自动把返回地址压入栈？而是非要放到寄存器 `$ra` 里？
    *   **答**：为了**速度**。寄存器访问比内存快得多。对于叶子过程（占比很大），放到寄存器里意味着完全避免了访存。只有在必要时（嵌套调用），才由软件决定压栈。这符合 RISC "Make the common case fast" 的原则。

虽然这个考点看起来比较基础，但在指令集设计（ISA）中，它体现了“软硬结合”的边界。特别是**符号扩展**和**溢出处理**，是考试中极易混淆的细节。

## **考点七：数据类型及其操作**

#### **1. 数据的双重视角 (Slide 26)**
*   **软件视角 (Software View)**：
    *   数据拥有丰富的类型：`int`, `char`, `short`, `bool`, `float`, `struct`, `pointer` 等。
    *   程序员关注数据的**语义**（它是代表年龄，还是代表地址？）。
*   **硬件视角 (Hardware View)**：
    *   **Bit is Bit**：硬件不知道这32个0和1代表什么。硬件只提供**操作指令**。
    *   数据的意义取决于**你用什么指令去操作它**。
        *   用 `add` 操作，它是补码整数。
        *   用 `add.s` 操作，它是IEEE754浮点数。
    *   **基本硬件类型**：
        *   **整数**：8-bit (Byte), 16-bit (Halfword), 32-bit (Word), 64-bit (Long/Double Word)。
        *   **浮点**：32-bit (Single Precision), 64-bit (Double Precision)。

---

#### **2. MIPS 对不同长度数据的支持 (Slide 27)**

MIPS 是 32位架构，寄存器固定是 32位。当我们要从内存加载一个比32位短的数据（如 8位 char）到寄存器时，**剩下的24位怎么填？**

这是本考点的**核心难点**：

*   **Load Byte (加载字节)**：
    *   `lb $rt, offset($rs)` (Load Byte Signed)：
        *   取8位，放入寄存器低8位。
        *   高24位进行**符号扩展 (Sign Extension)**。即如果那8位是负数（最高位1），高24位全填1；否则全填0。
        *   *用途*：`char` (signed char)。
    *   `lbu $rt, offset($rs)` (Load Byte Unsigned)：
        *   取8位，放入寄存器低8位。
        *   高24位进行**零扩展 (Zero Extension)**。即高24位永远填0。
        *   *用途*：`unsigned char`。

*   **Load Halfword (加载半字)**：
    *   `lh`：符号扩展。用于 `short`。
    *   `lhu`：零扩展。用于 `unsigned short`。

*   **Store (存储)**：
    *   `sb` (Store Byte)：截取寄存器的低8位写入内存（高24位被丢弃，不需要区分有无符号）。
    *   `sh` (Store Halfword)：截取寄存器的低16位写入内存。

---

#### **3. 算术运算中的类型与溢出 (Slide 27)**

MIPS 在算术指令中也区分了“有符号”和“无符号”，但这里的区别在于**是否处理溢出 (Overflow)**。

*   **有符号加法**：`add`, `addi`
    *   **行为**：将操作数视为补码有符号数。
    *   **溢出**：如果结果超出了32位有符号数的范围，**CPU会抛出异常 (Exception)**。
    *   *用途*：C语言中的 `int` 运算（但在很多现代系统中，C编译器通常使用 `addu` 来忽略溢出，由软件处理）。

*   **无符号加法**：`addu`, `addiu` (Unsigned)
    *   **行为**：同样是二进制加法（硬件电路其实是一样的）。
    *   **溢出**：**静默忽略溢出**（Wrap around）。就算发生了进位，也不产生异常。
    *   *用途*：C语言中的 `unsigned int`，地址计算（指针运算不应该报错），以及大多数常见的整数运算。

*   **💡 关键误区提醒**：
    *   `addi` 中的 `i` 代表 Immediate（立即数），`addu` 中的 `u` 代表 Unsigned（无异常）。
    *   所以 `addiu` 是 **"Add Immediate Unsigned"**。
    *   **考点**：`addiu` 的立即数仍然是**有符号扩展**的（16位扩展到32位），只是运算结果不报溢出异常而已。这一点非常容易搞错！

---

#### **4. 设计原则：正交性 (Orthogonality / Regularity)**

PPT (Slide 27) 提到了 MIPS 的设计美学：
*   **正交性**：每种数据类型（Byte, Half, Word）都有对应的 Load/Store 指令。每种运算（Reg-Reg, Reg-Imm）都有对应的算术指令。
*   **编译器友好**：这种规整性让编译器写代码生成器（Code Generator）更容易，因为不需要处理各种奇怪的特例（Special Cases）。

### **复习自测题 (必做)**

1.  **符号扩展题**：
    *   内存地址 `0x1000` 处存放着字节 `0xF0` (即二进制 `11110000`)。
    *   `lb $t0, 0x1000($0)` 执行后，`$t0` 的值是多少？(16进制表示)
    *   `lbu $t1, 0x1000($0)` 执行后，`$t1` 的值是多少？
    *   **解析**：
        *   `0xF0` 最高位是1。
        *   `lb` 做符号扩展 $\rightarrow$ `$t0` = `0xFFFFFFF0` (-16)。
        *   `lbu` 做零扩展 $\rightarrow$ `$t1` = `0x000000F0` (240)。

2.  **溢出理解题**：
    *   C语言代码 `int a = b + c;` 应该对应 MIPS 的 `add` 还是 `addu`？
    *   **答**：严格来说对应 `add`（因为有符号整数溢出在C语言中是未定义行为，某些环境希望捕获它）。但在实际工程和GCC编译中，为了性能和简化，默认通常生成 `addu`，除非程序员显式要求检查溢出。

3.  **立即数扩展题**：
    *   指令 `addiu $t0, $t0, -1` 合法吗？
    *   **答**：合法。虽然它是 `unsigned` 指令，但立即数 `-1` (`0xFFFF`) 会被符号扩展为 `0xFFFFFFFF`，然后与 `$t0` 相加。这实际上实现了减1的效果且不报异常。

#### 三、简答题
1.  **(1) 指令序列**:
    ```assembly
    slt $at, $s1, $s2   # if $s1 < $s2, $at = 1
    bne $at, $0, Label  # if $at != 0, goto Label
    ```
    **(2) 原因**:
    PPT Slide 30: 比较并跳转（如 `blt`）在硬件上过于复杂，会拉长时钟周期。将“比较”和“分支”拆分，可以简化电路，不需要在一条指令里做减法运算同时决定跳转，有利于流水线的高频运行。

2.  **指令序列**:
    *   Stack: `Push A`, `Push B`, `Add`, `Pop C`
    *   Load-Store: `lw $1, A`, `lw $2, B`, `add $3, $1, $2`, `sw $3, C`
    **分析**:
    PPT Slide 20。Load-Store 架构可以将数据缓存在寄存器中。如果后续还需要用到 A 或 B，不需要再次访问慢速的内存。而 Stack 机器（或 Memory-only）每次运算都必须频繁读写内存（Traffic 大）。

#### 四、计算题
1.  **(1)**: `add $t0, $t1, $t2` (Rs=$t1, Rt=$t2, Rd=$t0)
    *注意*: R-type 机器码顺序是 rs, rt, rd。这里 01001($9=$t1), 01010($10=$t2), 01000($8=$t0)。
    **(2)**: 将寄存器 $t1 和 $t2 的值相加，结果存入 $t0。

2.  **(1)**: `0x0000 2010`
    *解析*: PC+4 = 0x2004。Offset = 3。Target = 0x2004 + (3 << 2) = 0x2004 + 0xC = 0x2010。
    **(2)**: `0x0000 0010`
    *解析*: PC+4 = 0x2004。高4位是0。Target字段是4。地址 = 0000 || (4 << 2) = 0x00000010。
    **(3)**: **不能**。
    *解析*: 0x0000 2000 和 0x1000 0000 的高4位不同（0 vs 1）。J指令只能在同一个 256MB 块内跳转。需使用 `jr`。
