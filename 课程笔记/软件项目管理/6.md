### 第6章 项目人力与沟通计划

软件产品是众多开发人员的智慧结晶，人是项目中最重要的因素 。项目管理必须制定统一的计划与监督方法，同时结合灵活的沟通方式以保证信息的实时同步 。

#### 一、 对人力资源的认识

- **核心地位**：影响软件项目进度、成本、质量的因素主要是人、技术和过程，其中“人”排在第一位 。
    
- **六大模块**：人力资源规划、招聘、培训、绩效、薪酬和劳动关系 。
    
- **项目人力管理的三个保证**：
    
    - 保证最对的人参与项目：选择合适的人员 。
        
    - 保证每个人被最有效地使用：让每个人都有自己的岗位 。
        
    - 保证每个人发挥最大的潜能 。
        
- **团队创建与发展阶段**：
    
    - **形成阶段**：成员缺乏了解，情绪多为希望、怀疑、焦急；项目经理需明确方向和职责 。
        
    - **震荡阶段**：开始初步合作但遭遇挫折，情绪表现为紧张、不满、抵制和对立 。
        
    - **规范阶段**：凝聚力形成，获得归属感，情绪表现为信任、合作、忠诚 。
        
    - **辉煌阶段**：关系融洽、绩效极高，项目经理可充分授权 。
        
- **团队选人原则**：学历不等于能力，能力不等于适合 。业务精通并非唯一标准，需综合考量系统思维能力、沟通表达能力、总结反思能力及快速学习能力 。
    

#### 二、 项目组织结构

项目组织结构是指描述团队中谁向谁汇报、权力如何分配的框架图 。主要分为三类：

- **职能型组织结构**：
    
    - **优点**：能充分发挥职能部门的资源集中优势，技术专家可跨项目共享，成员事业具连续性和保障性 。
        
    - **缺点**：多重领导（部门经理与项目经理）；当利益冲突时，更重视部门目标而忽视项目目标；项目经理没有充分的权力 。
        
- **项目型组织结构**：
    
    - **优点**：专职项目经理负责，目标单一且以项目为中心；避免多重领导，组织结构简单，决策速度快 。
        
    - **缺点**：资源不能共享，规模经济丧失；项目处于封闭状态，成员缺乏事业连续性和安全感 。
        
- **矩阵型组织结构**：
    
    - **特点**：既利于项目目标实现，又利于公司目标方针贯彻 。
        
    - **缺点**：易引起职能经理和项目经理的权力冲突，资源共享易引发项目间冲突，成员面临多头领导，决策较慢 。
        

#### 三、 责任分配矩阵 (RAM)

- **概念**：用来对项目团队成员进行分工，明确其角色与职责的有效工具 。
    
- **作用**：解决工作相互推诿、责任推卸、分工清晰但不愿协作等内部资源损耗问题 。
    
- **形式**：通常将工作内容与相关人员对应，明确如“负责”、“参加”、“主持”等具体的职责属性 。
    

#### 四、 项目干系人计划

- **定义**：能影响项目决策、活动或结果，以及会受到项目结果影响的个人、群体或组织 。
    
- **分类**：包括项目发起人、出资方、客户、用户、项目经理、团队成员、供应商、政府部门等 。干系人对项目的影响既可能是积极的，也可能是消极的 。
    
- **分析步骤**：
    
    1. **无遗漏地识别**：构建完整的项目干系人结构图 。
        
    2. **按重要性分析**：了解各方需求并重点争取重要干系人的支持，同时不可忽视次要干系人潜在的阻力 。
        
    3. **按支持度分析**：将其分为首倡者、支持者、中立者、抵制者等，重点争取中间力量 。
        
- **权力/利益方格（核心考点）** ：
    
    - **权力高 + 利益高**：重点管理 。
        
    - **权力高 + 利益低**：令其满意 。
        
    - **权力低 + 利益高**：随时告知 。
        
    - **权力低 + 利益低**：花最少精力监督 。
        

#### 五、 沟通管理及模式

- **沟通目标**：确保信息高效、准确地产生、传递、接收和理解，消除信息不对称 。
    
- **信息损耗漏斗**：原始信息(100%) $\rightarrow$ 实际表达(80%) $\rightarrow$ 接收听到(60%) $\rightarrow$ 理解(40%) $\rightarrow$ 记住反馈(20%) 。
    
- **沟通渠道计算**：公式为 $N(N-1)/2$，其中 N 为人员总数 。渠道越多管理难度越大，项目经理应保持沟通渠道单一 。
    
- **沟通计划要素**：明确谁需要信息、需要什么信息、何时需要、沟通方式、问题升级程序及资源预算等 。
    

#### 六、 沟通方式及技巧

- **主要沟通方式对比**：
    
    - **书面沟通**：正式或非正式，准确可信、可复制且准确率高 。缺点是容易忽略语气和情感，导致理解偏差 。
        
    - **口头沟通**：即时、高效，有亲切感并能立即获得双向反馈 。缺点是容易遗忘、缺乏凭证，传播中易变形失真 。
        
    - **非语言沟通**：利用形体语言、表情等，具有无意识性、情境性和可信性 。
        
- **正式与非正式沟通**：
    
    - **正式**：按组织规章制度进行（如公函、报告、会议），事先有计划 。
        
    - **非正式**：组织规定之外的交流（如私下交流）。灵活速度快，能反映真实态度；缺点是难以控制，易传播小道消息或失真 。
        
- **单向与双向沟通**：
    
    - **单向**：只发不收（如做报告）。速度快、程序简单，但准确性差 。
        
    - **双向**：交互商谈。准确性高，增加参与感和责任心；缺点是速度慢、易受干扰 。
        
- **核心沟通技巧**：
    
    - **结论先行**：先亮出核心结论，再结构化展开，最后确认理解 。
        
    - **消除二义性**：明确量化标准，避免模糊词汇 。
        
    - **封闭式确认**：提问 $\rightarrow$ 确认对方理解 $\rightarrow$ 得到明确答复，形成沟通闭环 。
        
    - **区分事实与观点**：客观存在的行为/数据是“事实”，主观判断或感受是“观点”（如：迟到15分钟是事实，效率低是观点） 。
        
    - **运用沉默技巧**：包括主动式沉默（给对方压力）、回应式沉默、以及应急式沉默（大脑短路或装深沉） 。
