## 第2章 软件项目管理概述：核心复习大纲

### 一、 时代背景：技术变革与软件管理的痛点

- **技术变革的体现**：个人计算机升级换代、常用存储方式发生巨大变化、个人通讯方式和工具不断更新 。
    
- **行业现状与痛点**：“重硬件，轻软件”现象明显，软件项目普遍缺乏系统性的管理 。
    
- **作坊式生产的弊端**：过度依赖技术骨干、无文档式开发导致可持续风险大、无计划/方案/规则、开发成本易超支、产品往往不符合用户实际需求 。
    
- **项目失败的主要原因**：范围需求不明确占比最高（55%），其次是时间紧（45%）和资源预算不足（40%），而纯粹的质量差仅占8% 。
    
- **软件发展的三个阶段**：
    
    1. **软硬件一体化阶段（50s-70s）**：软件完全依附于硬件，功能单一 。
        
    2. **软件作为独立产品的阶段（70s-90s）**：操作系统出现，降低了开发调试难度，软件可作为独立产品生产 。
        
    3. **网络化和服务化阶段（90s-至今）**：出现服务化思想，直接调用服务避免“重复制造轮子” 。
        
- **我国信息化四个阶段**：启动阶段（80-90年代初） $\rightarrow$ 推进阶段（90年代初-末） $\rightarrow$ 发展阶段（99-01年） $\rightarrow$ 高速发展阶段（2001-至今） 。
    

### 二、 项目的概念及核心特点

- **项目的定义**：为创造一个唯一的产品或提供一个唯一的服务而进行的临时努力 。
    
- **日常活动的定义**：为满足日常生活的需要而每天进行的必要活动 。
    
- **项目与日常活动的异同**：
    
    - **相同点**：都需要人来完成、受有限资源限制、均需要计划/执行/控制 。
        
    - **不同点**：项目具有明确独特的目标、临时性（有起止时间）、不可重复、需专门资源和项目管理方法；日常活动则是维持现状、持续无终点、重复规律的 。
        
- **项目的六大特征**：
    
    1. **目标性**：贯穿始终，一切活动围绕目标 。
        
    2. **相关性**：有很多彼此相关的复杂活动 。
        
    3. **临时性**：有明确的开始点和结束点 。
        
    4. **独特性**：项目间无绝对重复，各具特点 。
        
    5. **资源约束性**：需要各种资源且资源是有限制的 。
        
    6. **不确定性**：存在很多风险和变化 。
        
- **层级概念**：项目群（协调管理一组相互联系的项目，目标呈战略性） $>$ 项目 $>$ 子项目（将项目分解为更小单位以便控制） 。
    
- **四大制约因素**：范围、时间、成本、客户满意度（干系人需求），其中客户满意度最为重要 。
    

### 三、 项目管理的概念、由来与关注点

- **项目管理定义**：为实现目标，采用有效手段对项目各阶段工作进行计划、组织、协调、指挥、控制，以取得良好经济效益的总和；最终需让所有项目干系人的需求得到不同程度满足 。
    
- **由来**：20世纪50年代后期发展，美国杜邦公司（设备维修）和美国北极星导弹设计均通过此方法大幅缩短了时间 。
    
- **项目管理的主要关注点（核心考点）**：
    
    - **战术上（三大约束）**：时间、成本、范围 。
        
    - **战略上（3个P）**：人员 (People)、问题 (Problem)、过程 (Process) 。
        
        - **人员**：分狭义（具体研发团队）和广义（含高层、客户、供货商等）。通过技能对齐、持续学习、激励机制等打造团队 。
            
        - **问题**：项目经理必须敏锐地发现问题，并能顺便给出解决方案 。
            
        - **过程**：采用标准化过程能产生均衡的产品质量；产品的质量依赖于企业的过程能力，而非纯依赖个人能力 。注意：软件过程不仅仅是开发流程，而是最佳实践的总和 。
            

### 四、 项目管理的知识体系 (PMBOK & CMMI)

- **基本缩写术语**：
    
    - **PMI**：美国项目管理学会 。
        
    - **PMP**：项目管理专业人员资格 。
        
    - **PMBOK**：项目管理知识体系指南 。
        
- **PMBOK 体系构成 (10-5-49)** ：
    
    - **10大知识领域**：整合、范围、进度、成本、质量、资源、沟通、风险、采购、相关方（干系人） 。
        
    - **5大标准过程组**：启动、规划、执行、监控、收尾 。
        
- **项目收尾工作**：
    
    1. **合同收尾**：核对要求，完成验收 。
        
    2. **行政收尾**：易被忽略，包含文档整理归档、释放/重新分配资源等 。
        
- **CMMI 软件能力成熟度模型（5个层级）** ：
    
    - **L1 已执行的** / **L0 不完整的** 。
        
    - **L2 已管理级**：遵守既定计划与流程，有资源准备，对流程有监测与控制 。
        
    - **L3 已定义级**：建立组织财富库，定义自己的标准流程 。
        
    - **L4 量化管理级**：管理流程量化与数字化，实现流程稳定性 。
        
    - **L5 优化级 (创新)**：主动预防问题、改善流程、运用新技术 。
        

### 五、 软件项目的独特性质与管理难点

- **软件项目的特殊性**：软件是无形的逻辑实体（而非物理实体），导致进度和质量难以度量和估计 。
    
- **软件项目六大特征**：无形逻辑实体、需要多人协作、大量业务流程创新、尚未完全摆脱手工开发、日趋庞大复杂、需满足一群人的需求及环境不断演变 。
    
- **高风险成因**：周期长、变数多、市场过度承诺、外部商业环境变化及内部人员变动 。
    

### 六、 软件项目管理四大阶段的核心与最大困难

- **项目启动**：明确目标和关键负责人。**最大困难**：如何有效地、正确地确定项目范围（需求） 。
    
- **项目计划**：组建团队、分配任务、设置进度。**最大困难**：项目计划的准确度差 。
    
- **项目执行控制**：跟进进度，利用数据做控制。**最大困难**：前期计划不准确导致关键路径不能锁定，且在时间/成本压力下容易导致质量管理流于形式 。
    
- **项目收尾**：成果汇报与复盘分析。**最大困难**：关于时间、质量、成本和项目范围的冲突会集中爆发出来 。
