# 第 3 章 Prompt 工程 - 复习目录

## 3.1 Prompt 工程简介

随着大语言模型（LLM）的发展，研究范式从传统的“预训练-微调-预测”转变为**“预训练-提示预测”**。
*   **核心优势**：无需对模型进行繁琐且昂贵的微调，通过精心设计的指令（Prompt）即可引导模型适应下游任务。

### 3.1.1 Prompt 的定义
*   **含义**：用于指导生成式 AI 执行特定任务的输入指令，通常是自然语言文本。
*   **目的**：清晰描述任务，引导模型生成特定的文本、图像或音频。
*   **组成**：通常包含任务说明、上下文、问题、输出格式等元素。

### 3.1.2 Prompt 工程的定义
*   **概念**：专注于设计和优化 Prompt 的技术，目的是将新任务构建为模型在预训练阶段已熟悉的形式。
*   **核心挑战**：随着 Prompt 内容丰富，长度增加会导致推理成本上升。
*   **压缩技术**：
    *   **LLMLingua**：由粗到细的压缩，可压缩至 1/20 而不损失性能。
    *   **FIT-RAG**：针对 RAG 场景，压缩检索内容至 50%。

### 3.1.3 Prompt 分词向量化
模型无法直接理解文本，需经过**分词（Tokenization）**和**向量化（Embedding）**。
*   **流程**：文本 -> Token 序列 -> Token ID -> 向量嵌入。
*   **分词算法**：如 BBPE (Byte-Level Byte Pair Encoding)。
    1.  初始化词表（单字节）。
    2.  统计相邻 Token 对频率。
    3.  合并高频对。
    4.  迭代直至达到预设大小。
*   **词表大小的影响**：
    *   **过小**：序列过长，语义难以区分。
    *   **过大**：长尾词汇学习不充分，难以捕捉形态关联。
*   **分词效率对比**：中文语境下，DeepSeek、Qwen 等国产模型的分词效率（字/Token）优于 GPT-4 和 LLaMA。

### 3.1.4 Prompt 工程的意义
*   **无需微调**：激发模型潜能，低成本完成垂域任务。
*   **赋能领域**：
    1.  **垂域任务**：如 Text-to-SQL，无需监督微调即可生成高质量查询。
    2.  **数据增强**：生成高质量合成数据，用于“蒸馏”小模型（如 Alpaca, Evol-Instruct）。
    3.  **智能代理 (Agent)**：构建感知环境、自主行动的智能体（如斯坦福虚拟小镇）。

## 3.2 上下文学习 (In-Context Learning, ICL)

利用大语言模型涌现出的能力，通过在 Prompt 中提供示例，让模型在不更新参数的情况下学习任务逻辑。

### 3.2.1 上下文学习的定义
*   **范式**：Prompt = 任务说明 + 演示示例（Context） + 问题。
*   **形式**：
    *   **零样本 (Zero-shot)**：仅提供任务说明，无示例。依赖模型泛化能力。
    *   **单样本 (One-shot)**：提供 1 个示例。
    *   **少样本 (Few-shot)**：提供 k 个示例。性能随示例增加提升，但有边际效应。
*   **原理**：隐式贝叶斯推理。示例帮助模型“锚定”预训练中已有的概念（如情感、句法）。

### 3.2.2 演示示例选择
示例的质量直接决定 ICL 的效果，主要考量**相似性**和**多样性**。
*   **直接检索 (Direct Retrieval)**：
    *   代表方法：**KATE** (基于 RoBERTa 编码计算余弦相似度)。
    *   特点：选出最相似的 k 个，但容易同质化。
*   **聚类检索 (Clustering Retrieval)**：
    *   代表方法：**Self-Prompting**。
    *   特点：先聚类再从每个簇选最相似的，保证多样性，但可能牺牲部分相似性。
*   **迭代检索 (Iterative Retrieval)**：
    *   代表方法：**RetICL**。
    *   特点：动态选择下一个示例，兼顾相似性与多样性，适应复杂任务。

### 3.2.3 性能影响因素
1.  **预训练数据**：领域丰富度、任务多样性、数据分布特性（突发性/罕见类别有助于 ICL）。
2.  **预训练模型**：参数规模越大，ICL 能力越强（通常需达到亿级以上参数）。
3.  **演示示例**：
    *   **格式**：复杂推理任务需包含推理步骤（CoT）。
    *   **映射正确性**：大模型对标签错误敏感，小模型相对不敏感。
    *   **数量与顺序**：生成任务比分类任务更受益于数量增加；示例顺序对结果有显著影响。

## 3.3 思维链 (Chain of Thought, CoT)

针对算术、逻辑推理等复杂任务，模型规模增大遇到 "Flat Scaling Curves" 瓶颈。CoT 通过模拟人类思考过程，在答案前生成**中间推理步骤**。

### 3.3.1 思维链提示的定义
*   核心：引导模型**一步一步 (step-by-step)** 生成推理路径，最后得出答案。

### 3.3.2 按部就班 (线性推理)
强调逻辑连贯性和顺序性。
*   **Few-Shot CoT**：手工编写包含推理步骤的示例。
*   **Zero-Shot CoT**：
    *   方法：在问题后加一句触发词 **“Let's think step by step” (让我们一步一步思考)**。
    *   流程：推理生成阶段 -> 答案生成阶段（拼接 "Therefore, the answer is"）。
*   **Auto-CoT**：自动构建示例。利用 Zero-Shot CoT 生成推理链，通过聚类筛选多样化问题构造 Prompt。

### 3.3.3 三思后行 (非线性/树状推理)
引入审慎与回溯机制，模仿人类试错。
*   **ToT (Tree of Thoughts)**：
    *   将推理过程构建为树结构。
    *   操作：拆解（子问题）、评估（投票/打分）、搜索（BFS/DFS）。
    *   示例：24点游戏。
*   **GoT (Graph of Thoughts)**：
    *   扩展为图结构，支持思维的聚合、循环和自我修正。

### 3.3.4 集思广益 (集成推理)
利用集体智慧优化决策。
*   **Self-Consistency (自洽性)**：
    *   方法：对同一问题生成多条推理路径。
    *   决策：通过**多数投票 (Majority Voting)** 选择最终答案。
    *   效果：显著提升复杂推理任务的准确率。

## 3.4 Prompt 技巧

### 3.4.1 规范 Prompt 编写
*   **四大要素**：任务说明、上下文、问题、输出格式。
*   **原则**：
    *   **任务明确**：使用清晰动词（如“判断”而非“处理”），定义具体名词标签。
    *   **简洁明了**：避免冗长。
    *   **结构化布局**：重要信息放开头或结尾，使用分隔符（如 `###`, `---`）区分模块。
*   **上下文**：需丰富且与问题紧密相关，避免无关信息的干扰。
*   **输出格式**：指定结构化输出（如 JSON），并提供格式示例。

### 3.4.2 合理归纳提问
*   **复杂问题拆解 (分而治之)**：
    *   策略：分步引导（拆分为子问题逐一回答） -> 归纳总结（汇总子答案）。
*   **追问技巧**：
    1.  **深入追问**：挖掘特定概念深层信息。
    2.  **扩展追问**：拓宽讨论广度，获取多视角。
    3.  **反馈追问**：指出模型错误，要求修正（纠错机制）。

### 3.4.3 适时使用 CoT
*   **适用场景**：复杂推理（算术、常识、符号推理）。
*   **不适用场景**：简单任务（情感分类、常识问答），可能导致过度复杂化。
*   **模型要求**：通常在 100B 参数以上的大模型效果显著；小模型或未经过推理微调的模型可能产生逻辑错误或幻觉。
*   **灵活调整**：可指定输出详细程度（简略计算 vs 详细推导）。

### 3.4.4 善用心理暗示
利用大模型对人类语言模式的模仿能力。
*   **角色扮演 (Role-Playing)**：设定特定身份（如“经验丰富的兽医”），激发专业知识。
*   **情景代入**：设定特定环境（如“90年代街头”），调整语言风格和情感共鸣。
*   **积极暗示**：类似于“Fake it till you make it”，增强模型自信（虽然文档主要强调了角色和情景）。

## 3.5 相关应用

### 3.5.1 基于大语言模型的 Agent
*   **定义**：具有感知、规划、行动能力的智能体。
*   **核心架构** (以小浣熊医疗助手为例)：
    1.  **配置模块 (Profile)**：角色设定（Prompt 角色扮演）。
    2.  **记忆模块 (Memory)**：存储知识与交互历史（RAG 检索增强）。
    3.  **计划模块 (Planning)**：任务拆解与规划（CoT, 少样本引导）。
    4.  **行动模块 (Action)**：执行具体步骤，调用工具/API。

### 3.5.2 数据合成
*   **背景**：高质量真实数据枯竭，隐私受限。
*   **方法**：**Self-Instruct**。
    *   流程：构建种子任务池 -> 指令生成 -> 指令分类 -> 数据生成 -> 数据过滤 -> 循环迭代。
    *   作用：生成大规模指令微调数据，实现大模型向小模型的**知识蒸馏**。

### 3.5.3 Text-to-SQL
*   **目标**：降低数据库查询门槛，用自然语言生成 SQL。
*   **C3 框架 (基于 Prompt 的优化)**：
    1.  **清晰提示 (Clear Prompting)**：排版清晰，明确指令、Schema 和问题。
    2.  **提示校准 (Calibration with Hints)**：利用历史对话和先验知识纠偏。
    3.  **一致输出 (Consistent Output)**：利用 Self-Consistency 采样，保证 SQL 准确性。

### 3.5.4 GPTS
*   OpenAI 推出的定制化应用，允许用户通过 Prompt Engineering 和工具配置（Actions）构建专属的 ChatGPT 版本。
